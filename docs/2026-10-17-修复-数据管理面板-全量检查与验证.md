### 6.3 C 批建议（基于实测，不靠目测）

实测块（1440×900，users tab，40 行）：
`topbar 76` + `breadcrumb 35` + `gap 19` + `tabs 42` + `gap 16` + `toolbar-primary 61` + `toolbar-secondary 74` + `gap 17` + `sheet-head 71` = **thead 414**；行高 **64px**，首屏 **6 行**。1280 宽 secondary toolbar 换成 126px（wrap），thead 466。

**结论：C 批不能只压 thead。行高 64 是更硬的阻塞**——即使 thead 压到 240，13×64=832 > 660 可用高度，13 行仍不可能。

建议分两阶段：

**阶段 1（优先，约 1 人日）**
1. **行高先回到 42**：动作列当前实际内容宽 170px 塞在 112px 列里，标准密度 td padding 8px，整行被撑到 64。做法：每行只保留 1 个主操作 + ⋯ 菜单（或把「禁言」收进菜单），动作按钮 28–30px、td padding 6px，单元格 `white-space: nowrap`；用 density 探针断言 `firstRowHeight === 42`。
2. **删 `g-sheet-head` 重复标题/工具条（-71px）**：密度/视图/每页条数移进工具栏或表尾。
3. **合并 primary/secondary 两条工具栏（-87px）**：新增/导出 + 搜索/筛选/列配置/命令合成一条 48px 行；1280 下必须保持单行（当前会 wrap 到 126px）。
4. **面包屑并入 topbar（-54px）**：数据管理台的 `数据管理 › 模块 › tab` 可降级为 topbar 副标题；详情页仍保留 breadcrumb（详情页没有 topbar 标题重复问题）。
5. 预计 thead ≈ 200–220；13×42=546 + thead 42 + 页脚 50 = 638 < 780 可用 → 13 行可达。

**阶段 2（若产品坚持 240 且阶段 1 仍差 20–40px）**
- 把 topbar 做成滚动后收起/悬浮（shell 级改动），或把数据台切换为「紧凑壳」；这是 2–3 人日 + 10 个 page 型子页回归，不建议塞进 C 批 CSS 微调。

**兜底**
- 若产品不接受上述重构，就把验收线改成 `thead ≤ 300 / 行高 48 / 可见 ≥ 10`，同步 plans/027 与交接书；**但行高 64 必须在任何口径下先修**，否则「行高 34/42/48」这条永远是假的。

另：本次已修「空状态与空表格同时渲染」——`DashboardSheet` 加 `v-if="!emptyState"`，空表时只显示空状态，不再多出约 350px 空白。

## 9. 详情页内编辑（D2 升级，2026-10-18）

产品确认后落地：详情子页的「编辑」从「直开抽屉」升级为**页内编辑态**。

### 9.1 行为（最终形态：完整表单嵌入，2026-10-18 二次迭代）

- 详情页（`/:tab/:id`）点「编辑」→ **整个 EditDrawer 以 embedded 形态 Teleport 进记录面板**
  （`#detail-edit-slot`）：全部字段类型可用（图片上传 / 用户·商品选择器 / JSON / tags /
  异步 optionsSource 下拉），无遮罩、无滚动锁、无 Esc 关闭、头尾隐藏，
  分组自动全部展开（embedded 首渲染无 show 翻转，需 onMounted 补 expandAllGroups）。
- 顶栏按钮变「保存 / 取消」（DetailActionBar）；「返回列表」不变。
- **保存完整复用既有管线**：`openEditModal(record, { embedded: true })` 做全部字段预处理
  （forum 拆分 / subscriptions plan_name / json 缓冲 / 日期转换 / gifts 地址），
  `saveData()` 做必填与逐字段校验 → `SAVE_STRATEGIES[tab]` 组装 → **保存前差异预览确认**
  → PATCH → 审计（update + diff）→ 缓存失效 → 单行 patch 回列表。
- 保存成功：退出编辑态 + 重新拉取详情（只读视图立即反映新值）。
- 换记录 / 离开详情自动复位编辑态，防串记录。
- 列表页的弹层抽屉（新增 / 行编辑）不变 —— 同一组件两个实例 v-if/v-else 互斥，
  共享同一份 `editingItem`。**不用「单实例 + Teleport disabled 动态切换」**：
  disabled 与子树同帧翻转时内容会落在原位（实测）。

> 初版（简单字段页内 + 复杂字段弹抽屉的两层方案）已被本形态替代，
> DetailEditForm.vue 已删除；抽屉内分组折叠记忆（localStorage）与
> 「保存『xx』」分组快捷按钮在嵌入形态照常可用。

### 9.2 正确性要点（踩过的坑）

1. **详情取数从 `TAB_SELECT_COLUMNS` 窄列改为 `select('*')`**：保存策略会读取列表列之外的字段，
   窄列会让 `editingItem` 缺键 → 更新时把未知字段写成 undefined（数据丢失风险）。
2. `DetailEditForm` 对 `editingItem` 的就地变更经 computed 中转（同一对象引用），
   绕开 `vue/no-mutating-props` 的静态检查；prop 命名 `model` 而非 `modelValue`（非 v-model 契约）。
3. 编辑按钮按 `canEditCurrentTab` 门控（与抽屉入口同权限）。
