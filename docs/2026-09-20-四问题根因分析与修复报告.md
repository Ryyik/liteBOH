## 问题 1 · 「奶牛抱抱」头像框渲染成猫

### 现象
个人资料 hero、装扮网格里佩戴「奶牛抱抱」，画出来的是一张猫（白厚环 + 橙色小猫 + 鱼/爪）。

### 根因：**数据被顶掉**，不是资源引用写错

DB 实读（`avatar_frames`）：

| id | url | source_url |
| --- | --- | --- |
| `cow`（奶牛抱抱） | `…/admin-avatar-frames/xlonftfv2icxmq8fbziy.png` | `…/source/reao84qzvije1daqc2xt.png` |
| `white-cat`（白绒猫） | `…/admin-avatar-frames/mupu5trhd5napiwg7zew.png` | `…/source/vuika40xnfxjyqvhc6mo.png` |

把四张图下载下来比对**字节**（url 字符串不同，内容相同）：

```
cow 成品图  sha256 10b049d07330b38f…   ← 与 white-cat 成品图完全相同
cow 原图    sha256 0dd81319e2f26b9c…   ← 与 white-cat 原图完全相同
```

两张图**都是白绒猫**（仓库里 `/avatars/frames/cow-frame.png` 才是真奶牛）。
即：运营在头像框控制台把白绒猫的素材（原图 + 成品图）发布到了 `cow` 这个 slug 上，`cow.scale` 还是老的 1.60。

为什么一发布就"变猫"：前端清单是 **DB 优先合并**——`useAvatarFrame.js` 的 `allAvatarFrames()` 用 DB 行覆盖同 id 的内置行：

```js
return [ ...builtinOnly.filter(f => f.id === 'none'), ...remote, ...builtinOnly.filter(f => f.id !== 'none') ];
```

于是仓库里正确的奶牛素材被一张错的云图顶掉，且**没有任何一处会告警**：控制台 `save()` 直接 `upsert`，前端只认 url。

### 修复
1. **数据修复**（已应用）：`supabase/migrations/2026092001_avatar_frame_cow_restore.sql`
   - `cow.url` 回 `/avatars/frames/cow-frame.png`、`scale` 1.60、`source_url` 清空；
   - 迁移自带自检断言（库内不得再有行指向那张猫图）；
   - 白绒猫的 Cloudinary url 是对的（图就是白绒猫），不动。
2. **防复发**（`src/views/AvatarConsole/index.vue`）：
   - `applySource()` 记录素材归属 `ownerId / ownerKind`（`library` | `upload`）；
   - `save()` 新增 `findMaterialConflict()` 两道闸：
     ① 从框库选来的素材必须与当前 slug 一致（防止把 A 框素材发到 B 框）；
     ② 同一份**成品图或原图**不能被两个 slug 共用 —— 正是本次事故的形态；
   - 命中即拦截并给出可执行的提示，不再是静默写入。

### 验收
- `D1` cow/white-cat 成品图指纹不同、`D2` 原图不共用、`D3` `cow.url == /avatars/frames/cow-frame.png`、`D4` scale 1.60；
- `D5` 真库渲染：个人资料 hero 佩戴「奶牛抱抱」时 `background-image` = `…/avatars/frames/cow-frame.png`。

## 问题 2 · 横竖屏调节头像框缩放：比例对不上、竖屏手势方向反

### 先定位"交互面"
全仓检索确认：能「调节头像框缩放」的只有**头像框控制台编辑器**（`/admin/avatar-console` 的画布：拖拽摆位 / 滚轮缩放 / 滑杆），它同时是 `plans/010` 里设计过的 `StageCanvas`。用户侧的装扮网格、试戴弹层没有任何缩放手势。

### 实测（Chrome + CDP 真实触摸事件，横屏 1280×900 与竖屏 420×900 各一遍）

| 操作 | 修复前 | 判定 |
| --- | --- | --- |
| 滚轮上滚 | zoom 1.13 → 1.17、scale 1.60 → 1.55、滑杆同步 117 | 方向正确（上滚=放大素材） |
| **双指外撑** | zoom **1.13 → 1.13（不变）**、scale 不变，但**孔心偏移 0px → 306px** | ❌ 捏合退化成平移 |
| **双指内收** | zoom 不变 | ❌ 同上 |

### 根因
`onPointerDown` **不区分指针**：第二根手指落下的 `pointerdown` 直接覆盖 `dragState`，此后 `pointermove` 只按"后落下的那根手指"算位移 ——

- 捏合**完全没有缩放映射**（触屏没有滚轮，滑杆是唯一能缩的入口）；
- 手却按单指平移走：往外撑时素材被拖到一侧（孔心偏移瞬间冲到 306px，这个状态直接发布就会得到**错位的成品图**），主观感受就是"缩放手势方向反了"。

顺带发现同一段代码的健壮性缺陷：

```js
e.currentTarget.setPointerCapture?.(e.pointerId);   // 只判方法存在，没兜异常
```

指针已被浏览器释放时抛 `DOMException`，冒泡进 Vue 错误边界 → 整页被换成「页面出了点问题」（合成非活动指针事件可复现）。

### 修复（`src/views/AvatarConsole/index.vue`）
- `activePointers` Map 按指针数分流：**单指=平移**，**双指=捏合**；
- 捏合缩放按 **间距比 × 起手 zoom** 乘性推进（钳到 0.6–2.6），锚点仍是孔心（保持既有不变式：头像圆永远居中、`offset` 归零）；
- 捏合期间不再平移；捏合结束剩一根手指时**重建平移基准**，避免跳变；
- `setPointerCapture` 包 `try/catch`（失败只记日志，不再打崩整页）；
- badge 改为同时显示两个口径：`缩放 1.13× · scale 1.60`（此前 badge 只显示 zoom，而 zoom 与框层 scale 是**反比**关系，运营盯着数字调会得出"比例和画面不一致"的错觉）；
- 画布 `title`、上传成功提示补上「双指捏合」。

### 验收
探针 C 组横竖屏各 4 条：`C1` 滚轮方向 + 与滑杆一致、`C2` 外撑=放大且孔心偏移 ≤8px、`C3` 内收=缩小、`C4` 全程不进错误边界。修复前 `C2/C3` 红。

## 问题 3 · 个人空间「编辑资料」跳不到正确页面

### 实测
点按钮后 URL = `#/user-space?tab=settings`，面板停在**设置首页**（不是编辑资料）。

### 根因：URL 丢分区 → 随后被 route 驱动的重算覆盖
链路（`UserSpaceMain.vue`）：

1. `openEditProfileModal()` → `jumpWithSection('settings','edit-profile')`：只写了内存 ref `settingsSection='edit-profile'`，然后 `switchTab('settings')`；
2. `switchTab` → `syncUserSpaceTabRoute('settings')` 拼 URL 时**只带 `tab`，不写 `view`**（旧代码只在"tab 不是 settings"时才动 `view`）→ URL 没有分区信息；
3. 紧接着 `watch(currentTab)`（以及 `watch(() => route.query.view)`）触发 `resolveSectionFromRoute()`，按"URL 里没有 view"把 `settingsSection` **回落成默认 `'home'`** —— 刚设好的分区被冲掉。

副作用不止点击：分区不进 URL 意味着**刷新/分享会丢分区**（少一层深链能力）。

### 修复
- 新增 `SECTION_REFS`（tab → 分区 ref，单源）+ `withSectionQuery()`；`syncUserSpaceTabRoute()` 改为按同一口径把当前分区写进 `view`（等于默认值则删）→ **URL 成为分区单源**；
- `resolveSectionFromRoute()` 加守卫：URL 的 `tab` 与当前 tab 不一致（`router.replace` 尚未落地 / watcher 先烧）时**不采信旧 URL**，杜绝"用旧 URL 覆盖刚设好的分区"；
- `syncUserSpaceTabRoute` 的早退判断补上 `view` 比较（此前"只差 view"会跳过 replace）。

### 验收
- `A1` 点击 → `?tab=settings&view=edit-profile` 且 `.profile-edit-page-shell` 渲染；
- `A2` 深链直达可还原；`A3` 从导航切回「设置」仍落默认分区（没有被旧 view 粘住）。

## 问题 4 · 帖子详情页不再展示发帖时间

### 实测
- 横屏（landscape + ≥1025px，弹窗形态）：时间正常（`前天 23:47`）；
- **窄屏 / 竖屏（≤1024px，Threads 式整页）：页面上没有任何可见时间**。

### 根因：窄屏改版把承载时间的作者行精简掉了，但没人承接
`src/views/PostDetail/style.scoped.css` 的 `@media (max-width: 1024px)`：

```css
.post-detail-page .x-post-card .author-section .boh-avatar-wrap,
.post-detail-page .x-post-card .author-section .author-meta { display: none; }
```

`.post-time` 就在 `.author-meta` 里 → 被一起隐藏。设计意图是把身份收到顶部固定身份条 `.pd-author-bar`，但身份条只渲染了「返回 / 头像 / 昵称 / 关注」，**没有时间** → 窄屏下时间彻底消失。

注意不是数据问题：详情查询是 `posts` 的 `select('*', author:author_id(...))`，`created_at` 一直都在；`formatDate = formatSmartTime` 也没坏。

### 修复
- `PostDetailMain.vue`：身份条内新增 `.pd-author-bar-text`（昵称 + 时间两行，Threads 式）；
- `style.scoped.css`：`.pd-author-bar-text` / `.pd-author-bar-time`（11.5px、`--detail-muted`、单行省略）；
- 宽屏与横屏弹窗路径不动（本来就有时间）。

### 验收
- `B1` 竖屏：`.pd-author-bar-time` 文本存在且**真实可见**，同时内容区 `.author-meta` 仍是 `display:none`（证明是"把时间挪到身份条"，而不是把精简规则撤了）；
- `B2` 横屏弹窗：`.pd-modal-info .post-time` 可见。
- 探针的可见性判定用「祖先链无 `display:none` + 元素有盒子」——只读 `getComputedStyle` 会被 `display:none` 的父级骗过（第一版探针就因此误判为 PASS）。

## 遗留与建议

1. **素材唯一性只拦在发布口**：`findMaterialConflict()` 是发布时校验；更彻底的做法是给 `avatar_frames` 加一列成品图内容指纹（发布时算 SHA-256），把"同素材两占"拦在写入前，并可在用户端做一次一致性自查。
2. **控制台"缩放"口径**：建议后续把 `scale` 作为主显示（badge 已并列），避免运营把"素材缩放倍数"误当成"框大小"。
3. **窄屏身份条内容边界**：目前只承接 昵称 / 发帖时间 / 关注；位置、话题等仍在正文区，若要彻底统一需要再收敛一次信息架构。
4. **并发编辑提醒**：本次排查期间工作区另有会话在改 `vite.config.js` / BOHAI 相关文件；我执行 `git stash pop` 时命中了一个**遗留的旧 stash**（`bohai/multi-agent-cluster`），在 `src/views/BOHAI/**` 4 个文件产生冲突。已按"保留上游（更新）版本"处理完毕（冲突标记已清、stash 条目仍保留未删除），本次 4 个修复文件未受影响。
