# 路由组件 key 粒度评估与落地（App.vue:366）

日期：2026-09-25
状态：**已落地**（评估 → 2026-09-25 晚，用户拍板后实施，含 2 条护栏）

---

## 1. 结论

组件级 key 从 `activeRoute.fullPath` 改为 **`activeRoute.path`**（1 行 + 注释），并给 Newsroom 列表补 1 段 `?news=` 的 watch。

- **不能用 `fullPath`**：它含 query，任何「同页换参数」都会销毁重建整个路由组件 —— 组件内状态归零，且 `onMounted` 补发取数会覆盖带条件的结果（2026-09-25「抽奖名单」跳转失效的根因）。
- **也不能用 `name`**：`/news/1` → `/news/2` 的 name 相同，而 `NewsDetailPage` 只靠 `onMounted` 取数、**没有 watch(params)**，用 name 会在切换新闻时显示上一条。
- **`path` 正好**：对 params 敏感、对 query 不敏感，与 `boundaryKey` 的既有决策同源同口径。

## 2. 现状机制（改动前）

```html
<KeepAlive>
  <component v-if="activeRoute.meta?.keepAlive" :is="Component" :key="activeRoute.name" />
</KeepAlive>
<component v-if="!activeRoute.meta?.keepAlive" :is="Component" :key="activeRoute.fullPath" />
```

全站只有 3 个 keepAlive 路由（都在 `router/routes/user-space.ts`）走 name 分支豁免；**其余全部**受 `fullPath` 影响。

同一个坑的两半：`boundaryKey` 早已改成 `route.path`（`src/App.vue:88-91` 有明确警告注释），但 `tests/unit/global-error-boundary.test.js:96` 只断言了 `() => route.fullPath` 不出现在**边界**的 watch 里，**组件级 key 这一半没被覆盖**。

## 3. 影响面（改动前正在白白重建的页面）

| 页面 | 换参数的入口 | 页面自身能否响应 query | 重建的代价 |
| --- | --- | --- | --- |
| `/admin/data-management?section=&tab=` | `DataAdmin.vue:1345` | ✅ `switchTab` + 反向 watcher | **每次切表 2 次列表请求**（其一带空关键词，覆盖正确结果）；勾选/页码/滚动全丢 |
| `/activities-wall?tab=wall` | `ActivitiesWall/index.vue:34` | ✅ `computed` 读 query | 纯浪费（重建后状态与数据完全一致） |
| `/newsroom?q=&filter=` | `Newsroom/index.vue:521/522` | ✅ watch `query.q` / `query.filter` | 每次搜索/筛选重建 + 重跑 `loadNewsData()` |
| `/` 首页 `?view=` | `Home/index.vue:247/275` | ✅ watch `route.query.view` | 首页最重，最不该重建 |
| `/profile/:username` | 用户跳转 | ✅ watch `route.params.username` | 每次换主页重建 |

`NewsDetailPage`（`/news/:id`）**没有** watch params，是全站唯一「靠重建刷新」的页面 —— 这正是选 `path` 而非 `name` 的理由。

## 5. 已落地的改动

### 5.1 `src/App.vue`

```diff
- <component v-if="!activeRoute.meta?.keepAlive" :is="Component" :key="activeRoute.fullPath" />
+ <component v-if="!activeRoute.meta?.keepAlive" :is="Component" :key="activeRoute.path" />
```

并补了一段注释，写明两种错误粒度各自的后果（防止第三次复发）。

### 5.2 `src/views/Newsroom/index.vue`

深链 `?news=` 原本只在 `onMounted` 消费一次；不再重建后需自响应，已按既有 `query.q` / `query.filter` watch 的同款风格补上：

```js
watch(() => route.query.news, (raw) => {
  const id = typeof raw === 'string' ? raw.trim() : '';
  if (!id) return;
  const target = newsData.value.find((n) => String(n.id) === id);
  if (target) showModal(target);
});
```

`onMounted` 里的消费保留，负责首次进入 / 刷新时的落点。

### 5.3 护栏（两条，分别位于不同层）

1. **单元（源码级不变量）** — `tests/unit/global-error-boundary.test.js` 新增一条，与 boundaryKey 那条同款：

   ```js
   expect(appTemplate).toContain(':key="activeRoute.path"');
   expect(appTemplate).not.toContain(':key="activeRoute.fullPath"');
   ```

2. **探针（行为级）** — `scripts/probes/probe-dm-lottery-entries-jump.mjs` 新增：

   ```js
   const listReqs = entryRequests.map((u) => decodeURIComponent(u)).filter((u) => u.includes('select=id,lottery_id'));
   check('切表只发 1 次列表请求（组件未被重建）', listReqs.length === 1, `列表请求 ${listReqs.length} 次`);
   ```

   （注意 `request.url()` 是编码后的，逗号会变 `%2C`，必须先 `decodeURIComponent` 再匹配列名。）
