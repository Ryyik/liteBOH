# 重构验证协议（2026-09-29）

> 适用场景：**拆组件、搬代码、外置 CSS、删死代码**这类"不改变行为"的重构。
> 这类改动的失效是**静默的** —— 没有报错、没有测试变红，只是某个样式不生效、
> 某个事件没人接、某段逻辑被漏掉。所以验证必须**分层且每层都说明能力边界**，
> 而不是跑一遍 `verify` 绿了就宣布没事。

---

## 一、为什么 `verify` 绿了还不够

本仓库的 `verify` 是 **lint + type-check + 单测 + 8 道源码门禁**，它覆盖的是
「源码静态正确性」。而拆分类重构的失效恰恰**不在**这个范围内：

| 真实发生过的静默失效 | `verify` 能抓到吗 | 为什么 |
| --- | --- | --- |
| scoped CSS 的 `[data-v-x]` 与 JS 侧 scope id 不配对 → 样式不生效 | ❌ | 两侧都在源码里"看起来正常"，只有产物里能比 |
| `getForumImageKey` 两处实现漂移 → 图片已加载态失效 | ❌ | 两边各自语法正确，是**跨文件契约**不一致 |
| 外置 CSS 后 `!important` 被记成"新增" | ⚠️ 半 | 门禁**按文件**记基线，搬家会被判成新增（需人工判断是否搬家） |
| 新 CSS 还没 `git add` → 门禁用 `git ls-files` 枚举，**根本没扫到** | ❌ | 假绿：门禁绿 ≠ 文件被检查过 |
| prettier 重排后逐字断言假红 | ❌ | 是**假红**不是真问题，但会掩盖真问题 |
| 移动端菜单 `top: 64px` 与导航栏实际几何不一致 → 一条缝 | ❌ | 纯运行时视觉，静态无感 |

**结论：验证必须分层，且每层要清楚自己证明不了什么。**

---

## 二、六层验证（L1–L6）

### L1 静态层 —— 能力：语法/类型/结构/预算

```bash
npm run verify     # lint + type-check + 单测 + 8 道门禁 + 棘轮总账
```

**证明**：没有语法错误、类型错误、结构违规、预算超标。
**证明不了**：跨文件字符串契约、产物级一致性、运行时行为、视觉。

> ⚠️ **门禁用 `git ls-files` 枚举文件** —— 新增文件在 `git add` 之前**不会被扫到**。
> 所以「verify 绿」必须在**暂存之后**再确认一次。本会话踩过：外置 CSS 后第一次
> `verify` 是绿的，但那 4 个新 CSS 根本没被检查；`git add` 后重跑才报出 3 条。

### L2 单测层 —— 能力：行为契约

包含在 `verify` 里（当前 131 文件 / 2161 断言）。
**证明**：被断言的**具体行为**没变。
**证明不了**：没被断言的路径（本仓库大量 UI 行为没有单测覆盖）。

### L3 产物层 —— 能力：**证明"纯搬运"**（拆分类重构的核心证据）

```bash
# 改动前先留一份产物
mv dist-check /tmp/dist-before && npx vite build --outDir dist-check
# 改动后构建，再对比
npx vite build --outDir dist-check
node scripts/compare-builds.mjs /tmp/dist-before dist-check
```

它做四件事（L1–L4，见下），其中最关键的是 **声明级对比**：把变化过的 CSS
剥掉 `[data-v-*]`、把 8 位 scope 哈希后缀归一成 `-<scope>` 之后**逐条规则比对**。
差异只剩哈希本身 → 说明改动**语义中性**。

**证明**：产物结构、CSS 规则集合、体积变化**精确符合预期**（本会话用它证明过
CSS 外置 2,970,170 字节完全一致；也用它反证 ForumMain 删的确实是死代码 ——
chunk 字节不变，因为死代码本就被 tree-shaking 消掉了）。
**证明不了**：运行时行为、视觉。

### L4 配对层 —— 能力：排除"样式静默不生效"

已含在 `compare-builds.mjs` 里：**CSS 侧出现的每个 scope id，是否在 JS 侧同名出现**。
Vue 的 scoped CSS 依赖两侧 id 配对，不配对时**不会报错**，只是样式不生效 ——
这一层专门堵这个洞（L3 的规则比对**证明不了**它）。

### L5 运行时层 —— 能力：真实交互

```bash
node scripts/probes/<相关探针>.mjs
```

按改动面选跑（见 `AGENTS.md` §2 的「改动 → 必跑门禁」表）。
**证明**：真实浏览器里的交互与渲染。
**证明不了**：探针没覆盖的路径。

### L6 人眼层 —— **必须明示为人工步骤，不要假装自动化覆盖了**

视觉回归（间距、配色、层级）**没有自动化路径**。改到样式就必须人工看一次，
并在提交信息里写明「已人工确认」或「待确认」。

> ⚠️ 最危险的不是"没验证"，而是**把没验证的说成验证过了**。本会话反复出现
> 「我以为工具在证明，其实工具在瞎报」—— 所以每层的**盲区都要写出来**。

## 三、按改动类型选层

| 改动类型 | 必跑 |
| --- | --- |
| 删死代码 | L1 + L2 + L3（产物应字节不变，因为死代码本被 tree-shaking 消掉） |
| 搬代码 / 拆 composable | L1 + L2 + L3 + L4 |
| 外置 CSS / 改样式 | L1 + L2 + L3 + L4 + **L6**（+ 相关 L5） |
| 改运行时行为 | L1 + L2 + L5 + **L6** |

## 四、本协议的自身盲区（诚实清单）

1. **动态构造的字符串契约抓不到**：`` `badge-${type}` ``、`classList.add(variable)`、
   `window[name]()` 这类运行时拼出来的名字，静态与产物层都看不见。**只能靠 L5/L6。**
2. **`compare-builds.mjs` 的文件名哈希归一可能过宽**：若某个真实文件名恰好形如
   `-XXXXXXXX`，会被误归一。概率极低但存在。
3. **L3 只对"变化的 CSS"做声明级对比**：若 CSS 文件被增删（而非修改），
   它不适用，会明确报出「需人工看」而不是假装通过。
4. **门禁覆盖 ≠ 全量覆盖**：本仓库仍有门禁覆盖不到的契约（见上表）。

## 五、附：清理 unused-vars 的手法与风险分级（2026-09-29）

> 背景：仓库有 **189 条存量 `no-unused-vars` 警告**（两条规则都配成 `'warn'`，所以 `verify` 是绿的）。
> 2026-09-29 起 `npm run lint` 带 `--max-warnings 189`，**新增一条即 exit 1**；清理后请把数字改小。
> 这一段记录「怎么清」，来源是已删除的一次性脚本 `scripts/fix-unused-vars.mjs`（见文末说明）。

### 四个子类的风险**完全不同**，不能一把梭

| 子类 | 形态 | 手法 | 风险 |
| --- | --- | --- | --- |
| A 未用 catch 参数 | `catch (e) {}` | 改 `catch {}` | **零风险**（只去掉绑定） |
| D 未用函数参数 | `function f(a, unused) {}` | 改名 `_unused`（约定 `argsIgnorePattern: '^_'`） | **零风险** |
| B 未用导入 | `import { X } from '…'` | 删说明符 | **零风险**（具名导入无副作用） |
| **C 未用声明/变量** | `const { pptx, preset } = ctx;` / `const primary = color(...)` | 删那一项或整条 | **有风险** ⚠️ |

### C 类的两条硬规矩

1. **先看右值是不是纯表达式**。`const x = doSomething()` 删掉会**连副作用一起丢**——
   这不是"清理死代码"，是**改行为**。删之前必须人读一遍 RHS；`const { a } = obj` 这类解构是纯的。
2. **多行解构里只删那一项，保留整条解构语句**。`const { pptx, preset } = ctx;` 里 `pptx` 没用 →
   删 `pptx`，**不要**删整条（同批还有 `preset` 在用）。整条删 = 运行时 `undefined`。

### 两个实测过的坑

- **同行 + 别名 + 多说明符**：`import { Image as ImageIcon, Foo } from '…'`。按"局部名"做正则替换的脚本
  会把它删成 `import { Image as , Foo }` → **语法错误**。全仓目前只有 `src/views/PostDetail/PostDetailMain.vue:8`
  一处符合该形态（且 `ImageIcon` 在用），所以没触发过——**但这是一颗定时炸弹，别写这种脚本**。
  正解：删**整个说明符**（`Image as ImageIcon, ` 一起），或干脆手动。
- **默认导入 / 命名空间导入一律别用脚本动**：`import X from '…'` 被误判后会把**模块路径**删掉。
  另一版脚本就栽在这。

### 关于被删掉的那个脚本

`scripts/fix-unused-vars.mjs`（2026-09-29 删除）按设计**只**做 A / B / D 三类零风险项——
文件头写得很清楚，第 175 行还专门注明"只处理具名导入"。它从来没有（也不该）处理 C 类。
它被删的原因是：**活干完了、全仓零引用（不进任何 npm script 或文档），却仍带着上面那颗别名炸弹**。
清理 C 类时**不要**去找类似的"一键"工具，按上面的规矩逐个读。
