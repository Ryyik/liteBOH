## 0. 一句话背景

数据管理面板（`/admin/data-management`）有两个**会让运营做出错误决策**的缺陷：

1. **导出只导当前页**（10/20/50/100 条），toast 却说「数据导出成功」，没有任何条数提示 → 对账/发奖用错数据；
2. **筛选到 0 条时**，页面说「这张表还没有数据，点击新增」，而「清空筛选」按钮藏在折叠的筛选条里 → 用户以为数据丢了，或者去新增一条不符合筛选的数据。

本次只修这两件事。**不碰布局、不碰路由、不碰主题、不碰批量选择语义。**

### 2.3 改造点 1：抽出纯函数 `buildCsvContent`

**新建 `src/views/DataManagement/composables/csv-export.js`**（不要放进 `useDataAdminExport.js`：那个模块顶层会初始化 Supabase 客户端，单测 import 时会因为没有 env 直接抛错）：

```js
/**
 * 生成 CSV 文本（含表头）。纯函数，不碰 DOM / 网络，供单测直接调用。
 * @param {Array<Object>} rows     数据行
 * @param {Array<Object>} columns  [{ key, label }]
 * @returns {string} 带 BOM 之外的纯 CSV 文本（BOM 由调用方加）
 */
export const buildCsvContent = (rows = [], columns = []) => {
  const header = columns.map((col) => `"${String(col.label ?? '').replace(/"/g, '""')}"`).join(',');
  const lines = (rows || []).map((item) =>
    columns
      .map((col) => {
        let val = item?.[col.key];
        if (typeof val === 'object' && val !== null) val = JSON.stringify(val);
        let cell = String(val ?? '');
        // CSV 注入防护：以 = + - @ 开头加单引号（保持现有行为）
        if (/^[=+\-@]/.test(cell)) cell = "'" + cell;
        return `"${cell.replace(/"/g, '""')}"`;
      })
      .join(','),
  );
  return [header, ...lines].join('\n');
};
```

> 注意：现有实现的**表头没有加引号**，新实现统一加引号（更稳），这是允许的行为变化；但**CSV 注入防护必须保留**（`= + - @` 前缀加 `'`）。
>
> 然后在 `useDataAdminExport.js` 顶部 `import { buildCsvContent } from './csv-export.js';`，并删掉原 `exportData` 里内联的 CSV 拼装。

然后 `exportData` 改成：

### 2.5 改造点 3：`DataAdmin.vue` 注入 `fetchAllFilteredRows`

放在 `fetchTabData` 附近（约 `:3994` 之后），**必须复用与列表完全相同的筛选/排序装配**，否则导出的不是"当前筛选结果"：

```js
const EXPORT_BATCH = 1000;
const EXPORT_MAX_ROWS = 50000;

/** 按当前筛选条件拉取全部行（供「导出全部筛选结果」用）。 */
const fetchAllFilteredRows = async (tabId = currentTab.value) => {
  const table = dataConfig[tabId]?.table;
  const selectColumns = TAB_SELECT_COLUMNS[tabId];
  if (!table || !selectColumns) return [];

  // ⚠️ 每次循环必须重建 query：Supabase builder 的 .range() 会原地改状态，
  //    复用同一个对象会导致第二批 range 叠加，拿到空数组或错位数据。
  const buildQuery = () =>
    applySearchAndSortUtil({
      query: supabase.from(table).select(selectColumns),
      tabId,
      keyword: searchQuery.value,
      statusFilter: statusFilter.value,
      dateFrom: dateFromFilter.value,
      dateTo: dateToFilter.value,
      advancedRules: activeAdvancedRules.value,
      sortKey: sortKey.value,
      sortOrder: sortOrder.value,
      configs: {
        tabSearchFields: TAB_SEARCH_FIELDS,
        statusFilterFields: STATUS_FILTER_FIELDS,
        dateFilterFields: DATE_FILTER_FIELDS,
        tabSortColumns: TAB_SORT_COLUMNS,
        tabDefaultSort: TAB_DEFAULT_SORT,
      },
      allowedAdvancedFields: (currentColumns.value || [])
        .filter((c) => !c.virtual)
        .map((c) => c.key),
    });

  const rows = [];
  for (let from = 0; ; from += EXPORT_BATCH) {
    const { data, error } = await buildQuery().range(from, from + EXPORT_BATCH - 1);
    if (error) throw error;
    const batch = data || [];
    rows.push(...batch);
    if (batch.length < EXPORT_BATCH) break;
    if (rows.length >= EXPORT_MAX_ROWS) {
      throw new Error(`结果超过 ${EXPORT_MAX_ROWS} 行，请先缩小筛选范围再导出`);
    }
  }
  return rows;
};
```

把它加进 `createExportCenter({...})` 的调用参数里（在 `DataAdmin.vue` 里搜 `createExportCenter(` 找到注入点）。

## 3. 任务 B：空状态三分支

### 3.1 现状代码（`DataAdmin.vue:616-634`）

```html
<div v-else-if="totalRecordCount === 0 && hasLoadedOnce" class="empty-state">
  <div class="empty-icon">📭</div>
  <h3>暂无数据</h3>
  <p>
    {{ searchQuery ? '没有找到匹配的数据' : '当前模块还没有数据，点击新增按钮添加第一条记录' }}
  </p>

    <Plus :size="16" />新增数据
  </button>

```

**问题**：`totalRecordCount` 是**含筛选**的 count（`DataAdmin.vue:3074-3080` 注释明确）。只用了状态/日期/高级筛选时，`searchQuery` 为空 → 走「还没有数据」分支，并给「新增」主按钮。而「清空筛选」按钮在 `.filter-bar` 内，`showFilterBar` 折叠时**页面上没有任何重置入口**。

### 3.2 目标行为（三分支，判定顺序不可换）

| 条件 | 标题 | 说明 | 按钮 |
| --- | --- | --- | --- |
| `searchQuery` 非空 | 没有匹配的记录 | 没有找到包含「xxx」的记录。 | 清除搜索 + 清除全部筛选 |
| 有筛选但无搜索 | 没有符合筛选条件的结果 | 当前筛选条件下没有记录。 | 清除全部筛选 |
| 无搜索无筛选 | 暂无数据 | 这张表还没有记录。 | 新增（沿用 `canCreateCurrentTab && !isModerationTab`） |

> 顺序原因：`hasActiveFilters` **包含** `searchQuery`（`useDataAdminFilterState.js:91-97`），所以必须先判搜索，否则永远进不到搜索分支。

### 3.3 新增纯函数 `src/views/DataManagement/composables/data-admin-empty-state.js`

```js
/**
 * 空状态判定（纯函数，供单测）。
 * @returns {null | {kind, title, description, showClear, showCreate}}
 */
export const resolveEmptyState = ({
  totalCount = 0,
  searchQuery = '',
  hasActiveFilters = false,
  canCreate = false,
} = {}) => {
  if (Number(totalCount) > 0) return null;

  const keyword = String(searchQuery || '').trim();
  if (keyword) {
    return {
      kind: 'no-match',
      title: '没有匹配的记录',
      description: `没有找到包含「${keyword}」的记录。`,
      showClear: true,
      showCreate: false,
    };
  }
  if (hasActiveFilters) {
    return {
      kind: 'filtered-out',
      title: '没有符合筛选条件的结果',
      description: '当前筛选条件下没有记录，清除筛选后可查看全部。',
      showClear: true,
      showCreate: false,
    };
  }
  return {
    kind: 'empty',
    title: '暂无数据',
    description: '这张表还没有记录。',
    showClear: false,
    showCreate: Boolean(canCreate),
  };
};
```
