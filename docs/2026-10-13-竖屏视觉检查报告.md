## 二、AI 相关（重点）

### A1 ·【P0】AI 设置抽屉竖屏不可滚动 —— 下半部分分区全部不可达

- **描述**：竖屏打开 AI 设置（抽屉）后，内容总高约 **2344px**（含 7 个分区），而视口只有 844px。实测**没有任何可滚动祖先**：
  - `.ai-settings-body`：`scrollHeight == clientHeight == 2344`（不构成滚动容器）；
  - `.ai-settings-drawer`：`scrollHeight=2532 / clientHeight=844`，但 `overflow-y: hidden`；
  - 即：**超出的约 1500px 内容被裁掉且无法滚动到**。点顶部导航（如「用量与订阅」）只会切换标题高亮，内容纹丝不动（`jumpTo` 的 `scrollTo` 因 body 不可滚动而失效）。
  - 受影响分区：**外观 / 用量与订阅（AI 额度）/ 呼出方式 / 数据**——涉及 AI 额度百分比展示，属于用户高频入口。
- **位置**：`src/views/BOHAI/BOHAI/components/BohaiSettingsPanel.vue`。根因在 L2437 的 `@media (max-width: 768px)` 块：`.ai-settings-drawer` 转 `flex-direction: column` 后，`.ai-settings-main`（L1940，只有 `min-width: 0`）**缺 `min-height: 0`** ⇒ main 被内容撑高 ⇒ `.ai-settings-body`（L1984，`flex:1; min-height:0; overflow-y:auto`）拿不到受限高度，整条 flex 高度约束链断裂。
- **证据**：`04-ai-chat-settings-top.png`、`zz-follow-settings-usage2.png`、`zz-follow-nav-scrolled.png`（点了「用量与订阅」，`bodyScrollTop` 仍为 0）；实测数据：`bodySh=2344=bodyCh`、`drawer 2532/844 overflow:hidden`、scroller 探测为空。
- **建议**：在 `≤768` 断点块内补 `.ai-settings-main { min-height: 0; }`（一处即可恢复整链）；顺手给「抽屉不可滚」加一条探针断言（`body.scrollHeight > body.clientHeight` 且 `scrollTop` 能变化）。

### A2 ·【P1】设置抽屉顶部导航：竖排条 + 横滑裁切 + 被导航岛压住

- **描述**（三个子问题同区）：
  1. **「返回应用」被压成 57×113 的竖排条**：文字逐字竖排（返/回/应/用），13px 字在 57px 宽的条里折了 4 行，图标被全局导航岛挡住一半；
  2. **分区 tabs 横向溢出**：`.ai-settings-nav` `scrollWidth=798 / clientWidth=390`，默认可视 2.5 项；第 3 项「记忆与上下文」文字在视口右缘**被切断**（读到「记忆与上下」），7 个分区中 4 个需横滑才能触达，且**无渐隐/箭头等滚动提示**；
  3. **与全局导航岛重叠**：抽屉全屏打开时 `#unified-nav-container`（z-index 9999）仍浮在最上层，压住抽屉左上角（苹果 Logo 覆盖「返回应用」icon 区域）。暗色下同样。
- **位置**：`BohaiSettingsPanel.vue` ≤768 块（`.ai-settings-nav` / `.ai-settings-nav-item`）+ 全局导航未随全屏抽屉让位。
- **证据**：`04-ai-chat-settings-top.png`、`zz-follow-settings-nav.png`、`zz-dark-ai-settings.png`；实测：`back-app rect = 57×113`，tabs `sw=798/cw=390`。
- **建议**：① `.ai-settings-back-app { flex:none; white-space:nowrap }`（或竖屏收成纯 ← 图标 + aria-label）；② tabs 行给右缘渐隐或把 7 个分区改成两行 wrap（竖屏分区不多，wrap 成本低）；③ 抽屉打开时把全局导航岛临时隐藏或降到抽屉层级之下（至少让出安全区）。

### A3 ·【P1】「密钥与模型」三个对话框无样式 —— 弹层掉进文档流，看不到

- **描述**：点「添加平台 / 添加 Key / 从平台拉取 / 手动添加模型」后，对话框**不以浮层出现**。实测三个对话框的 computed style：`.g-dialog-overlay` 与 `.g-dialog` 均为 `position: static; background: transparent`，被渲染在页面**文档流底部**（打开瞬间 rect.y≈1878，位于页面最下方；滚动时随文档移动，`scrollY 700 → dialogY 1178`）。竖屏下用户只能看到按钮「毫无反应」（实际要滚到页面最底部才看到一坨无样式表单）。
- **位置**：`src/views/DataManagement/components/KeysAndModels.vue`（L250 / L357 / L425 三处使用 `.g-dialog-overlay`）——**该系列样式仅定义在 `FreemodelsConfig.vue` 的 `<style scoped>`（L857-870，`position:fixed; inset:0; z-index:1100` 等），无法作用于 KeysAndModels 的元素**；KeysAndModels 自身（含 scoped `@import` 的两个 css）没有任何 `.g-dialog*` 定义。
- **证据**：`zz-km-dialog-probe-1.png` / `zz-km-dialog-probe-2.png`（对话框「不在」）+ `zz-km-m390-dialog.png`（页面底部的裸表单碎片）；computed 实测如上。
- **建议**：把 `.g-dialog*` 系列从 `FreemodelsConfig.vue` scoped 里提到共享的非 scoped 样式（如 `styles/overlays.css`，或去 scoped 的共享层），两个组件都用同一份；补一条探针断言「打开对话框后 `.g-dialog-overlay` 的 computed position 为 fixed 且 rect 在视口内」。

### A4 ·【P1】admin AI 配置：初始加载 `?section=` 不带 `tab` 时内容错表

- **描述**：直接打开 `/admin/data-management?section=keys-models`（或 `moderation-model`、`lab-ai-model`）——分组头显示「AI 配置」、模块 tab 行也在，但**内容区渲染的是「用户管理」表**（33 条记录/用户卡片），4 个模块 tab 全部无选中态。点一下任意模块 tab 才恢复。桌面 1440 同样复现 ⇒ 与视口无关。
- **位置**：`src/views/DataManagement/DataAdmin.vue:1755`：
  `const currentTab = ref(isValidAdminTab(routeQueryTab) ? routeQueryTab : 'users');`
  初始加载只认 `query.tab`，兜底**硬编码 `'users'`**，没有查 `ADMIN_SECTION_DEFAULT_TABS`（该表目前只在点击路径 `useDataAdminNavigation.js:173` 使用）。
- **证据**：`zz-admin-m390-entry.png`、`zz-admin-d1440-entry.png`；对照：带 `&tab=keys-models` 的链接正常（`zz-admin-m390-keys.png`）。分享链接/书签/外链只带 `?section=` 的场景会直接中招。
- **建议**：初始 `currentTab` 改为三级兜底：`合法 query.tab` → `ADMIN_SECTION_DEFAULT_TABS[activeAdminSection]` → `'users'`；把这段抽成一个可单测的纯函数，并补单测（`?section=keys-models` 无 tab ⇒ 落 `keys-models`）。

### A5 ·【P2】admin 页顶栏在 390 下溢出 32px，右上角用户菜单被裁

## 附录 B · 方法与限制

- **采集器**：`scripts/probes/probe-portrait-visual-audit.mjs`。每面：注入登录态（pinia，user/admin 两档）→ 等渲染 → DOM 诊断 → 多档截图 → axe `color-contrast`；admin 面额外打桩 `api-key-vault` / `freemodels`（mock 数据）与 `admin_*` RPC。
- **DOM 诊断口径**：横向溢出（排除横向滚动容器，分「静态布局」与「transform/fixed 后代」两桶）；文本截断（`scrollWidth>clientWidth` / `scrollHeight>clientHeight`）；小字号（<11.5px 直接持有文本的元素）；遮挡采样（文本元素中心点 `elementFromPoint` 被 fixed/absolute 元素盖住 ≥2 次才报）。
- **限制**：① 伪造会话，无真实后端数据——AI 对话为**空态**、消息/概览为**空态或错误态**（其中「概览加载失败：您的账号已被封禁或禁言」是假会话下 RPC 失败的**误映射文案**，非本轮 UI 缺陷，但对真用户也会误导，建议顺手修错误映射）；② admin 的密钥/模型行为 mock 数据；③ 未覆盖：真实对话消息流排版、加载中/长列表骨架、Work 面板（桌面档）、全站暗色；④ 关于「移动模拟下 innerWidth 被拉大」的现象（如 admin=422）已按 `docScrollWidth` + 溢出元素落点交叉验证，避免误报。
- **复跑**：`node scripts/probes/probe-portrait-visual-audit.mjs`（全量 ~4 分钟）或 `--only=04,10` 子集；产物覆盖到同目录。
