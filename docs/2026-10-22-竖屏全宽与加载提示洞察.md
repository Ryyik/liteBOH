# 竖屏「全宽布局 + 加载提示」专项洞察（390×844）

- **日期**：2026-10-22 · **视口**：390×844 @2x（`isMobile + hasTouch`，浅色主题）
- **采集器**：`docs/demos/portrait-adaptive-audit.mjs`（本次新建，可复跑；**诊断脚本不是探针** —— 只出数不做断言）
- **产物**：`debug-screenshots/portrait-adaptive-2026-10-22/`（逐页 `-w-*` 宽度截图 / `-slow` 慢网截图 / `adaptive.json` 数值）
- **与 10-13 报告的分工**：那份查溢出/截断/对比度；这份只查两件事——**内容有没有吃满竖屏宽度**、**请求未回时用户看到什么**。

**方法**：每页两个场景。① 正常网络等数据落定后量 DOM（多列网格的实际列宽、并排卡片宽度、容器留白）；② **只延迟数据面**（`/rest/v1/**`、`/rpc/**` 挂起 15s，鉴权与静态资源放行），在导航后 4s 取快照，此时所有数据请求必然还在 pending —— 这个窗口里看到的 UI，就是用户弱网下真实看到的东西。

**已知局限（必须先说）**：登录态是 pinia 注入的伪会话，`getCurrentUser()` 返回 null。所以**依赖真实会话的页面（消息、概览、资产、礼物、咖啡馆）的慢网结论不可信**——它们显示空态是「没用户」而不是「没加载」。本报告只采信公开页（首页/论坛/商店/抽奖/活动/新闻/相册）与代码层证据。

## 二、竖屏全宽：该改哪里，哪里别乱改

### W1 ·【P1】全宽做到了，但顶部被浮动导航岛吃掉

这不是「内容没铺满」，恰恰相反——**内容铺满了，顶部却没有为那座 `position: fixed; z-index: 9999` 的导航岛留安全区**。

实测（`uspace-assets-w-top.png`、`uspace-posts-w-top.png`）：页面第一个内容块「顶部动态导航已启用」的提示条上半被岛切掉，「空间 / 资产 / 印象」三个 tab 紧贴岛下缘，视觉上像被压扁。uspace 五个 tab 全部复现。

- 影响面：`/user-space?tab=*` 全部 5 个 tab + `/user-space/assets` 页头。
- 修法方向：页面根容器 `padding-top` 接一个 `--nav-island-h`（或 `env(safe-area-inset-top) + 岛高`），而不是每个页面各写一份。10-13 报告 A2 提过「抽屉打开时让导航岛让位」，同一个根因的另一面。
- ⚠️ 别用 `margin-top` 顶——那会让 sticky 子元素的吸顶位置跟着下移，签到/筛选条会浮在内容中间。

### W2 ·【P2】多 tab 一行塞满

| 位置 | 现状 | 实测/证据 |
| --- | --- | --- |
| 资产页二级 tab | 概览/装扮/积分/订阅/订单/抽奖/赞助 7 项刚好塞满 390，每项 ~50px | `uspace-assets-w-top.png`；10-13 报告 U4 已记「再增一项即溢出」 |
| admin 模块 tab | 密钥与模型/BOHAI 模型/AI 额度/审核模型/实验室模型，总宽 443px vs 容器 357px，第 5 项初始不可见 | 10-13 报告 A6（实测 `sw=443 / cw=357`） |
| 首页顶部 tab | 官方/最新/关注/新闻/活动/成员 6 项，每项 ~58px，可读但已到临界 | `home-w-top.png` |

共同点：**都用「等分一行 + 不 wrap」**。竖屏下正确解法是 `flex-wrap: wrap`（分区不多，两行成本低）或横滑 + 右缘渐隐提示；`overflow-x: auto` 而不给渐隐，用户根本不知道右边还有。

### W3 ·【P2】admin 统计卡竖屏仍按 4 列（静态推断，未实测）

```
src/views/DataManagement/components/ApiKeyConsole.vue:1223   .g-api-key-summary     repeat(4, minmax(0,1fr))
src/views/DataManagement/components/FreemodelsConfig.vue:786 .g-freemodels-summary  repeat(4, minmax(0,1fr))
src/views/DataManagement/styles/base.css:369                 .stats-section         repeat(4, 1fr)
src/views/DataManagement/styles/console.css:1922             .overview-status-bar   repeat(4, 1fr)
src/views/DataManagement/styles/google-components.css:482    .g-bar-grid            repeat(7, 1fr)
```

390 视口减两侧留白 ≈ 358px，4 列含 gap 后每列 ~80px，7 列时 ~45px——「活跃 Key / 总调用 / 失败率」这类「数值 + 标签」卡片在这个宽度下必然折成两行或溢出。10-13 报告已证明 admin 确实被移动端访问（顶栏 32px 溢出、tab 行溢出都是竖屏巡检抓到的），所以这条不是「后台只在桌面用」可以搪塞的。

### 该改的边界：这些地方**不要**动

避免下一轮 AI 凭直觉「统一改成单列」，以下是实测合格、改了反而更差的：

- **弹窗体系**：`width: 100% + max-width 440~600px + 外层 16px padding`（`pa-modal` / `bind-prompt-sheet` / `edit-modal`）在 390 下实际宽 358px，已经是「近全宽卡片」的正确做法，不该改成 100vw。
- **商店商品区**：主视觉全宽 + 商品卡 2 列 174px（`shop-w-top.png`），两列是电商竖屏的通行密度，改单列会拉长滚动。
- **首页 feed / 新闻流 / 活动卡 / 生日页**：全宽单列，帖子卡、大图卡、按钮堆叠都吃满 390（`home-w-top.png`、`birthday-w-top.png`）。
- **journey 的 18/9/8 列网格**：`stratum-cut-face`、`memory-inventory` 是像素装饰色带，不是内容栅格，列宽 19~49px 是设计。
- **用户空间页头 3 列**：`user-center-page-header-inner` min 列 52px 看着窄，但那是「返回 / 标题 / 操作」的固定结构，塌成单列反而丢返回键位置——真要动的是它的顶部安全区（W1），不是列数。

## 三、加载提示：不是「有没有骨架」，是「有没有出口」

### 先说好消息（阴性结论，别重复排查）

公开页与详情页的骨架覆盖率是 **6/6 + 2/2**，慢网 4s 快照下的可见加载指示数量：

| 页面 | 指示器数 | 形态 |
| --- | --- | --- |
| 首页 feed | 52 | 卡片骨架（头像/标题/正文行） |
| 新闻 `/newsroom` | 48 | 日期/分类/标题块 |
| 相册 `/albums` | 18 | 网格骨架 |
| 商店 `/shop` | 12 | `product-skeleton` 卡 |
| 抽奖 `/lotteries` | 12 | 封面/标题/行 |
| 活动 `/activities` | 6 | 头部 + 卡片 |
| 新闻详情 `/news/1` | 7 | `ndp-skeleton` 全套 |
| 帖子详情 `/forum/post/1` | 29 | `detail-skeleton-block` + 「加载中…」 |

首屏另有 `App.vue` 的 `bootReady` 骨架与 `index.html` 内联兜底（10s/12s 两道超时），这条链路是完整的。

**`Messages/index.vue` 是这一块的标杆**：`withTaskTimeout` 包住每一步 + auth 竞态补拉一次 + `dataLoadedOnce` 保证「拿不到用户也必须落空态」+ 独立错误文案（L1994-2054）。要统一加载规范，照它抄。

### L1 ·【P1】没有超时出口 —— 全仓系统性问题

```
Grep "withTaskTimeout" src/  →  只命中 2 个文件：
  src/views/user-center/Messages/index.vue
  src/views/user-center/Address/index.vue
```

其余所有页面的 `await getXxx()` / `await supabase.from(...)` 都没有超时。Supabase JS 的 fetch 没有默认超时，于是**网络挂起（不是报错）时骨架永远转下去**。

实测证据：把数据面挂起 15s，`/shop`、`/lotteries`、`/activities`、`/albums` 在 4s 快照时全部停在骨架；`CommunityLotteries` 的 `loadLotteries`（L912-932）只在 `catch` 里落 `loadError`，**永不 resolve 就不会进 catch**。

- 这是「加载提示」最贵的一类缺陷：提示在了，但用户等到天荒地老也不知道该刷新。
- 修法：在 API 层统一包超时（`withTaskTimeout` 已有实现，只是没推广），或给 Supabase client 的 `global.fetch` 加 `AbortSignal.timeout()`。**一处改，全站受益**，比逐页加骨架性价比高一个量级。

### L2 ·【P2】骨架和真实内容不是同一个布局

| 页面 | 骨架实测 | 真实内容 |
| --- | --- | --- |
| `/lotteries` | `community-lottery-card` 2 列，列宽 96px | 全宽单列卡片 |
| `/newsroom` | `secondary-news-item` 2 列，列宽 96px | 主卡全宽、列表卡全宽 |

骨架屏的价值是「占位尺寸 = 最终尺寸」，列数不一致会在数据回来那一刻整页重排——比没有骨架更难受（CLS 跳动）。修法：骨架容器复用真实列表的同一套栅格类，别另写一份。

### L3 ·【P3】用 `--` 冒充加载态

`src/views/Birthday/index.vue:563,569`：

```js
if (!celebrationDate.value) return '--';
```

「距离生日还有 `--` 天」——用户分不清是「还没填生日」还是「正在加载」。同类写法：资产页积分卡加载中显示 `0`（`ah-skeleton-points-card` 只在部分位置生效）。建议：数据未就绪时不渲染数字位，或复用现有 `skeleton-line`。

### L4 ·【P3】专题页零骨架

静态扫描 + 实测一致：`/gift`、`/anniversary-cafe`、`/boh-8-years-journey`、`/character-book` 模板内没有任何 skeleton/加载文案。其中 journey 实测 `docH = 36030px`（3.6 万像素长页），下方「参与名单 / 排行榜」类区块依赖 Supabase，弱网下滚到那里就是一片空白——**首屏没问题，深处有洞**，这类缺陷最容易漏测。

### L5 ·【P3】后台组件打开即空表

`ModerationModelConfig.vue`：`onMounted` → `await loadDbConfig()`，但整个 `<script setup>` 里没有 loading 变量，模板也没有占位 ⇒ 打开「审核模型」页先看到空表格，数据回来再「凭空长出」几行。同族待查：`EditDrawer.vue`、`AdminContentPublishModal.vue`、`AvatarConsole`（首屏取数部分）。

## 四、修复优先级（按性价比）

1. **L1 请求超时下沉到 API 层** —— 一处改全站受益，弱网体验提升最大，且能顺手统一错误文案；
2. **W1 顶部安全区** —— 影响 uspace 全部 5 个 tab，用户第一眼就看到，一个变量解决；
3. **W2 多 tab 换行/渐隐** —— 资产页 7 项、admin 5 项，改 `flex-wrap` 即可；
4. **L2 骨架列数与真实对齐** —— 抽奖、新闻两处，消除加载完成时的重排；
5. **W3 admin 4 列降档** —— 4 处 `repeat(4)` + 1 处 `repeat(7)`；
6. **L3/L4/L5 打磨** —— `--` 占位、专题页骨架、后台 loading。

改完复跑：`node docs/demos/portrait-adaptive-audit.mjs --only=shop,lotteries,uspace-assets`
（`--skip=width` 只测加载，`--skip=slow` 只测宽度）。

## 附录 · 判据与已知误报

- **宽度判据**：遍历所有 `display:grid` 且解析出 ≥2 列的容器，报「列数 + 每列像素宽 + 容器宽」；`minCol < 120px` 记为窄列。并排同宽兄弟（宽 0.3~0.85 vw 且有圆角/背景）记为「半宽卡」。
- **加载判据**：可见元素中 class 命中 `skeleton|loading|spinner|shimmer`、或 `aria-busy="true"`、或短文本命中「加载中」的，计为加载指示；同时记录 `body.innerText` 长度与 `docH` 判断白屏。
- **已知误报（不要当缺陷）**：
  - `uspace-messages` / `overview` / `assets` / `gift` 的慢网快照显示空态或错误态 —— **伪会话导致 `getCurrentUser()` 为 null**，不是加载态缺失；
  - `/gift` 显示登录墙同理；
  - `character-book` 本身是静态设定集，无请求；
  - `journey` 的 18/9/8 列网格是像素装饰，不是内容栅格。
