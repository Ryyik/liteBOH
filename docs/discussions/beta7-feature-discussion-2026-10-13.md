### 用户额外提出的关键问题

> **"BOHAI 感觉不够智能"**

这不是一个功能需求，而是一个**质量诊断**，可能涉及多个层面：

| 层面 | 症状 | 根因方向 |
|------|------|----------|
| 模型本身 | 回答泛泛、不够深 | Ultra 档绑 `openrouter/free`，免费模型能力天花板低 |
| 上下文不够 | AI 不了解用户/站点情况 | 检索连接器覆盖面不够、注入上下文太浅 |
| 只会说不会做 | 让它帮忙做事做不到 | 只有读连接器，没有写能力（tool use） |
| 规则太死 | 回答保守、千篇一律 | 否定式规则仍多于肯定式 |
| 记忆太短 | 跨轮忘记之前说的 | 长期记忆机制薄弱 |
| 响应慢 | 等太久觉得"卡" | 首字延迟已降到 1.6s，仍有感知空间 |

## 4. BOHAI 智能化提升方案（A/B/C/D）

针对"不够智能"问题，提出四个层面的改进：

### A. 模型升级（最快见效）

- **Ultra 换型**：把 `openrouter/free` 换成强模型（Claude/GPT-4o/Gemini Pro）—— 需先查库（§20 第 3 项）
- **智能路由**：按问题复杂度自动选模型，简单问题用快模型省额度，复杂问题切强模型
- **模型 A/B**：同一问题并行问两个模型，取更好的（成本高但质量天花板拉满）

### B. Tool Use / Function Calling（质变）

- **写连接器**：在现有 9 个读连接器基础上加写能力
  - `create_post`：帮用户起草并发布帖子
  - `save_to_collection`：帮用户收藏内容
  - `set_reminder`：帮用户设提醒
  - `create_activity`：帮运营建活动
- **多步规划**：复杂请求拆成多步执行（"整理周报" → 检索 → 分析 → 生成文档）

### C. 更深的上下文注入

- **用户画像注入**：每轮自动注入"用户是谁、发过什么、什么等级、最近关注什么"
- **站点动态注入**：AI 知道"站上最近在讨论什么、有什么活动在进行"
- **对话摘要记忆**：超过 N 轮后自动压缩成摘要，不丢关键信息但省 token

### D. 回答质量提升

- **肯定式规则**：否定式→肯定式（plans/024 已起步，P2-1 消融验证仍未做）
- **Few-shot 示例**：给 AI 看几个"好回答"范例对齐风格和深度
- **自评/重写**：生成后自评，低于阈值自动重写（psych-guard 雏形可泛化）

### 与选定项的关系

```
BOHAI 智能化提升（A+B+C+D）
  ├── B（Tool Use）→ 3（Work generators）自然落地
  │     "帮我做成 PPT" → AI 调 generate_ppt → 下载
  ├── 15（多模态输入）扩展 B 的输入面
  │     用户发图 → AI 看图分析 → 调工具处理
  └── C（上下文注入）让每个工具调用都带着用户语境
```
