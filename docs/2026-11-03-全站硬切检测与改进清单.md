# 全站硬切检测与改进清单（2026-11-03）

> 审计范围：`src/` 全部视图与组件（路由跳转、页面/组件切换、弹窗抽屉、加载与骨架屏、列表增删、主题切换）。
> 方法：静态排查四路并行（路由层 / 弹层 / 加载态 / 列表与状态），关键结论已人工复核源码。
> 已排除的「非硬切」正面项见文末附录 A；已确认干净的高频模块见附录 B。

## 〇、总评

局部动效纪律很好（tab 双向过渡、灵动岛、toast、多数弹窗、Shop/Cloud+ 图片淡入都有成熟实现），**硬切集中在四类系统性缺口**：

1. **路由级过渡全局缺失** —— App.vue 刻意撤回、plans/005 至今 TODO；
2. **主题切换零过渡** —— 全仓无 `startViewTransition`/全局颜色 transition；
3. **骨架⇄内容与图片淡入机制覆盖率低** —— `useImageLoaded` 只有 Shop 接入，骨架分支约 20 处裸 `v-if/v-else`；
4. **列表增删无 FLIP** —— 消息/评论/关注/影集等增删均为数组重写、瞬跳补位。

## P0 — 高影响（核心路径、高频感知）

### P0-1 路由级切换无过渡（含底栏「内容/我/图库」整页重挂）
- **位置**：`src/App.vue:452-503`（RouterView 内无 `<Transition>`）；`plans/005-add-router-view-fade-transition.md` Status: TODO
- **触发**：任意路由跳转——顶栏菜单、底栏三独立路由互切、进出 PostDetail/admin 等 hideNavbar 页
- **表现**：旧页瞬失、新页瞬现。keepAlive 与非 keepAlive 两个 `<component :is>` 分支都无包裹
- **原因**：2026-09-20 实现过一版但过渡类名从未生效（疑与外层 `<Suspense>` 接管顺序冲突），已刻意撤回，App.vue:453-468 注释明确「不要凭直觉加回来」
- **改法**：先做一轮专项验证（最小 repro 搞清 Suspense × Transition 解析顺序），通过后再按 plans/005 的 200ms fade 落地；护栏 `probe-route-switch` 需同步扩展「过渡类名确实被加上」的断言

### P0-2 主题切换全屏颜色一帧翻转
- **位置**：`src/utils/theme-manager.js:84-134`（`applyTheme()` 直接 `setAttribute('data-theme')` + `classList.toggle('dark')`，并批量写 10 个容器）
- **触发**：主题开关 / ThemeModal / 系统跟随（入口 6 处：UnifiedNavbar:975、ProfileMain:1467、CloudPlusMain:2191、Shop:390、UserSpaceMain:1953、DataAdmin:4025）
- **原因**：全仓 0 处 `startViewTransition`；dark-mode.css 无 transition 规则；无 html/body 级颜色过渡
- **改法（一行级）**：`applyTheme` 包 `document.startViewTransition(...)`（不支持的浏览器自动降级为瞬切）；或给 `html` 加 `transition: background-color .25s` + 变量消费端渐变（成本更高，不推荐）
