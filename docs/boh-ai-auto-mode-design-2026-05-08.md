# BOH AI Auto 模式落地方案

## 目标

Auto 模式不是第四个固定模型，而是一层“意图路由器”：用户不需要手动判断该开快速、思考、专业、Cloud+ 参考、Cloud+ 随手记还是公共记忆，BOH AI 根据输入自动选择。

## 当前首版已落地

1. 模式自动选择
   - Auto 主流程由 `Qwen/Qwen3.5-4B` 输出结构化分类结果。
   - 日常问答：走快速模式 `Qwen/Qwen3-8B`。
   - 复杂问题、方案设计、推理、复盘：走思考模式 `deepseek-ai/DeepSeek-R1-0528-Qwen3-8B`。
   - 内部资料/RAG 长文本整理：优先 `THUDM/GLM-Z1-9B-0414`。
   - 代码、报错、命令：走专业模式 `Qwen/Qwen2.5-7B-Instruct`。
   - Minecraft 指令：走专业模式 + 指令知识库与校验链路。
   - “总结我的最近日常”：走思考模式，并优先触发 Cloud+ 参考。

2. 公共记忆确认
   - 当用户分享明显的社群事实或社群事件时，Auto 不直接写入公共记忆库。
   - AI 会先询问保存到 Cloud+、公共记忆还是两者。
   - 用户回复同意后才写入，回复拒绝则跳过。

3. Cloud+ 参考确认
   - 当用户要求总结自己的最近日常，且 Cloud+ 参考未开启时，AI 会先请求授权。
   - 已授权但当前未开启时，Auto 会自动打开 Cloud+ 参考。
   - 快速模型也会判断“这次回答是否应该参考 Cloud+”。

4. Cloud+ / 公共记忆保存
   - 用户可以说“保存到 Cloud+”“写入公共记忆”“两者都保存”。
   - Auto 会统一进入确认流程，再调用对应写入能力。
   - 公共记忆写入会做重复检测，避免沉淀重复内容。

5. 可见动作说明
   - Auto 内部判断不展示。
   - 等待/思考阶段只展示动画，不展示模型名或状态文字。

6. RAG 模型栈
   - 向量嵌入：`BAAI/bge-m3`。
   - 检索重排：`netease-youdao/bce-reranker-base_v1`。
   - 当前 Supabase Edge Function `boh-ai-retrieval` 已默认使用这两个模型，可通过环境变量覆盖。

7. 扩展能力预留
   - OCR：`deepseek-ai/DeepSeek-OCR`、`PaddlePaddle/PaddleOCR-VL-1.5`。
   - 语音输入：`FunAudioLLM/SenseVoiceSmall`、`TeleAI/TeleSpeechASR`。
   - 图像生成：`Kwai-Kolors/Kolors`。

## 推荐体验

默认模式建议设为 Auto。快速/思考/专业仍保留给用户手动指定，但普通用户不必理解模型差异。

Auto 的动作说明应该短、诚实、非技术化。不要展示“向量检索、路由规则、temperature”这类内部词，用户只需要知道 AI 为什么这么回答、参考了什么。

## 记忆写入策略

公共记忆是社群资产，不适合完全自动写入。建议分三层：

1. 明确指令
   - 用户说“记住/写入记忆库/保存这条”：可直接进入确认或写入流程。

2. Auto 识别
   - 用户自然分享社群事件：先询问再写入。

3. 后台候选
   - 低置信度内容进入待确认池，后续在管理页审核。

## 后续优化建议

1. 增加“本轮 Auto 判断”调试面板，仅管理员可见，用于观察误判。
2. 给 Cloud+ / 公共记忆确认卡片加“编辑后写入”，避免把口语原文直接沉淀。
3. 对 Cloud+ 总结增加时间范围选择：最近 7 天、30 天、本月、自定义。
4. 对代码/指令类问题进一步区分：
   - 普通代码：专业模式。
   - Minecraft 指令：专业模式 + 指令知识库。
   - 站内操作指令：专业模式 + 站点操作手册。
5. 给动作说明做固定文案表，避免不同功能各写各的，保持 BOH AI 的人格一致。
