## 1. 为什么合：三页其实是同一件事的三张皮

| 页面 | 真身 | 数据源 | 详情形态 |
| --- | --- | --- | --- |
| 新闻 | `src/views/Newsroom/index.vue`（607 行） | `news` 表（`useNews.js`） | `/news/:id` 独立页（`NewsDetailPage.vue`，带 OG） |
| 活动 | `src/views/ActivitiesWall/index.vue`（91 行宿主）→ `src/views/activities/ActivitiesList.vue`（363 行） | `activity_campaigns`（报名）+ `activities`（往期） | 导航栏延伸岛 `ContentDetailIsland` |
| 节目 | `src/views/Shows/index.vue`（299 行） | **3 条硬编码** + `CreatorShowsPanel`（用户投稿） | 外链 B 站 |

四个必须知道的现状：

1. **新闻页早就在混排节目**。`Newsroom/index.vue:211` 的 `feedData = sortByDateDesc([...newsData, ...SHOW_ITEMS])`，`SHOW_ITEMS` 硬编码在 `:156-196`。
2. **同一批节目存了两份**。`Shows/index.vue` 的 `shows` 数组（`const shows = ref([...])`）与上面的 `SHOW_ITEMS` 是同样三条（冬眠生存 / 方块街 / 新年活动），字段名不同、只有一处有 `date`。这是「改一处要动两处」的典型。
3. **`/shows` 没有任何导航入口**。`src/config/site-nav.ts` 里没有它；入口只有首页页脚（`views/Home/components/homeFooterData.js:18`）、全局搜索（`config/site-search-sources.ts:527`）、AI 站内指引（`data/ai-site-guide.js:28,49`）。
4. **UserSpace 的「节目」tab 已退场**，留下死导出：`views/user-center/UserSpace/async-loaders.js:47`（`preloadShowsComponent`）与 `:290`（`AsyncShows`）无人引用。

另外两处平行面，合并后要划清边界、不要造第三份：

- 论坛「新闻」「活动」两个分区（`config/forum-sections.ts:38-39`，吃帖子 `post_kind`）——是论坛帖，不是这套编辑卡片。合并后应让它们深链到新页。
- 智能概览 `/overview`（`views/SmartOverview`）——是「你离开 N 天的增量摘要」，与新页「全量栏目」是两件事。

## 2. 目标形态

```
/newsroom?tab=feed      ← 默认；资讯流：新闻 + 节目混排（现状直接复用）
/newsroom?tab=activities ← 活动：报名区 + 按月归档（复用 ActivitiesList）
/activities-wall  → 302 → /newsroom?tab=activities
/shows            → 302 → /newsroom（节目已在流里；CreatorShowsPanel 另行安置，见 §5.4）
```

页头：`BOH 新闻社 · BOH SHOWS` / 大标题「资讯」/ 副标题「新闻、活动、节目，都在这一页」。
段控：`资讯流` / `活动`，滑动下划线（对齐 `UserSpace/components/SegmentTabs.vue` 的观感，见 §4.3）。

**为什么不是三个 tab**：新闻和节目已经是同一个混排流，拆开反而多一层；活动有「进行中 / 已结束」两种时态和报名交互，是另一种消费方式，所以只有它单独成段。

## 3. 现状架构（改之前必须看懂）

### 3.1 岛上的搜索 / 筛选是真在跑的，不是死代码

- `Newsroom/index.vue:531-537` 在 `onMounted` 里 `showIsland.notify({ kind: 'news-tools', … })`，把 `query / filter / options / onSearch / onFilter` 交给顶栏。
- 顶栏渲染在 `components/UnifiedNavbar/GlobalNavStatusCard.vue:13-29` 的 `is-news-tools` 分支。
- 选筛选 → `selectNewsFilter`（`:79`）→ `item.onFilter(value)` → 页面 `router.push({ query: { filter } })` → 页面 `watch(() => route.query.filter)`（`index.vue:243`）重算列表。
- 搜索同理，走 `?q=`（`index.vue:257`）。

⚠️ **位置切片契约**：`GlobalNavStatusCard.vue:74-76`

```js
const primaryNewsOptions = computed(() => newsOptions.value.slice(0, 3));
const newsCategoryOptions = computed(() => newsOptions.value.slice(3, 7));
const showCategoryOptions  = computed(() => newsOptions.value.slice(7));
```

`options` 是按**下标**切的，不是按类型。要加「活动」的筛选项（全部 / 报名中 / 往期），不能直接往数组后面塞——会落进「节目分类」组。两种改法：
- (a) 给 item 传结构化 `groups: [{label, items}]`，改 `GlobalNavStatusCard` 按组渲染（推荐，顺带把下标契约废掉）；
- (b) 页面按当前 tab 只传本段该有的 options（`options` 整体替换），最小改动但保留了下标脆性。

### 3.2 活动面板对宿主的三个隐性依赖

`ActivitiesList.vue` 不是纯组件，它假设自己住在一个「活动墙宿主」里：

| 依赖 | 位置 | 合并后怎么办 |
| --- | --- | --- |
| `inject('remountWallIsland')` | `ActivitiesList.vue:110` | 详情岛关闭后回调重挂常驻岛。新宿主不提供常驻岛 ⇒ 传 `null` 即可（`inject` 有默认值），但要确认关闭详情后不会留下空白槽位 |
| `--nav-h` 自己再测一遍 | `ActivitiesList.vue:164-171` | 与 `ActivitiesWall/index.vue:21-27` 的 `--aw-nav-h` 是**同一件事测了两遍**。合并时统一成一个变量 |
| 页头 padding 靠 `:deep()` 覆盖 | `ActivitiesWall/index.vue:61-72` | 合并后 `ActivitiesList` 的页头要**删掉**（新页只保留一个页头），这些 `:deep()` 补丁随之作废 |

### 3.3 三页的导航避让各写各的

`Newsroom` 用 `--nav-h`（`index.vue:562-565`），`ActivitiesWall` 用 `--aw-nav-h`（`:21-27`），`ActivitiesList` 又用 `--nav-h`（`:164-171`）。合并后**只留一份**（建议页面根节点写 `--nav-h`，子面板一律读它）。

**别新写第三份**——仓库里已经有「增高」「横滑」各写过 4 份的教训（`plans/021` §1.3）。
