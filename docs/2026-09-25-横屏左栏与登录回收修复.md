## 二、① 横屏左栏：为什么「换个入口就没了」

### 2.1 先排除：`/user-space` 的左栏一直是好的

用户确认是「横屏电脑 + 左右栏布局 + 有左栏导航」。先按这个口径把 UserSpace 侧量了一遍（1440×900 / 1366×768 / 1280×800 / 1200×800 / 1100×800 / 1024×768 / 1024×600，明暗两套，登录与未登录两种）：

- `body.page-userspace` ✓、`--userspace-rail-w` = 240/88 ✓、`.userspace-rail` 可见 ✓、`.tab-page` 左偏栏宽 ✓
- 左栏条目 = 方块/我的/资产/消息/设置 + 发布/搜索 + 首页 ✓
- `probe-rail-landing.mjs` 45/45、`probe-pd-modal.mjs` 42/43（J1 是骨架时序，与布局无关）

⇒ UserSpace 没有回归。**问题只可能出在「没有左栏的那个论坛入口」上。**

### 2.2 定位：论坛的入口已经变成首页 `/`

`UnifiedNavbar/index.vue:548` 的注释与导航定义写得明确：

```
2026-09-22 首页社区化改版：论坛迁到首页（下滑直达），顶栏「论坛」与「首页」同指 `/`
  { name: "forum", path: "/?view=latest", label: "论坛" }
```

底栏单源 `config/bottom-nav.ts` 同样：`{ id: 'community', label: '方块', route: '/' }`。

而首页在横屏下：`landscape-rail.css` 里**只有** `.user-space-page` / `.profile-page` 两套左栏规则；首页底栏槽位 `.home-bottom-nav-slot` 在桌面/横屏被整槽关掉（`Home/style.scoped.css:156`）。实测 1440×900：`rail = ABSENT`、`bottomNavSlot = none` —— 首页论坛层在横屏下**既没有左栏也没有底栏**，只剩顶部导航。用户看到的「左右栏被改没了」就是它。

（顺带核对：`docs/2026-09-22-首页改版实施交付说明.md` 第 79 行写的是「首页不挂底栏……UserSpace 横屏仍走 SideRail」；而更早的方案稿里其实提过「可选左栏（SideRail 模式承接「正在发生」）」。也就是说首页左栏是**当时列入考虑但没做**的一块，现在补齐。）

## 三、② 灵动岛登录的「回收」为什么生硬

### 3.1 实测症状（修复前）

| 视口 | 加 `mobile-login-closing` 后 0 / 120 / 300 / 550 / 700ms |
|---|---|
| 横屏 1440×900 | `860×276@290,72`（满岛）→ **一帧直接** `241×77@600,10`、opacity 0；之后 700ms 纹丝不动 |
| 竖屏 390×844 | `transform` 恒为 `matrix(1,0,0,1,0,0)`、`opacity` 恒为 1 —— **完全没有任何变化**，到 720ms 直接被卸载 |

即：横屏是「单帧闪掉」，竖屏是「静止 720ms 后消失」。两条都谈不上回收。

### 3.2 根因：`fill-mode: both` 的动画值把属性「冻结」了，过渡接不上

展开态这张卡的三个属性都不是普通声明，而是**入场动画停住的值**：

- 竖屏 `.boh-login-modal-container { animation: mobileIslandAppear 900ms … both }`
- 横屏 `.boh-login-modal-container { animation: landscapeLoginIslandIn 560ms … both }`
- 成功浮层 `mobileSuccessIn 260ms ease both` / `loginSuccessReveal 360ms … both`

浏览器在**移除动画、同帧又改同一属性**时不会为这次变化启动过渡（before-change 值来自动画填充态，不是可插值的普通声明）。所以：

- 写 `animation: none` + `transform/opacity` + `transition` → 过渡被跳过，属性一帧落到终值（横屏实测）；
- 连 `animation: none` 都不写 → 填充态继续持有 `to` 关键帧，写什么都被吃掉（竖屏实测）。

另外，竖屏原本还叠着一条 2026-09-04 的残留规则（`transform: translateX(-50%) scale(0.32) translateY(-42vh)`）同特异性但源序更后，静默压掉 09-21 那版重写；且 `translateX(-50%)` 在基础盒（`inset:0 / width:100%`）上等于左移半个视口，就算生效也是朝左上角飞出屏幕。已删除。

### 3.3 修法：回收改用显式关键帧动画

关键帧动画的优先级高于一切普通声明、且不受「填充态」限制，是这里唯一稳的路子：

```css
/* 竖屏 */ @keyframes mobileIslandRetract { from { transform: none; border-radius: 0; opacity: 1 }
                                        to   { transform: translateY(-6vh) scale(0.82, 0.16); border-radius: 64px; opacity: 0 } }
/* 横屏 */ @keyframes landscapeLoginIslandOut { from { transform: none; border-radius: 0 0 30px 30px; opacity: 1 }
                                               to   { transform: translateY(-62px) scale(0.28); border-radius: 30px; opacity: 0 } }
/* 成功浮层 */ @keyframes loginSuccessFade { from { opacity: 1 } to { opacity: 0 } }
```

终态是按「收进灵动岛」反推的：横屏 `241×77@600,10` 恰好落在导航胶囊那一条；竖屏 `320×135`（岛宽 310 / 岛高 144），`origin: 50% 84px` + 上移 6vh 后终态中心 ≈ 84px = 岛中心。`prefers-reduced-motion: reduce` 下位移动画被既有 `!important` 锁死，另补一条「回收态 = 纯淡出」，避免 reduce 用户又看到「到点消失」（不新增 `!important`，important-budget 仍 1319/1319）。

### 3.4 验证

新增 `scripts/probes/probe-login-island-retract.mjs`（**15 断言，15/15**）：两个视口各断言「有在跑的回收动画 / 120ms 处 transform 严格处于起止之间 / opacity 严格处于 (0,1) / 收尾落在目标几何 / 收尾不回弹」，外加 reduce 档两条。

- 竖屏实测：`390×844 → 365×593@12,7 → 331×245@30,17 → 321×143@35,20 → 320×135@35,20`（op 1 → .65 → .16 → .01 → 0）
- 横屏实测：`860×276@290,72 → 511×164@464,37 → 294×94@573,15 → 244×78@598,10 → 241×77@600,10`
- 反证：把竖屏回收改回 `animation: none` → **10/15**（5 条红）→ 恢复 → 15/15

## 五、可复用的两条经验

1. **`animation-fill-mode: both/forwards` 会让该属性从此「不可过渡」**。凡是「入场用动画、离场用过渡」的组件，离场几乎必然失效（且表现是「没有动画」而不是报错，极易漏）。判据：`getAnimations()` 为空 + 加类瞬间 `getComputedStyle` 已是终值。要么离场也用关键帧动画，要么别给入场用 `both`。
2. **同一张卡在不同 shell 里有两套结构时，先问「用户是从哪个入口进来的」**。本例 UserSpace 侧一切正常，问题只在首页入口；只要把「论坛的规范化入口」指到首页（`/?view=latest`），就必须同时把首页的页面级结构补齐 —— 组件可以复用，**页面级规则（让位 / fixed / 居中基准 / 暗色变量）必须逐个挂**。
