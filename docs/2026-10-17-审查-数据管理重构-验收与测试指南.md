## 2. 必须改（P0）

### P0-1 详情页的「编辑 / 删除 / 面包屑」全部绑到了错误的表（实际是 `users`）

- **位置**：`src/views/DataManagement/DataAdmin.vue:6846-6847`（`recordTab`）、`:6867-6874`（`openRecordDetail` push 不带 query）、`:6876`（`onEditRecord`）、`:6880-6889`（`onDetailDangerDelete`）、`:1941-1947`（`currentTab` 初始化）；`src/App.vue:381`（`:key="activeRoute.path"`）。
- **现状**：
  ```js
  // DataAdmin.vue:6870
  router.push({ name: 'DataManagementRecord', params: { tab: currentTab.value, id: String(item.id) } });
  ```
  `App.vue:381` 用 `:key="activeRoute.path"` 渲染路由组件，列表 `/admin/data-management` → 详情 `/admin/data-management/:tab/:id` 的 path 变化会**销毁并重建** `DataAdmin`。重建后 `currentTab` 只从 `route.query.tab` 解析；`openRecordDetail` 没有带 query，`ADMIN_SECTION_DEFAULT_TABS['overview']` 又是 `undefined`，于是 `resolveInitialAdminTab` 落到 `'users'`。
  详情页的 `RecordPane` 用的是 `recordTab`（正确），但 `onEditRecord`、`onDetailDangerDelete`、`canDeleteCurrentTab`、`currentModule`（面包屑）全部读 `currentTab`（=`users`）。
- **影响**：详情页点「编辑」打开的是用户表抽屉；Danger zone 对所有记录都显示「删除此记录」（因为 users 表有 delete 权限），确认后 `deleteItem` 删的是 `profiles`；只读的审计记录也会出现删除按钮。面包屑模块名与侧栏高亮同样错位。列表返回后的滚动位置也丢失（组件重建，见 P1-6）。
- **改法**：
  1. 在 `DataAdmin` 初始化时优先认路由参数：若 `route.params.tab` 是合法 tab，`currentTab` 直接取它；`activeAdminSection` 取该 tab 的 `module` 对应 section。这样深链和站内跳转都正确，不必往详情 URL 塞筛选 query。
  2. `openEditModal` / `onDetailDangerDelete` / `canDeleteCurrentTab` / `moduleLabel` 改为显式接收 `recordTab`（或新增 `detailConfig = dataConfig[recordTab]`），详情分支不再读 `currentTab`。
  3. 若产品要求保留列表滚动，给两条 DataManagement 路由加 `meta.keepAlive`（当前 `App.vue` 的 `KeepAlive` 分支只认 `meta.keepAlive`），或在离开前记录 `scrollTop` 并在 `router.back()` 后恢复。
- **验证方式**：新增探针（或 Playwright 脚本）：从抽奖列表第 2 页进入详情 → 断言侧栏选中「抽奖」、面包屑为 数据管理/抽奖管理/…；点「编辑」→ 断言抽屉标题与表单字段属于 `lotteries`；点 Danger zone → 断言确认文案含 `lotteries`；返回 → 断言页码/筛选/滚动位置。
- **成本**：中。

### P0-2 `admin_batch_delete` 的 `or_ilike` 分支永远不可达，带搜索词的全量删除必失败

- **位置**：`supabase/migrations/2026101703_admin_batch_delete.sql:87-97`（列校验在 op 分支之前）、`:98-112`（`or_ilike` 分支）；前端 `src/views/DataManagement/DataAdmin.vue:6938-6941`。
- **现状**：
  ```sql
  v_col := v_item->>'column';          -- or_ilike 的条件没有 column 字段 ⇒ NULL
  v_op  := lower(v_item->>'op');
  if v_col is null or not exists (...) then
    raise exception 'unknown filter column: %', v_col;   -- 先在这里抛
  end if;
  if v_op not in (...,'or_ilike') then ... end if;
  if v_op = 'or_ilike' then ... end if;                  -- 永远到不了
  ```
  前端构造的是 `{ op: 'or_ilike', columns: [...], value: '%kw%' }`（`:6940`），没有 `column`。线上函数体已核对：`v_col is null or not exists` 的位置在 `or_ilike` 之前（prosrc 位置 1856 < 2175），即线上同样是坏逻辑。
- **影响**：只要当前筛选包含搜索词（最常见的筛选方式），「全选全部 → 删除」就**必失败**，提示 `unknown filter column: <NULL>`。只有状态/日期条件时才能用。这是 E 批的头号能力，但从未被真实调用过（线上 `admin_audit_logs` 0 行可佐证）。
- **改法**：把 `or_ilike` 分支移到列存在性校验之前（该分支自行逐列校验 `columns`），或在 `v_op = 'or_ilike'` 时跳过 `v_col` 校验；补一条事务内 `BEGIN … ROLLBACK` 的 SQL 测试，覆盖 `or_ilike` / `eq` / `gte` 三种条件与 count 预检。
- **验证方式**：对任意表执行
  `select admin_batch_delete('<table>', '[{"op":"or_ilike","columns":["title"],"value":"%测试%"}]', <count>);`
  事务内跑，修复前应复现 `unknown filter column: <NULL>`，修复后返回 count。
- **成本**：低。

### P0-3 C 批布局验收未完成（不是「未达」，是计划要求的探针与目标都没交）

- **位置**：`plans/027-data-admin-console-rebuild.md:139`（要求新增 `probe-data-admin-density.mjs`）、`:156`（`thead ≤ 240`）；交接书 `§4.7`/`§5.1` 自认 414–474px。

  2. **改验收线**：如果产品接受 414px，则把验收线改为 `thead ≤ 480` 且「首屏 ≥ 9 行」，并在 plan/交接书同步，不许留一条永远红的验收线。

- **成本**：高（方案 1）/ 低（方案 2，但需产品签字）。

## 5. 回归风险

1. **详情路由重建实例**：任何依赖「列表内存态」的逻辑（选中、滚动、展开行、批量条）在详情往返后都会丢；目前只有筛选/页码通过 URL 恢复。若后续有人在详情页加「返回上一位置」，必须先解决 P0-1/P1-6。
2. **10 个 page 型子页未覆盖**：`PityGrantConsole`（C 批语义改动 ~1238 行）、`PointsGrantConsole`（~530）、`LotteryOperationsPanel`（~435）、`SubscriptionGrantConsole`、`ApiKeyConsole`、`KeysAndModels`、`FreemodelsConfig`、`AiQuotaConfigConsole`、`ModerationModelConfig`、`LabAiModelConfig`。`batch-a-empty-search.png` 里已经出现 `rpcEntryCountRows … forEach is not a function` 的取数错误（mock 环境下），说明这些面板的取数路径值得单独回归。
3. **批量删除可删审计类表**：`lottery_admin_audit_logs` / `api_key_vault_audit_logs` / `moderation_logs` 在白名单内，一次误操作会毁掉审计链。
4. **`log_admin_action` 对全体登录用户开放**：审计可被普通用户刷入，后续做「审计可信」时会被这批脏数据拖住。
5. **数据库发布门禁整体是红的**：`check:db-lint` 4 个存量 error、`check:db-advisors` +2（`user_ai_endpoints`/`user_ai_models`）。交接书只提了 advisors，没提 db-lint；发布前必须明确「这两条存量债谁在什么时候还」。
6. **工作区地雷**：未提交的 `DataAdmin.vue` 已 `import { resolveInitialAdminTab } from './composables/resolveInitialAdminTab.js'`，而该文件未跟踪。谁只提交 `DataAdmin.vue`、不提交这个新文件，CI 构建会断。
7. **`users`/`points` 详情的敏感字段为空**（P2-10），容易被误报成「详情页丢数据」。
8. **导出 >50000 行直接抛错**（设计如此），但 UI 没有预判；大表用户会在点击后才看到失败。
