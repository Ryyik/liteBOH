# 「我」页 UI 精简方案（2026-10-26）

> 对象：`/user-space?tab=posts` —— UserSpace 的「我」页（空间 / 资产 / 印象 三段）。
> 承接：工作区当前未提交的 **IA 融合第一刀（资产入口卡）/ 第二刀（印象摘要行）**。
> 行号基于 **2026-10-26 工作区**（`UserSpaceMain.vue`、`ProfileHomePanel.vue` 均为 ` M` 未提交）。

## 一句话结论

「我」页不是"区块太多"，而是**同一个目的地被三层导航各开了一个入口**：
底栏 5 席 → 段控 3 段（空间｜资产｜印象）→ 段内 tab（内容 3 / 资产 7）。
主页又在段控之下铺了资产卡、印象行、服务行 —— 于是「资产」「印象」各有 2 个入口，「积分」有 3 个。

**精简原则：一个目的地只留一个入口；入口放在离它最近的那一层。**

## 一、现状盘点

### 1.2 重复入口矩阵（这是核心问题）

| 目的地 | 入口 1 | 入口 2 | 入口 3 |
| --- | --- | --- | --- |
| 资产 | 段控「资产」（`UserSpaceMain.vue:772`） | 主页资产卡（`ProfileHomePanel.vue:238`，`openAssetsHub`） | — |
| 印象 | 段控「印象」（`:773`） | 主页印象摘要行（`:144`，`openProfileImpressions`） | — |
| 积分 | 积分卡（`:177`） | 资产卡「积分明细」（`:241`） | 资产段内「积分」tab（`AssetsHubPanel.vue:1011`） |
| 发帖 | 底栏/左栏「发布」 | 热力图空态「去发帖」 | 作品空态 / 草稿空态「去发帖」（各一） |

| 发帖数 | Hero 统计「N 发帖」 | 内容 tab「作品 N」 | — |

> 注意：`openAssetsHub()` / `openProfileImpressions()` 的实现都是 **`jumpWithSection('posts', 'assets' | 'impressions')`** —— 即「切到那一段」，不是开浮层（`UserSpaceMain.vue:1916-1924` / `:1956-1960`）。
> 所以主页卡片与段控 tab **是同一目的地的两条路**，不存在"一个是快捷、一个是完整"的分工。

## 二、顺带查出来的真实缺陷：3 处「去发帖」是死按钮

三处空态 CTA 都 `emit('switch-tab', 'posts')`：

- `ProfileHomePanel.vue:469`（作品空态）
- `ProfileHomePanel.vue:528`（草稿空态）
- `ActivityHeatmap.vue:323`（热力图空态 `@action`）

父层接的是 `UserSpaceMain.vue:123` 的 `@switch-tab="switchTab"`，而 `switchTab()` 第一句有效逻辑就是：

```js
const switchTab = (tabId) => {
  const nextTab = resolveAccessibleTab(tabId, { promptLogin: true });
  if (nextTab !== tabId) return;
  if (currentTab.value === tabId) return;   // ← 已经在 posts，直接 return
```

这三个按钮渲染在 **posts 页内部**，所以 `currentTab` 恒为 `posts` ⇒ **点击完全无反应**（不切页、不改 URL、不打开编辑器）。

> 判定方式：源码级推断（链路闭合）。落地前用一次点击实测确认：空数据账号打开 `/user-space?tab=posts`，点热力图「去发帖」，观察 URL 与编辑器是否变化。
> 修法：改为 `openComposer()`（打开同一份发帖会话，双宿主共用），**不是**再 emit 一个 tab id。

## 三、方案：三档，按风险分层

### A 档 · 纯减法（零结构风险，建议先做）

| 编号 | 动作 | 效果 | 代价 |
| --- | --- | --- | --- |
| A1 | 删「服务」整段（`ProfileHomePanel.vue:278-327`） | 少一个段标题 + 2 行；Cloud+ 底栏已有「图库」席 | 摄影集失去主页入口 → 移入资产段「装扮」tab 尾部 |
| A2 | 删积分卡下的操作说明文案（`:231`） | 少一行常驻噪音（操作说明不该常驻） | 无 |
| A3 | 删 Hero 的 `@handle` 行（`:81`） | 少一行与名字完全重复的信息 | 他人空间（`ProfileMain` 复用同一份）需同步判断 |
| A4 | Hero 统计 3 chip → 2（删「发帖」，`:113-117`） | 发帖数已由内容 tab「作品 N」承担 | 统计行更短 |
| A5 | 修 3 处「去发帖」死按钮（见 §二） | 修 bug + 消掉重复 CTA | 只保留热力图一处，作品/草稿空态改为纯文字 |

A 档合计：**区块 8 → 7，重复 CTA 4 → 1，页面缩短约 190–220px（竖屏）**。

### B 档 · 结构合并（需改结构 + 改探针）

| 编号 | 动作 | 说明 |
| --- | --- | --- |
| B1 | 主页资产卡四宫格 → 收成一行「资产 ›」 | 四格里三格（订单/抽奖/赞助）在多数账号是空态占位，信息价值低。改后：`订阅 <状态>` + 两枚动态角标（有待处理订单 / 有待抽奖次数时才出现）+ 箭头。入口唯一性保持：点它 = 进资产段 |
| B2 | 段控 3 段 → 2 段（空间｜资产），印象改为摘要行下方的展开区 | 印象从"第三个 tab"降为"主页的一段可展开内容"，社交证明仍在一屏内。需要 `?view=impressions` 深链仍能落到展开态（`resolveSectionFromRoute` 映射到 `impressionsExpanded=true`） |
| B3 | 内容 tab 与资产段 tab 对齐为一套组件 | 现状：内容面板自带一份 tab 样式（`profile-content-tabs`），资产段自带另一套（`AssetsHubPanel:1009-1015`）。段内两级 tab 视觉不同源，是"层级感混乱"的观感来源之一 |

B 档收益最大、风险也最大的一项其实是 **B2**：段控是 IA 的骨架，`?view=` 参数真源、redirect、深链回落、探针断言全都压在它上面。
**建议 B1 单独做（改动小、收益明显），B2/B3 合并成一刀、先出 demo 再动。**

### C 档 · 需要你拍板的一个取舍

**积分卡（`ProfileHomePanel.vue:177-232`）留在主页，还是降进资产段「概览」？**

- 留主页：它是玩家向的"门面资产"（卡面可换皮肤），有展示价值；但占 200–240px，且与资产段「概览」重复计数。
- 降进资产段：主页立刻短一屏，资产语义收拢到一处；但"卡面装扮"这个高频炫耀点被推深一层。
- **我的建议：留主页，但压成"薄卡"** —— 保留卡面视觉（约 120px），把 `1,280 可用积分` 与「设置卡面」并到一行，去掉「Free」重复角标（Hero 的 tier-badge 已有）。这是唯一既保留情感价值、又不吃一屏的做法。

## 四、明确不做（划边界，避免范围蔓延）

- 不动底栏 5 席（内容/消息/AI/图库/我）—— `src/config/bottom-nav.ts:52-64`，2026-10-22 刚补「图库」，决策记录在同文件注释里。
- 不动资产段内部 7 个 tab（概览/装扮/积分/订阅/订单/抽奖/赞助）—— 那是资产自己的完整页，精简它需要单独的账。
- 不动论坛（内容 tab 的 6 席）—— 属 `plans/022` 任务 3，仍挂「待拍板」。
- 不动设置页（`ProfileSettingsPanel`）—— 8 行入口是另一块，本轮不碰。

## 五、落地顺序与验收

1. **先确认并行会话边界**：`UserSpaceMain.vue` / `ProfileHomePanel.vue` / `ProfileImpressionsSection.vue` 当前均为 ` M`（IA 融合未提交）。动手前先让这一刀落定提交，否则会互相覆盖。
2. **跑基线**（改动前的红线）：
   - `node scripts/probes/probe-user-space-ia.mjs`（91 断言）—— 记下改动前的 PASS 数
   - 竖屏探针：`npm run probe:portrait-visual-audit -- --only=userspace`（若筛选名不符，先 `--list`）
   - 截图留证：`docs/demo-shots/` 现有 `ia2-me-mobile-after.png` / `ia2-me-desktop-after.png` 作为对照基线
3. 做 A 档 → 跑探针 → 截图肉眼过（**样式类改动必须截图肉眼验收，程序化差分漏检过**）。
4. 做 B1 → 同上；B2/B3 单独一轮，先出 demo 页面确认观感。
5. 门禁：`npm run verify:fast` + `probe-user-space-ia` + 竖屏双档（390×844 / 1280×800）。

### 探针要补的三条断言（新增精简护栏）

- `去发帖` 类 CTA 在整个 posts 页内**最多 1 个**。
- 点击热力图空态 CTA 后，**发帖编辑器会话必须打开**（当前为 no-op，这条断言现在就会红 —— 正好是反证）。
- 段控项数与「重复入口矩阵」（§1.2）对齐：资产/印象各只有 1 个入口。
