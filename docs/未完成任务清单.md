### 9.2 两个报障的候选根因（**未实测，按可能性排序**）

**① 缩略图不立即出现**
- **A（最可能）主线程被抢占**：blob 预览是同步建好的、数据也就位了，但紧接着 tfjs+nsfwjs 的动态 import 与模型初始化（建 WebGL 上下文 / 编译 shader / 传权重）就占住主线程，300ms 后压缩又接力（还得解码原图）。Vue 的 DOM patch 与首帧绘制排在后面 ⇒ 用户看到的是"卡一下才出图"。
- **B** `<img loading="lazy" decoding="async">`（`PostComposer.vue:836`）—— 网格恒在视口内，lazy 只有风险没有收益。
- **C 已出的图会再闪一次**：上传完成后 `updatePendingPostImage(uploadId, {...result.data, …})` 把 `url` 从 `blob:` 覆盖成 Cloudinary 远端地址（`forum-format.js:261 normalizeForumImage` → `getCloudinaryTransformedUrl`）。移动网络下这张图要重新下载 ⇒ 白块/回退。

**② 慢 + 输入无响应 + 无提示**
- **D（「整体慢」最强候选）云端审核不可达时**：`CLOUD_TIMEOUT_MS = 8000`，失败还重试一次（+250ms），且**检测是全局串行** ⇒ 最坏单张 ~16s、6 张 ~96s 才全部回落本地。冷却（`COOLDOWN_UNREACHABLE_MS=60s`）要等"确认不可达"后才生效，**第一张最慢**。
- **E 输入无响应**：主线程阻塞。`forum-image-moderation.js:28 yieldToTyping` **只覆盖 classify 阶段**，压缩 / 上传 / tfjs import 都没让路。
- **F 无提示是设计使然，不是 bug**：预热管线传 `quiet: true`（`1855`、`1986`）刻意不写中间态；`handlePostImageSelection:1741` 显式把 `postImageUploadStatus` 置空；`PostComposer.shouldShowImageStatus()` **只在 `uploadStatus === 'failed'` 时显示**。灵动岛只在**发布中**展示（`ForumMain.vue:580-594`）。⇒ 选图到发布之间**全程零提示**。
