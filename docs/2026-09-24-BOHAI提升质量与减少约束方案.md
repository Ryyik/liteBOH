# BOHAI 提升质量与减少约束方案

- 日期：2026-09-24
- 前置：`docs/2026-09-24-BOHAI约束密度审查与精简建议.md`（约束密度度量与重复清单）
- 性质：**方案，除已注明"已实施"的项外均未改代码**

---

## 0. 核心判断

**每一条硬约束都在补偿一个上游缺陷。** 所以"提质量"和"减约束"不是两个目标 —— 修掉上游，约束自己就变成多余的；只删约束而不修上游，只会让行为变差。

据此，下面 6 项都按同一个结构写：**上游缺陷 → 动作 → 质量收益 → 可删约束 → 验证 → 风险**。先讲为什么能删，再讲删多少。

---

## M1 · 用示例替代禁令（最高杠杆）

**上游缺陷：禁令只能排除，不能生成。**
「不许出现『比如』『还是』『或者』」告诉模型什么不该做，却没告诉它"那该问什么"。模型只能退到最安全的形式——泛化、问卷式的问句。这正是"合规但没用"的来源。

**证据：** 附录里唯一给出"正确形状"的是【对照示例】3 组（284 字符），而它是最有效的部分。与之相对，纯禁令有 817 字符：

| 段落 | 字符 | 内容性质 |
| --- | ---: | --- |
| 【四类禁止问的问题】 | 204 | 纯禁令 |
| 【第五类禁问】 | 225 | 纯禁令（含 3 行论证） |
| 【接住≠复述】 | 133 | 纯禁令 + 1 组对照 |
| 【回答里不许出现他的原句】 | 255 | 纯禁令 + 1 组对照 |
| **合计** | **817** | |

**动作：** 把这 817 字符压成**一段 6~8 轮的真实访谈节选**（以好轮次为主，中间夹 1 组差/好对照）。示例里天然包含一次一问、接住的方式、钩住原词、例外优先、不重复、不给选项——全部隐含，不需要逐条声明。

**质量收益：** 模型拿到可模仿的**形状**，而不只是禁区。few-shot 相对纯 instruction 的优势是稳定的。

**可删：** 817 → 约 300（示例本身要占位），净省 **~500 字符**。

**验证：** 探针的 `未钩住上一句`、`泛化提问` 两项计数应下降。

**风险：** 示例即标准——示例里有瑕疵会被放大。素材来源现成：探针跑出来的好轮次直接可用。

## M2 · 用状态块替代"状态类"规则

**上游缺陷：模型数不准轮次。**
所以你们做了两件事：每轮喂状态块（精确数字），**同时**又在附录里写了依赖状态的散文规则。同一件事两个载体，而且会打架。

**证据：** 状态块已经给了 `向下追问深度：2 / 2（再追一层之前必须先做反映）`、`距上次小结：4 轮（满 4 轮需做一次）`（`interview-engine.js:173-176`）；而附录 P-4 又说"最多连问两层；第三层之前必须先插入一次反映或确认"，P-5 说"每 4 轮做一次小结"。散文是死的，状态是活的——两者不一致时模型无所适从。

**动作：** 凡"看状态才决定"的规则，只保留在状态块 + L2，删掉附录里的散文版。

**质量收益：** 模型不必在"数轮次"和"听对方说话"之间分配注意力。

**可删：** P-4 / P-5 及散条约 **150 字符**（量不大），但主要收益是**消除冲突**。

**验证：** `ladderingDepth` 的分布 + 探针轮 4 / 轮 5。

**风险：** 低。状态块每轮重建，比散文更准。

## M3 · 修 A/B 双路径 —— 顺带删掉整个 `<mode_switch>`

**上游缺陷：模式判定交给了模型。**
附录让模型自己判断"用户是否想探索自己"，于是需要一整套 `<mode_switch>` 规则（279 字符），还催生了"附录 + 分层规则"两套并行载体。

**证据：** `expertState` 全仓库只有一个写入点（`BOHAIMain.vue:1898`）。路径 A（加号入口）全开；路径 B（`BohaiSettingsPanel.vue:119` 手动选风格）下状态块 / L0-L2 / 守门 / 封闭域**全为 false**——但 `<mode_switch>` 第 2 条仍邀请模型自行进入访谈。详见审查文档 §8。

**动作：** 入口决定模式，而不是模型自判。

**质量收益：** 行为一致；**隐私边界一致**（B 不再是检索敞口）。

**可删：** `<mode_switch>` 整段 **279 字符**。

**验证：** 两条路径分别跑探针，`guardStats` 应一致。

**风险：** 需产品决策。上一轮已提出两种修法（统一 / 分叉显式化），**你还没选**。

## M4 · 约束下沉到代码（但要先降误报）

**上游缺陷：守门阈值偏保守 → 误报 → 不敢删 prompt 副本。**
怕触发率上升，所以 prompt 里那几份副本一直留着。这是一个自我锁定的循环。

**证据：** `PARROT_SIMILARITY_THRESHOLD = 0.75`、`REPEAT_SIMILARITY_THRESHOLD = 0.7`（bigram 包含度）；`guards.js:42-46` 注释自认"误报……比漏检更伤"。而 `shouldRewrite` 对全部 6 种类型都返回 true（含较软的 terms / advice）。

**动作（严格按序）：**
1. 先用 `guardStats` 量出真实 `triggered / checked` 与 `adopted / triggered`
2. 若 `adopted / triggered` 很低 → 误报多 → 调阈值
3. 阈值稳了**再**删 prompt 里的代码副本

**质量收益：** 重写次数下降 = 延迟下降 + 少一次"被改差"的机会。

**可删：** P-1 / P-2 / P-3 / P-6 / P-7 / P-9（已由代码覆盖）≈ **400 字符**（**必须等第 2 步完成**）

**验证：** `guardStats` 前后对比。

**风险：** 中。顺序不能乱——先删后调会把行为变差。

---

## M5 · 死约束落地或删除

**上游缺陷：规则写了没有校验器。**
「一个问题不超过 30 字」写在附录【两个硬指标】里，但 guards 只数问句**个数**，不查**长度**。

**动作：** 二选一——给 guards 加 `LONG_QUESTION`（正则，成本极低），或删掉这条。

**质量收益：** 落地则问题真的会变短（访谈质量提升）；删除则少一处无效注意力。

**可删：** 【两个硬指标】69 字符（其中"一个问号"那半句由 `MULTI_QUESTION` 覆盖，可直接删）。

**验证：** 新增断言。

**风险：** 低。但**落地会增加重写次数**，必须与"软违规不整轮重写"一起做。

## M6 · 用参数替代规则（唯一不动 prompt 的项）

**上游缺陷：模型能力不足，于是用规则去补。**
`BOHAIMain.vue:1886` 的注释已经承认了这一点："轻量模型跟不上这套协议（实测 fast 会退化成问卷）"——所以访谈强制从 `fast` 升到 `pro`。

**反直觉的一点：访谈现在跑在 `pro`，temperature 只有 0.18。**
低温换稳定、高温换自然。访谈要的是"像人"，不是"准确"——0.18 偏冷，配合大量否定式约束，很容易出问卷腔。**约束和温度是替代关系**：温度能给的自然度，不必用规则去规定。

**动作：** 给访谈态单独一份 generation profile（现在 `getGenerationProfile` 只按 mode 取，没有访谈分支），把 temperature 提到 0.3~0.35，**同时**更大胆地删风格类约束。

**质量收益：** 对话更像人。

**可删：** 风格类约束可以更激进。

**验证：** 探针 + 人工盲评（同 9 轮剧本跑两版，不看参数选哪版更像人）。

**风险：** 中。`GENERATION_PROFILE_BY_MODE` 是**全局共享**的，不能直接改 `pro`（会影响所有 pro 会话）——必须走访谈专属分支。

## 排序（顺序不能乱）

| 步 | 动作 | 依赖 | 说明 |
| --- | --- | --- | --- |
| 1 | **M3** 修 A/B 路径 | 你的决策 | 修 bug，且解锁 M2 的删除 |
| 2 | **M4-1** 量数据 | 需跑探针 | 拿到 `guardStats` 与问题分布 |
| 3 | **M4-2** 调阈值 | 步 2 | 误报降下来才能安全删副本 |
| 4 | **M1** 示例替代禁令 | 步 2（示例素材来自探针） | 最大质量杠杆 |
| 5 | **M2 / M4-3** 删冗余 | 步 3、4 | 附件的删减主体 |
| 6 | **M5 / M6** 微调 | 步 5 | 小步试 |

**为什么不能先删 prompt：** 删除的正当性来自"代码已经兜住了"，而代码兜得牢不牢要靠 `guardStats` 证明。跳过测量就删，等于把风险从 prompt 转移到用户身上。

## 不该删的（防过度删除）

- **安全类**：`<safety>`、L0-3 危机干预、C-1/C-2 不诊断与不给医学建议、BASE 身份归属。越硬越好，还应该继续加强。
- **产物契约**：`PSYCH_REPORT_SPEC`。它不是风格约束，是输出格式约定，删了报告结构就散。
- **无代码覆盖的语义约束**：`【只能用他说过的话】`、`【他只回了一个词时】`。`guards.js:13-14` 明确说编造不做自动检测（假阳性比漏检更糟），所以这两段**没有代码兜底**，删了就是真的丢了。
- **`【对照示例】`**：是资产，方向是**扩写**而不是删。

## 验证闭环

两项配合使用，缺一不可：

1. **`guardStats`（每轮自动，已实施）** —— 读法：
   - `triggered / checked` 偏高 → prompt 规则没生效（该继续精简 prompt，还是加固代码，由此判断）
   - `adopted / triggered` 偏低 → 守门在误报（该调阈值，而不是继续加规则）
2. **探针 `scripts/probes/probe-psych-dialog-quality.mjs`** —— 9 轮固定剧本，直接 import 产品 guards，输出「问题分布」。

**消融判据：** 每次只删一组规则 → 该组对应的 violation 类型出现率**不上升 → 该组是死重，可以删**。上升明显 → 保留。

**当前阻塞：** 探针在沙箱下无法启动 Chrome（code-sign clone 的 file-delete 被拒），且需真实模型额度。**基线数据尚未取得**，因此上表所有"可删"仍是**待验证的建议值，不是结论**。

# 实施记录（2026-09-24 第二轮：M3 + M6 + M1）

## 结论先行：一处判断被推翻

**我上一轮推荐的 M3 修法（统一：切风格即建 expertState）是错的**，实施前才发现原因：

`currentResponseStyleId` 是 **localStorage 里的全局设置**（`useModelConfig.js:101-102`），不是按会话的。
所以「风格=心理就封闭域」会把这名用户**所有**对话的站内检索与记忆全部关掉 —— 副作用远大于收益。

**改为分叉显式化**：风格 = 陪伴式；正式访谈 = 加号入口（会建 expertState）。
这样路径 B 不可能进入访谈，也就不存在「访谈内容进检索上下文」的问题。

## M3 实际做法：把两个语义从单一标志里拆出来

原实现只有一个 `psychInterviewActive`（= `expertState` 存在），同时管着两件触发条件本就不同的事：

| 语义 | 应生效于 | 旧实现 |
| --- | --- | --- |
| 封闭域（不检索 / 不写记忆 / 不拉健康与私域数据） | 心理角色下说话 | 仅 expertState |
| 访谈协议（状态块 / L0-L2 / 锚定 / 守门） | 仅正式访谈 | 仅 expertState |

实施时把**附录按注入条件拆成两个导出**，而不是靠代码里加一个宽标志 —— 因为风格是全局的，宽标志会误伤：

| 导出 | 注入条件 | 内容 |
| --- | --- | --- |
| `PSYCHOLOGIST_PROMPT_APPENDIX`（陪伴式） | 风格 = 心理专家（全局） | `<constraints>` / `<instructions>` / `<how_to_start_interview>` / `<safety>` |
| `PSYCH_INTERVIEW_APPENDIX`（访谈协议） | `psychInterviewActive`（会话级） | `<interview_protocol>` / `<no_options>` / `<epistemic_layering>` / `<report_format>` |

- `<mode_switch>` **删除**，换成 `<how_to_start_interview>`：明确「不要主动发起访谈」+ 告诉用户走加号入口。
- `<safety>` 留在陪伴式侧 —— 危机干预在陪伴式里同样需要。
- 注入点：`useChatEngine.js:1916`。

## M1 实际做法：禁令 → ✗/✓ 对照

删除的纯禁令段与去向：

| 原段落 | 字符 | 去向 |

| 【第五类禁问】 | 225 | → 铁律一行 + 一条 ✗（铁律可被 guards `OPTIONS` 正则检测） |
| 【接住≠复述】 | 133 | → 压缩为 2 行 + 1 组 ✗/✓（guards `PARROT` 兜底） |

【两个硬指标】、`<no_options>`、`<epistemic_layering>`、`<report_format>`。

**新增测试**：`tests/unit/psych-expert-prompt.test.js` 里加了一组「规则覆盖（M1 防丢）」断言 ——
每条被删的禁令都必须能在示例里找到对应的 ✗，或由 guards 的 violation 类型兜底，
并断言 ✗ 与 ✓ 成对（数量相等）。这样后续再改示例时，静默丢规则会被测试挡住。

## M6 实际做法：访谈态专属生成参数

`chat-engine-config.js` 新增 `PSYCH_INTERVIEW_GENERATION_PROFILE = { temperature: 0.3, top_p: 0.8, frequency_penalty: 0.12 }`。

- `getGenerationProfile(modeId, { factualQuestion, operationQuestion, psychInterview })` 新增第三个入参。
- **两个坑**：
  1. `psychInterview` 必须进 `cacheKey`。漏掉它会让访谈态与非访谈态互相串味，而且是**静默**的（表现只是"有时候像问卷腔"）。已加断言锁住。
  2. 访谈覆盖必须放在 `factualQuestion / operationQuestion` 的降温 clamp **之后** —— 访谈中途难免出现"我该怎么办"这类问句，若让 clamp 生效会把温度压到 0.14，立刻退回问卷腔。
- 未改 `GENERATION_PROFILE_BY_MODE.pro`：那张表全局共享，会影响所有 pro 会话。
