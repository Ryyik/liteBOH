## 二、问题分类标准

### 2.1 类别维度

| 代号 | 类别 | 判定标准 |
|---|---|---|
| **O** | 过时代码与资产 | 全仓零引用的文件/资源；已被新实现取代但旧实现仍在；一次性脚本长期滞留 |
| **B** | 历史缺陷 | 报告/计划中记录为"待修"但代码未落地；同一问题被多次修复（根因未除）；已修但记录未关闭 |
| **S** | 结构与规范 | 巨型文件、重复实现、命名不一致、注释缺失、分层混乱 |
| **D** | 文档 | 与代码不符、命名不统一、状态未同步、缺少入口文档 |
| **E** | 工程配置 | CI 门禁缺失、构建脚本不一致、类型检查覆盖弱、lint 配置疏漏 |
| **SEC** | 安全 | 已实测可复现且未修复的安全问题（引用 `docs/2026-09-21-安全审计报告核验与全量复检.md`） |

### 2.2 优先级判定标准

| 级别 | 判定标准 |
|---|---|
| **P0** | 可被外部利用造成数据泄露/权限越界；或导致生产事故且当前无缓解层。需立即处理 |
| **P1** | 直接阻碍维护效率或质量保障失效（CI 不跑测试、文档无法作为依据、根因未除的反复返工）；或安全纵深防御负债 |
| **P2** | 显著增加理解/修改成本，但不阻塞交付（重复实现、巨型文件、仓库体积） |
| **P3** | 整洁度问题，可随其他改动顺带处理 |

`🔴 未修复` / `🟡 部分修复` / `🟢 已修复但记录未关闭` / `⚪ 待确认`

### 8.2 在改动中发现的缺陷

**缺陷 1（中）— `alter default privileges` 防复发不完整，与其自身的实证结论矛盾**

`2026092101_...sql:120`：

```sql
alter default privileges in schema public revoke execute on functions from anon;
```

同一文件 `:9-13` 已实测证明：**只撤 anon 无效**，因为函数的 EXECUTE 同时存在 PUBLIC 授权，anon 经 PUBLIC 继承（"只撤 anon → `anon_can_execute = t`；撤 anon, public → `f`"）。但这条"防复发"语句只撤了 `anon`——**未来新建的函数仍会经 PUBLIC 默认获得 EXECUTE**（PostgreSQL 对新建函数默认授予 PUBLIC），anon 依然可执行。即：存量修好了，增量会重新长出来。

**修法**：`alter default privileges in schema public revoke execute on functions from anon, public;`

**缺陷 2（中）— 回滚附录 73 行 SQL 语法全部错误，事故时不可用**

`2026092101_...sql:129-201` 的"回滚附录"全部写成：

```sql
-- revoke execute on function public.reserve_ai_token_quota(...) to anon, authenticated;
```

恢复授权必须用 `grant`，`revoke ... to` 是**无效语法**。这 73 行注释一旦在事故中被取消注释执行，**每一条都会报语法错误**——即这份回滚附录在最需要它的时候是失效的。

**修法**：`grant execute on function ... to anon, authenticated;`（Part 3 恢复段的 `grant insert, update, delete on all tables ... to anon;` 写法是正确的，可作参照）。
