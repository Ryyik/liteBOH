## 五、对 C 报告的审查意见

### 判断准确、且是三份里独有的

1. **P1-1 `scoped @import` = 编译期复制且互相失效**（最有价值的一条）。Vue scoped 会把导入方的 `[data-v-X]` 加到共享 CSS 的每个选择器上 → N 份字节副本，且为 A 组件编译的那份**命中不了 B 组件的 DOM**。产物证据：`dist/static/css/DataAdmin-*.css` 中 `.g-*` 带 **12 个不同 scope id**，该 chunk 628KB 占全站 CSS 的 20%，而源文件只有 29.8KB。
   **这条链解释了 `!important` 的来源**——共享样式表静默不生效时，唯一奏效手段就是用 `!important` 硬穿。这是三份报告里唯一触及"为什么会有 1735 个 !important"的因果解释。
2. **P0-2 路由校验死代码**（见第三节，已实测复现）。
3. **P1-6 DataAdmin 拆法纠错**（见第四节，已实测复现）。
4. **改动频次 × 体量交叉**：`ForumMain`（4515 行 / 47 次改动）、`UserSpaceMain`（3115 / 45）、`DataAdmin`（6638 / 40）——"每次改动都在最难的地图上改"，这个论证比单纯排行数有力得多。
5. **"应当保留的优点"一节**：点名 `Lab/index.vue`（4650 行、**0 处 Supabase 直连**）应当作分层重构的模板，而不是待清理对象。这个反向判断很专业。

### 需要打折或商榷的

1. **"第 0 批约 30 分钟"低估了**。它自己就说 P0-2 修完"预期立刻爆红，需先跑一遍确认 53 条路由的真实性"——那就是要逐条核对 53 个组件路径，不是配置改动级别的活。
2. **`check:dark-tokens` 的 `dark-gate-scopes.json` `"strict": []` 为空**这条（P0-3），本轮整改未处理，需先核实当前文件内容再下结论——若属实，则"暗色门禁当前不阻断任何构建"是比 `!important` 更优先的问题。
3. **P1-5 死 CSS 25% 的判据**（类名 token 未在标识符中出现）会误伤模板字符串动态拼名（`` `badge-${type}` ``），它自己也标注了。建议按它说的"**在 P1-1 之前先做**"，但 codemod 后必须跑一遍视觉回归。
4. **`AvatarCropModal.vue:146` 那批 `--glass-blur-*` 变量实际未生效**（靠 `var()` 兜底字面量在跑）——这条若属实是"静默失效"的典型，但本轮只做了 `glass-aliases.css` 补偿，**根因（39 个 SFC 仍在 scoped 里 @import）未处理**。
