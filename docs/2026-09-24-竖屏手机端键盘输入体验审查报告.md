# 竖屏手机端键盘输入体验审查报告

- 日期：2026-09-24
- 范围：竖屏手机（portrait phone）软键盘弹出/收起时的输入体验
- 方法：静态代码审查（CSS 布局模型 + 视口 API + 表单属性），未做真机复现
- 结论：**主流程存在 3 处 P0 级遮挡问题**，根因是「键盘抬升」能力只在 1 个页面做了，其余页面缺失，且全站未使用任何 `enterkeyhint` / `inputmode` / `autocomplete`

---

## 0. 背景：项目现有的键盘适配能力盘点

项目里已经有 3 处各自独立实现的键盘/视口适配，但**没有任何统一抽象**：

| 位置 | 机制 | 覆盖范围 |
|---|---|---|
| `src/main.js:243-269` | `visualViewport` resize → 写 `--real-vh` / `--viewport-height` / `--viewport-width` | 全局，但只服务「旋转后取真实高度」这一目的 |
| `src/views/Login/index.vue:224-237` | `visualViewport` → `--boh-visual-height` + `mobileKeyboardOpen` 标志（阈值 120px） | 仅登录页 |
| `src/views/PostDetail/PostDetailMain.vue:516-525` | `visualViewport` → `--pd-dock-inset`，配合 `modal-layout.css:300-311` 抬升 fixed 底栏 | 仅帖子详情**整页模式** |

同时 `src/style.css:354-359` 有一条全局兜底：

```css
/* P0 竖屏可操作性：防止 iOS 输入框自动缩放 */
@media (max-width: 768px) {
  input, textarea, select { font-size: 16px !important; }
}
```

这条是有效的，且方向正确。问题出在**它只解决了「聚焦时不放大页面」这一个子问题**，键盘遮挡、回车语义、键盘类型这三类问题都没有覆盖。

---

## 1. P0 · 键盘遮挡（影响主流程可用性）

### 1.1 全屏发帖编辑器：底部工具条被键盘永久遮挡

**现象**：竖屏点「发帖」进入全屏编辑器，点正文框打字后，底部的定位/标签/图片/草稿 chips 行被键盘盖住，输入过程中无法操作任何工具。

**证据**：

- `src/views/Forum/components/PostComposer.vue:720` — chips 行 `mobile-composer-chip-row` 位于编辑器最底部
- `src/views/Forum/styles/replies-responsive.css:547-562`

```css
.mobile-composer-overlay {
  position: fixed;
  inset: 0;
  display: flex;
  flex-direction: column;
  height: 100dvh;        /* ← iOS 上 dvh 不随键盘收缩 */
  overflow: hidden;      /* ← 外层不可滚，无法把底栏顶上来 */
  padding-bottom: env(safe-area-inset-bottom);
}
```

**根因**：`100dvh` 只响应浏览器工具栏（地址栏）的收放，**不响应软键盘**。iOS Safari 键盘弹起时视觉视口收缩，但布局视口与 `dvh` 不变，叠加 `overflow: hidden` 后底部区域既不会收缩也无法滚动到可见位置。

**注意**：该 overlay 由 `isForumPortraitComposer()`（`(max-width: 1024px) and (orientation: portrait)`，见 `src/utils/forum-viewport.js:59-60`）触发，**正是竖屏手机路径**，且经 `Teleport to body`（`ForumMain.vue:4085`）挂在 body 上，脱离页面流。

**修复方向**：复用 PostDetail 已验证的模式 —— 在 overlay 根元素上写入 `--composer-keyboard-inset`，用 `height: calc(100dvh - var(--composer-keyboard-inset, 0px))` 或直接 `bottom: var(--composer-keyboard-inset)`。

---

### 1.2 BOHAI 聊天输入框被键盘遮挡

**现象**：BOH AI 对话页，点底部输入框后输入区被键盘盖住。

**证据**：

- `src/views/BOHAI/BOHAI/styles/adaptive-layout.css:1-22`

```css
.bohai-page {
  height: 100vh;
  height: 100dvh;   /* ← 同上，iOS 不随键盘收缩 */
  overflow: hidden;
}
```

- `src/views/BOHAI/BOHAI/styles/adaptive-layout.css:659-675` — `.input-area` 是 grid 的 `grid-row: 5`、`align-self: end`，即**贴底**
- 全文件只有 `safe-area-inset-bottom`，**没有任何 keyboard inset**

**根因**：与 1.1 相同。BOHAI 是纯 flex/grid 贴底布局，没有 PostDetail 那样的 `--pd-dock-inset` 等价物。

**修复方向**：与 1.1 共用同一套 inset 变量。

---

### 1.3 底部导航栏无键盘感知，会浮在键盘上方

**现象**：iOS 上键盘弹起时，`position: fixed` 的底部导航栏不会消失，会出现在键盘上方，压住输入区或产生明显视觉错乱。

**证据**：

- `src/views/user-center/UserSpace/components/UserSpaceBottomNav.vue:52` — `hidden` 属性**只由滚动方向驱动**，无键盘判据
- 全站 `visualViewport` 引用仅 3 处（见第 0 节），均不涉及底栏

**根因**：iOS 的 `position: fixed` 元素锚定在**布局视口**底部，键盘弹起时布局视口不变，fixed 元素便停留在原位（键盘后方或上方），而视觉视口已收缩。

**修复方向**：键盘弹起时（`innerHeight - visualViewport.height > 阈值`）给底栏加 `is-hidden` / `translateY(100%)`。注意 Login 已有现成的判据逻辑（`Login/index.vue:229`，阈值 120px）可以提取复用。

## 2. P1 · 交互正确性

### 2.1 手机端回车语义死锁（BOHAI）

**证据**：`src/views/BOHAI/BOHAI/BOHAIMain.vue:1762-1767`

```js
const handleEnter = (e) => {
  if (e.isComposing || e.keyCode === 229) return;
  if (globalAiPreferences.enterToSend ? e.shiftKey : !(e.metaKey || e.ctrlKey)) return;
  e.preventDefault();
  sendMessage();
};
```

默认值 `enterToSend: true`（`src/composables/useGlobalAiPreferences.js:15`）。于是：

| 设置 | 桌面行为 | 手机行为 |
|---|---|---|
| `enterToSend = true`（默认） | Enter 发送 / Shift+Enter 换行 | Enter 发送；**手机键盘没有 Shift，永远无法换行** |
| `enterToSend = false` | Cmd/Ctrl+Enter 发送 | **手机键盘没有 Cmd/Ctrl，永远无法回车发送** |

两种设置下手机端都有一条路径被物理封死。

**修复方向**：移动端忽略 `enterToSend`，固定为「Enter 换行 + 发送按钮发送」，或改为「Enter 发送 + 键盘上方工具栏提供换行」。建议与 `enterkeyhint` 一起改（见 2.3）。

---

### 2.2 viewport 缺 `interactive-widget=resizes-content`（但**不能单独加**）

**现状**：`index.html:67`

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=5.0, user-scalable=yes, viewport-fit=cover" />
```

缺少 `interactive-widget=resizes-content`。该属性让 Android Chrome 在键盘弹起时收缩**布局视口**，是解决遮挡最省事的方案。

**⚠️ 风险：本项目不能直接加，必须成对改造断点。** 项目大量布局判据依赖视口高度，一旦布局视口随键盘收缩，这些断点会在打字过程中翻转，导致布局中途跳变：

- `src/views/Forum/styles/composer.css:561` — `@media (orientation: portrait), (max-width: 1023px), (max-height: 599px)` → 键盘一弹，`max-height: 599px` 命中，发图大卡片凭空出现
- `src/utils/forum-viewport.js:16-17` — `FORUM_LANDSCAPE_QUERY = '(orientation: landscape) and (min-width: 1024px) and (min-height: 600px)'` → 平板横屏（1024×768）键盘弹起后高度跌破 600px，**从左右分栏布局瞬间切成手机单列布局**
- `src/views/Forum/styles/composer.css:576` — 同一组判据的镜像

**建议**：优先走 1.1 / 1.2 的 JS inset 方案（不改变布局视口，无跳变风险）；若要启用 `interactive-widget`，需先把上述「高度敏感断点」全部改成基于 `dvh`/自定义属性，并补一条键盘态断言脚本。

### 2.3 全站 0 处 `enterkeyhint` / `inputmode` / `autocomplete`（表单属性）

**证据**：`grep -rn "enterkeyhint|inputmode|autocapitalize|autocorrect" src/ --include="*.vue"` → **0 命中**（`autocapitalize` 仅 Login 的 loginId 有）。

后果是键盘右下角永远显示「换行 / return」，而不是用户期望的动作标签，且键盘类型不匹配：

| 场景 | 文件:行 | 现状 | 建议 |
|---|---|---|---|
| 登录账号 | `Login/index.vue:572`（及 `:706` 移动副本） | `type="text"`，无 autocomplete | `autocomplete="username"` + `enterkeyhint="next"` |
| 登录密码 | `Login/index.vue:588`（及 `:722`） | 无 autocomplete | `autocomplete="current-password"` + `enterkeyhint="done"` |
| 帖子详情评论 | `PostDetail/PostDetailMain.vue:2189`、`:2384` | `type="text"`，`@keydown.enter` 已能发送 | `enterkeyhint="send"` + `autocapitalize="off"` + `autocorrect="off"` |
| 发帖标题 | `PostComposer.vue:593` | `<textarea rows="1">`，回车插入换行 | `enterkeyhint="next"`，并拦截 Enter 跳到正文 |
| 发帖正文 | `PostComposer.vue:605` | 无属性 | `autocapitalize="off"` |
| BOHAI 输入框 | `BOHAIMain.vue:414` | 无属性 | `enterkeyhint="send"`（配合 2.1） |
| 主题回复框 | `PostDetail/components/CommentThread.vue:201` | 无属性 | `autocapitalize="off"` |

**参考基准**：`src/views/Join/index.vue:83/114/145/179/186` 已经正确使用 `autocomplete="username" / "email" / "new-password" / "bday-*"`。**登录页应该对齐注册页的标准**，目前两页不一致。

## 3. P2 · 细节问题

1. **登录页 DOM 中存在重复 id**
   `Login/index.vue` 桌面表单与移动表单各渲染一份 `id="loginId"`（:572 / :706）和 `id="password"`（:588 / :722）。重复 id 破坏 `<label for>` 关联与密码管理器自动填充，也会触发 HTML 校验告警。建议改成 class 选择或按断点条件渲染。

2. **`--real-vh` 语义被键盘污染**
   `main.js:243-255` 的 `syncViewportMetrics` 用 `visualViewport.height` 计算 `--real-vh`，且监听 `visualViewport` 的 resize。这意味着**键盘弹起也会改写 `--real-vh`**，任何依赖它的全屏面板会跟着键盘缩放。当前消费者是 `src/styles/vendor/unified-nav.css:1743-1776`（导航面板高度）与 `AnniversaryCafe/style.scoped.css:24`（`min-height: calc(var(--viewport-height, 100vh))`）。
   建议：拆成「旋转视口」与「键盘可视区」两个变量，或在该函数里排除键盘态。

3. **防缩放兜底只覆盖到 768px**
   `src/style.css:355` 的断点是 `max-width: 768px`。769–1024px 的竖屏平板（如 iPad 竖屏 820px）仍会因输入框字号 < 16px 触发 iOS 自动放大。建议放宽到 `max-width: 1024px`。

4. **键盘适配逻辑三处重复、无抽象**
   `main.js` / `Login` / `PostDetailMain` 各写一份 `visualViewport` 监听与 inset 计算，阈值（120px）与写法都不统一。建议抽成 `useKeyboardInset()` composable，输出 `inset` / `isKeyboardOpen`，由需要抬升的容器统一消费。

## 4. 建议的修复优先级

| 优先级 | 事项 | 涉及文件 |
|---|---|---|
| **P0** | 发帖全屏编辑器键盘抬升 | `replies-responsive.css:547`、`PostComposer.vue` |

| **P1** | 抽 `useKeyboardInset()` 统一三处实现 | 新增 composable + 3 处改造 |

**推荐先做**：把 PostDetail 已验证的 `--pd-dock-inset` 模式提取为 composable，同时喂给发帖编辑器和 BOHAI 输入区 —— 这三处是同一类问题，一次抽象可解三处，且不触碰任何断点，零回归风险。
