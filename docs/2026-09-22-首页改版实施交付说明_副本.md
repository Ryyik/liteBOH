## 0. 一句话目标

首页改为「**满屏 Hero 开场画 → 下滑直达论坛**」：首屏一张横竖屏兼容的清晰街景大图；下滑直接是论坛帖子流；现有 hero 海报流以论坛「**官方**」分区**原样**保留；底部导航全站统一为 **方块 / 消息 / 设置 / 我的**。管理后台（HeroConsole）同步升级：**首屏唯一 Hero** 与 **官方 Hero 流** 两类管理。

交付范围 = P0 全量（本文所有任务）。预计 0~1 条轻量 DB 迁移。

## 2. 任务 A：首屏 Hero（清晰大图 + 字体）

### A1. 大图规格（横竖屏兼容）

- **双构图两张**：
  - 竖屏 `1170 × 2532`（约 9:19.5，覆盖 iPhone 全系 + Android）
  - 横屏 `2560 × 1440`（16:9，桌面/平板横屏）
  - 格式 WebP q82（单张目标 ≤ 350KB，可再加 AVIF 由 `<picture>` 选择）；`<img>` 带 `width/height`（防 CLS）+ `fetchpriority="high"`（它是 LCP）+ `object-fit: cover`
- **构图要求**（给生图/摄影的 prompt 方向）：「方块街街景，Minecraft 体素风格，黄昏暖光，街角咖啡馆与书店，干净无人物特写，大面积天空留白」；**主体居中 60% 安全区**，上 22% 留白（叠问候）、下 18% 留白（叠下滑提示）；横竖同主题、分别裁切，不要一张图硬拉两用
- **文字可读性**：问候与提示所在区域加浅 scrim（黑色 12%~25% 渐晕），文字对比度 ≥ 4.5:1
- **数据**：`home_heroes` 新增 `template='street-scene'` 行 + 横竖图字段（`image_portrait` / `image_landscape`）。迁移走 Management API 执行 + **同一事务**手写 `supabase_migrations.schema_migrations`（version/name/statements text[]），结尾 `notify pgrst,'reload schema'`
- **降级链**：street-scene 行缺省 → 回落项目现有品牌图 `main1-1280.webp`；再缺省 → 纯暖色底 + 问候（页面永不白屏）
- **交互行为**：
  - 高度 `100svh`（横竖屏一致；**必须用 svh**，防移动端地址栏抖动）
  - 图上只有两层：左上时段问候（「晚上好，欢迎回到方块街」）、底部中央「往下逛逛 ↓」呼吸提示（2s 循环，用户首次滚动后淡出）
  - **随滚动自然滚出，不回归**：普通文档流，无 sticky / 无视差 / 无滚动劫持
  - Hero 完全离开视口后（IntersectionObserver）暂停图片解码/卸载，滚回顶部恢复

### A2. 字体（定案：苹方 / 系统栈，不引入 web 字体）

- 全站统一系统栈：`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", sans-serif`——展示层与正文同栈，**零字体加载成本、零 FOUT、零 CLS**
- 展示层气质靠排版而非字体：
  - 问候语：苹方 Semibold（`font-weight: 600`）28~34px + `letter-spacing: 0.02em` + 图上 scrim（黑 12%~25% 渐晕，对比度 ≥ 4.5:1）
  - 下滑提示：14px + `letter-spacing: 0.08em`
  - 时间戳/数字：`font-variant-numeric: tabular-nums`
- 决策记录：曾评估霞鹜文楷 Lite（OFL），demo `home-hero-font-demo.html` **留作对照存档**；用户已定苹方。未来若想要手写感，按 demo 内五要点自托管接入即可（swap、不进 render-blocking 链、只 preload 用到的分片）

## 3. 任务 B：下滑直达论坛 + 「官方」tab

1. 首页骨架：`StreetSceneHero`（100svh）→ 论坛区块（顶部圆角 20-24px + 描边作分界，进场 fade+24px reveal 一次，包 `prefers-reduced-motion`）
2. **论坛组件单源复用** UserSpace 的 AsyncForum——不是复制，是同一组件挂到首页；分区数据、30s 轮询、过渡动画全部原样
3. 分区 tabs 七席：**官方 / 最新 / 关注 / 新闻 / 活动 / 成员 / 印象**（官方居首＝用户指定；**默认分区仍为 `latest`**）
4. 「官方」= `view=official` → 渲染现有 hero 流**原样**（新 `HomeHeroFlow.vue` 包裹现有 `HomeHeroRow` 循环，`DynamicHomeHero`/`BuiltinHeroRenderer` 与各弹窗一律不动；排期/显隐/归档机制零改动）
5. 惰性挂载：首次切到「官方」才加载 hero 渲染层（**不得进首屏壳**）；已访问分区 keepAlive 缓存；切换过渡复用 `userspace-tab-in/out` 既有类
6. URL：`/?view=official` 深链直达；`resolveSectionFromRoute` 合法值集合加 `official`
7. 未登录：帖子流展示公开内容 + 「登录后互动」引导；上线前按 `pg_policy` 复核 anon 读权限（**不得回退 anon-execute 基线**）

## 4. 任务 C：底部导航统一「方块 / 消息 / 设置 / 我的」

### 4.1 终态
- **全站唯一一组底栏 items**（用户指定顺序）：**方块 / 消息 / 设置 / 我的**
  - 方块 → `/`；消息 → `/user-space?tab=messages`；设置 → `/user-space?tab=settings`；我的 → `/user-space?tab=posts`
- 两处挂载同一组件同一配置：①首页（移动端，滚到论坛区 IO 检测后 250ms 滑入，Hero 屏隐藏，滚回顶部滑出；包 `prefers-reduced-motion` 直显直隐）②UserSpace 内常显
- 桌面/横屏：首页不挂底栏（顶部 UnifiedNavbar 足够）；UserSpace 横屏仍走 SideRail（消费同一 config）

### 4.2 资产的去处
- `assets` **保留为合法路由与 tab**（`USER_SPACE_VALID_TABS` 不删它），只是**不再占底栏**
- 在「我的」页顶部加资产快捷入口卡（钱包/订阅/积分 → `/user-space?tab=assets`）；底栏在 assets 路由下「我的」高亮

### 4.3 改动点
- 新建 `src/config/bottom-nav.ts`：items（id/label/icon/route/badge 来源）唯一真源
- `useUserSpaceTabs.js`：`userSpaceNavItems` 删 community；`USER_SPACE_VALID_TABS` 删 `'community'`；默认 tab 改 `'posts'`；底栏 items 改由 config 注入（组件消费方式不变：未读徽标/预载/指示器逻辑全保留）
- 重定向：`?tab=community`、`/user-space/posts` → `/?view=latest`（沿用 `src/router/routes/user-space.ts` 既有模式，保留其余 query）
- `UserSpaceMain.vue`：移除 community 分支的模板/懒挂载/过渡方向判断
- 「我的」页（posts tab）：顶部加资产入口卡
- 未读徽标：同一 notifications store，两处底栏一致

## 5. 任务 D：Hero 管理后台升级

**现状**：已有 `HeroConsole`（`/admin/hero-console`，「首页英雄区装修」）——左侧列表（搜索 / 草稿-已发布 / 首屏显示-已归档筛选）+ 中间预览 + 编辑器 + 草稿/发布，数据走 `stores/homeHeroes.ts`。在它基础上升级为两类管理，不重做。

### D1 首屏唯一 Hero（street-scene 模板）
- 模板选择新增「首屏街景」类型；编辑器支持**双图上传**（竖 1170×2532 / 横 2560×1440，WebP ≤350KB，走现有 Cloudinary 签名上传管线）
- **单例语义**：同一时刻只允许一条已发布 street-scene——保存/发布时前端校验 + DB partial unique index（`where template='street-scene' and <published 条件>`）并发防呆，冲突给友好报错
- 预览：竖/横双框切换（对齐 `home-hero-font-demo.html` 的构图，叠加 scrim / 问候 / 呼吸提示位置示意）
- 首页端缺省回落逻辑不变（无生效行 → `main1-1280.webp`）

### D2 普通 Hero 流管理（官方 tab）
- 现有能力全保留（列表/搜索/筛选/草稿/发布/归档）；增强：
  - 列表新增「官方 tab」视图：按 `sort_order` 展示官方 tab 实际排布，支持拖拽排序写回
  - 行内增加「官方位次」标记
  - 预览区增加「官方 tab 堆叠预览」（模拟首页官方 tab 的卡片堆叠效果）

### D3 权限与安全
- 入口已在 admin 路由（requiresAdmin 覆盖）；写通道沿用 homeHeroes store 现有模式，**不新增匿名可写面**（项目红线：anon 可写表 = 0）
- street-scene 字段 + partial unique index 的迁移与任务 A 的 DB 迁移**合并为一条**

## 9. 红线与项目坑（来自实战，务必遵守）

1. **勿动 `dist/`**（构建验证只产出 `dist-check`）
2. **勿动 `--liquid-*` 玻璃单源**；暗色覆写走 theme-manager 13 容器白名单机制
3. 新 `!important` 必须登记 `scripts/important-budget.json`（例外：`html.<页> body{overflow:visible!important}`）
4. 动态数据（流/hero）**不进 SW 预缓存壳**；hero 渲染层与论坛组件异步加载，不进首屏壳（首屏壳只有 9 个静态 import 的 app-*.js）
5. `push-sw.js` / shell 预缓存相关文件没任务就不要碰
6. 生产构建剥 Vue 告警——「没告警」不能当验证依据；用探针断言
7. 探针（Playwright）必加 `--no-proxy-server --proxy-server=direct:// --proxy-bypass-list=*`；同一 path 只注册一条 `page.route`；mock Supabase 必回 `Access-Control-Expose-Headers: Content-Range`
8. 本机 zsh 的 `grep` 多模式 `\|` 静默失效——用专用搜索工具
9. **改完必反证**：stash（带 pathspec，先看 `git stash list`）→ 确认探针变红 → pop → 复跑全绿
10. 部署相关（SSH push / CI 盯构建 / version.json 核对）不在本交付范围；本任务只做到 `dist-check` 构建 + 本地探针全绿
