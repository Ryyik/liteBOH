## 广告图片「白图」修复（13:00）

报障：「广告图片加载不出来，上传了也是一个白图」。

根因（已在线上数据核实）：`advertisements.image_url` 存的是上传返回的 Cloudinary 原址
`https://res.cloudinary.com/dkqae7j1m/image/upload/v1794362329/boh-cloud-plus/admin-ads/xxx.jpg`，
而 `AdSlot.vue` 模板直接 `:src="ad.image_url"` —— **没走全站统一的库图改写层**。
该域名大陆不可达（`utils/db-image-url.js` 头部 2026-09-29 实测记录），全站其它库图
（帖子封面 / 活动 / 新闻 / 相册 / 商城）都经 `resolveDbImageUrl` → `cdn.blockofhome.cn`，只有广告位漏了。

⚠️ 表象极易误判为 CSS 或「上传失败」：请求在 TLS 阶段**挂起**、不是 rejected
⇒ `@error` 不触发 ⇒ 连 📢 占位都不出现，只剩 `.ad-slot-media` 的 `#f2f2f4` 近白底。
所以「白图」而不是「裂图」。用探针只看 `naturalWidth` 也抓不到（当时 0×0 还以为是 lazy），
必须看 **img.currentSrc 的域名**。

改动三处：
1. `src/views/Forum/components/AdSlot.vue` —— `mediaUrl = computed(() => resolveDbAdImage(ad.image_url))`；
   失败标记改用 `useImageFailure`（按 URL 记账，换图/重传自动恢复，替掉单个布尔）。
2. `src/utils/db-image-url.js` —— 新增 `DB_AD_IMAGE_TRANSFORM = f_auto,q_auto:good,c_limit,w_1400`
   （**c_limit 不是 c_fill**：裁切归 CSS 的 object-fit，预裁会让 `card_size=auto` 档变形）+
   `resolveDbAdImage`。
3. 后台预览（「上传了也是白图」的另一半）：`EditDrawer.vue`、`DataAdmin.vue` 的图片预览
   原来用 `getImageUrl`（asset-helper）—— 它对 http(s) **原样直通**、不改写主机，
   所以同一张图在后台抽屉/列表/卡片缩略图里同样白。全部换成 `resolveDbImageUrl`。

自证：新增 `tests/unit/ad-image-cdn.test.js`（11 条，含反证：把 `:src` 改回 `ad.image_url` 当场 2 红）。
`tests/unit/shop-image-cdn.test.js` 是同类事故的先例，写法照抄。
浏览器实测：广告 img `currentSrc` 已变成
`https://cdn.blockofhome.cn/dkqae7j1m/image/upload/f_auto,q_auto:good,c_limit,w_1400/v1794362329/...`，
200、natural 750×750、complete。
`npm run verify` 全绿（343 files / 4500 tests）。
