## 首页来回滚动加载不全 探查（22:21 用户反馈）
- **复现硬证据（probe-home-scroll.mjs）**：模拟快速来回滚动（步长 1800px + 60ms 间隔 + 5 轮瞬跳），scrollHeight 在过程中 **5587 → 5684 → 5738**（+97 / +151px），PASS：所有行 IO 800px 兜底全渲染、21 张图全 loaded、无报错。
- **行高对照（占位 720px vs 真实）**：
  - Beta6RenewalHero: 760（+40）
  - MascotNewHero 方块设定集: 756（+36）
  - AgentPreviewHero BOHONE: 702（−18，反向收缩！）
  - 其余行 720±，总累计净 +97 ~ +151px
- **根因**：`.home-hero-row` 同时挂了三层占位高度，互相打架：
  1. `.is-deferred { min-height: min(720px, 78vh) }`（900vh 视口下 = 702px）
  2. `@supports (content-visibility: auto) { contain-intrinsic-size: auto 720px }`（跳过渲染时占位）
  3. 各 hero 组件自身 min-height（如 Beta6 `min(86vh, 760px)` = 760）
- **机制**：滚动下行时 IO 触发 `<slot v-if="shouldRender">` → 真实内容挂上 → 各行替换为真实高度 → 页面总高度变化 → 滚动条位置与内容对不齐 → 用户感觉"内容在跳、加载不全"。阶段 3 瞬跳 5 轮期间高度来回涨 151px，最容易被误判为"没加载完"。
- **次要**：content-visibility: auto 在真实 Chrome（不是 headless）快滚下可能出 paint-skip 留白（已知 Chromium 1404124 / 1466315 类 bug），本次 headless 未现；IO 800px margin + 60ms 短间隔的极端快滚仍能保证全部触发，PASS。
- **建议修法**（等用户拍板）：
  - A) 干掉 `.is-deferred` 固定 min-height + 把 `contain-intrinsic-size` 改成每行 hero 自声明（通过 CSS 变量 `--row-intrinsic`），各英雄区暴露自己的预测高度
  - B) 直接删 `content-visibility: auto`（IO 800px 已经跳过 slot 渲染，c-v:auto 的额外布局优化收益小、副作用大）
  - C) 把 IO 改成 `rootMargin: 0` + 先用 `ResizeObserver` 实测首行真实高度后回写 `contain-intrinsic-size`，动态收敛占位
- 探针 path: probe-home-scroll.mjs；截图 debug-screenshots/home-scroll-{row1..6,final-mid}.png。
