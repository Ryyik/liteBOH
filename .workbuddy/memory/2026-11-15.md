## 修「hover 上去不展开」（同日下午）

用户报障：mini 态 hover 不展开。实测定位到**两个原因**：

1. 🔴 **汉堡上被代码特意屏蔽了 hover 展开**（`isOverMiniBurger` 早退，是 11-14 为修
   「点击落空」加的）。但 mini 态只有 logo/登录/汉堡三个元素，用户想展开**必然指向
   汉堡** —— 对照实测：hover logo→720、hover 登录→720、hover 空白→720、**hover 汉堡→176**。
   代价比收益大，删掉早退。
2. ℹ️ **导航胶囊不是视口居中，而是偏右 120px**（`landscape-rail.css` 的
   `body.page-home .unified-nav-surface { left: calc(--userspace-rail-w / 2) }`，
   ≥1280 档 rail=240）。这是有意的「跟内容列居中」，不是 bug —— 但往屏幕正中 hover 会落空。

配套改动（不改会引入新问题）：

- **展开态保留汉堡**（CSS 去掉 `:not(.nav-expanded)`）：否则 hover 触发后汉堡消失，
  鼠标下方突然变成空白/搜索按钮（误触），而且没有按钮可以点回去。
- **汉堡点击改 `pointerdown`** + click 只认 `detail === 0`（键盘合成 click 恒 0）：
  pointerdown 在汉堡位移前触发，必定命中；detail 判据避免鼠标单击被 toggle 两次。
- **🔴 修 toggleMiniPin 取消钉住收不起来**：原来走 `scheduleMiniCollapse`，它 280ms 后
  检查 `miniPointerInside` —— 点击时指针必然还在汉堡上 ⇒ 永远不收。改成立即收。
  收起后胶囊缩回 176、汉堡退回原位，指针自然落到胶囊外，不会被 pointerenter 拉起。

探针：mini-bar 30/30（`!burgerRendered` 断言改为 `G_hover_burger_kept`）、optical 20/20、
mobile-menu 52/52、nav-dark ALL PASS、type-check + verify:fast 绿。

手动实测（h5/h7）：hover 汉堡 →720×50；点汉堡→pin；移开→保持；再点→176×44；
键盘 focus→720、Enter→pin、再 Enter→176；鼠标单击只 toggle 一次。

## 开屏期间不挂载导航栏（同日下午，用户口径）

`App.vue` 的 `<UnifiedNavbar v-if>` 现在在首页开场画（`.home-gate`）在场期间为 false
—— 是**不渲染**，不是隐藏。开屏层是 inset:0 满屏浮层 + 锁滚动，导航压上去既抢视觉
重心又跟「下滑揭开」的手势层抢 z 轴。

### 架构（为什么不是简单加个判断）

开屏状态住在 Home 内部（`useGatePull` 的 `gateDismissed`），导航在 App 级 —— 没有共同
祖先可 provide。所以：

- 新建 `utils/home-gate-storage.js`：把「看过开场画」的 localStorage 判据（key +
  24h 窗口 + buildId 指纹）从 useGatePull **抽出来独立**。不抽的话 App 静态导入
  useGatePull 会把**首页整条懒加载链**拉进主包。
- 新建 `composables/useHomeGate.js`：模块级 `homeGateScreening` 单例，
  **初始值同步**由 `readGatePassed()` 算出（否则已通过过的会话会先挂载再卸载，闪一下）。
  注释里写明它只表示「开场画还没看完」，不等于「在首页」。
- `utils/global-navbar-visibility.js` 加第 2 个**显式参数** `gateScreening`
  （刻意不读全局单例：那是纯路由判据 + 有单测，读可变状态会让 `path:'/'` 的用例
  取决于跑测时的 localStorage —— 第一版就这么写，红了 3 条）。
- `Home/index.vue` watch(gateDismissed) → `setHomeGateScreening(!dismissed)`，immediate。
- 补 4 条单测（开屏中 / 结束 / 非首页 / 不覆盖 hideNavbar），12/12 绿。

实测：首次进首页 nav=false+gate=true；开屏结束 nav=true；已通过后刷新首帧即 true；
非首页不受影响。开屏结束走 App 的 `unified-nav-slide` 220ms 滑入。

## 下拉面板改成「悬浮岛」（用户口径「把这个也做成岛的形式」）

形态：从「与胶囊同宽的整块面板」→ **挂在被点一级项正下方的悬浮岛**。
实测 718 宽里内容只占 181（右侧 537 = 75% 无内容），岛是 224×150~245、radius 20。

- 定位挂在 `.nav-menu-item`（vendor 已是 `position: relative`）→ 换哪项跟哪项走
- 宽度 `max-content` + `min-width: 224` → 各面板同宽，不会点一个跳一个
- 条目 `a` 改 `display:block`（整行可点），行盒宽度 = 岛内宽 202
- 分组标题 `::after` 补 `›`（原先 chevronCount: 0，岛变小后更需要"还有内容"的提示）
- 玻璃 0.82 → **0.92**：岛变小后背后页面的 tab 文字（官方/最新…）会透进卡片上半部

### 三个必须记住的坑

1. **`left:0;right:0;margin:auto` 对 `width:max-content` 不居中** —— 引擎走 shrink-to-fit，
   auto 边距在宽度定下来之前归 0（实测偏右 98 = 半张卡）。改用 `left:50%` + **`translate: -50% 0`**。
   ⚠️ 不能用 `transform: translateX(-50%)`：vendor 的进出场动画就是 transform
   （translateY + scaleY），两个声明互相覆盖、动画直接失效。`translate` 是独立属性，
   实测动画全程 cardCx 恒定（751），不漂。
2. **`a:hover` 的悬停底色一直是被全局重置吃掉的**：`src/style.css:290`
   `a:hover { background-color: transparent !important }`（压 glass-ui-vue 用）。
   特征：`matches(':hover')` 为真、`transform` 生效，但 computed background 仍是透明 ——
   只看截图会误判成"没写 hover"。暗色之所以正常，是 navbar-dark.css 用 !important 另写了一份。
   ⇒ 悬停底色改放 **`li:hover`**（行盒与 a 等宽），不用 !important、不动全局重置；
   同时把 vendor `a:hover` 的 `translateX(4px)` 置 none（整行有底色后文字滑动像行裂开）。
3. 岛在 DOM 里是 surface 的后代 ⇒ 鼠标从胶囊穿过 11px 空隙进岛**不会**触发 pointerleave 收起
   （实测空隙停 450ms 仍展开）；岛内点击正常导航并回缩到 180。

### 验证

mini-bar 30/30、optical 20/20、mobile-menu 52/52、nav-dark ALL PASS、verify:fast 绿（exit 0）。
1440/1024/744/700 四档：岛 224 宽、中心与被点项严格对齐（误差 0）、无横向溢出。

## 下拉从「窄卡」改成「宽岛」（用户口径「点开下拉菜单变一个类似别的岛的那种」）

形态：**surface 自己长高成岛**（与 `has-status-card` / `has-boh-island` 同一套机制），
菜单内容坐在长出来的玻璃里，不再在导航下面浮一张卡。
实测：服务/关于（3 项）720×113 单行三列；探索（4 项）720×160 2×2；社区（5 项）720×160 3+2。
圆角 30，展开材质 `var(--liquid-bg-strong)` + `var(--liquid-filter)`。

- 高度：`.nav-submenu` 在 `<li>` 里，**不是 surface 的文档流子节点** ⇒ 撑不开 surface；
  JS 用 ResizeObserver 实测写 `--nav-submenu-h`，surface 走 `calc(rest + var(--h))`。
- 定位：`.nav-submenu` 用 `position: fixed` + `left/right: 0` —— surface 带 transform，
  fixed 的包含块就是 surface，左右 0 恰好铺满岛宽（别再改回 absolute）。
- 列数按条目数：≤3 → 3 列（一行）、4 → 2 列、≥5 → 3 列。

### 四个坑

1. **surface 是 `overflow: visible`** ⇒ 长高过程中（50→160）菜单已在玻璃**外面**画出来了
   （看起来"内容先蹦、玻璃后追"）。展开态必须 `overflow: hidden`。
2. **扁平二级的 `li` 直接挂在 `ul` 下，没有 `.nav-submenu-pane`**（只有分组型才渲染 pane）
   ⇒ 网格只写在 pane 上，社区会排成一列。ul 与 pane 两处都要写。
   pane 用 `grid-column: 1/-1` 再内部铺网格，**不能**用 `display: contents`
   （那样下钻 Transition 打在 pane 上的 transform 会失效）。
3. **材质切换要过渡 `backdrop-filter`**：否则模糊在 height=50 时"啪"地打开，先闪一下才长高。
4. 动画突兀的三段来源都去掉了：vendor 的 `translateY(-12px)+scaleY(.96)+400ms`、
   li 的 50~250ms 错峰淡入、height 500ms。现在只留「高度 260ms + 内容淡入 160ms」。

## 下拉改「单列 + 流畅展开 + 竖屏对齐」（用户：「展开动画不够流畅」「一行显示一个选项」「竖屏也要优化」「文字灵动闪光一下」）

### 单列（一行一项）
`--nav-cols` / `submenuCols()` 整个删掉，`.nav-submenu` 回 `display: block`（pane 也是 block）。
裸单列在 720 宽的岛里只有一个 40px 的字，右半场 650px 全空 —— 所以每行补了**右侧路径**
（`.nav-submenu-meta`，取 `node.path`，下钻入口显示 `{{n}} 项`）。
模板 7 处 `{{ x.label }}` 都包成 `<span class="nav-submenu-label">` + `<span class="nav-submenu-meta">`。
实测：探索 4 项 → 岛 720×255，行 694×46.6；社区 5 项 → 251。

### 流畅度（三处根因，都实测过）
1. **`backdrop-filter` 是掉帧主因**：height 50→255 的 300ms 里每帧都要按新裁剪区重算一次
   720px 宽的模糊。展开态改成**不写 backdrop-filter**，改用局部令牌 `--nav-frost-bg`
   （rgba(252,252,254,.97)，`--liquid-bg-strong` 的 .84 压不住背后 tab 栏，实测字会透过来）。
   帧采样：点击→520ms 每帧记高，`max frame gap 16.9ms`、单调增长、无停顿。
2. **`--nav-submenu-h` 首帧是 0**：旧写法 `await nextTick()` 之后才量 ⇒ 打开那帧是
   `height: calc(rest + 0)`，下一帧才跳目标值（肉眼=「卡一帧再弹开」）。
   现在用 `:ref` 收 `submenuEls`（菜单常驻渲染、收起态只是 `visibility: hidden` ⇒ 可量），
   `watch(expandedMenu, { flush: 'pre' })` 在**类挂上之前**同步预量。ResizeObserver 只兜三级下钻。
3. **多轴不同步**：旧值 max-width 300ms / height 260ms / 圆角 260ms（尾部几十毫秒形状还在扭）。
   现在统一 300ms + 新令牌 `--nav-open-ease: cubic-bezier(.32,.72,0,1)`
   （`--ease-emphasized` 是 (.16,1,.3,1)，前 15% 走完 60% 距离 ⇒ 读作"啪"地弹开）。
   只用于导航，**不要上提成全局令牌**。
   另：内容块**不再自己淡入**（`.nav-submenu` 的 opacity/visibility 关闭时推迟 300ms），
   出入完全由 surface 的高度裁切揭示 —— 一层动画才没有"玻璃在长、内容在抖"。
   vendor 的 `letter-spacing .3s` 过渡也钉死（6 行同时重排字距 = 展开时文字在抖）。

### 🔴 新坑：`:global(...)::before` 的伪元素会被管线吞掉
写成 `:global(#x .nav-submenu a)::before { position: absolute; ... }`，编译产物变成
`#x .nav-submenu a { content: ""; position: absolute; inset: -2px -20% }` —— **`::before` 没了**，
声明直接落在 `a` / `li` 上。现象极难认：`li` 宽 2px、`a` 宽 32px、`ul` 高 18px、岛只长到 68px。
✅ 正确写法：伪元素放**里面** —— `:global(#x .nav-submenu a::before)`。
（同类先例：`:global(A) .b` 前缀式会丢掉后代选择器。凡 `:global()` 一律整段包裹到伪元素。）

### 2. 快速来回切换时旧菜单残留（用户报障）
根因不是 z-index，是**可见性用了延迟 transition**：
`opacity 0s linear 300ms` 本意是「关闭时等玻璃收完再消失」，但它对**所有**失活都生效 ——
A → B 切换时旧 `ul` 也在等这 300ms ⇒ 两个菜单同时可见、叠在一起。
改法：transition 全删，可见性交给 JS 的 `.is-closing`：
`watch(expandedMenu)` 里，切到别的菜单就立即清空 `closingMenu`，只有「变 null」才保留 300ms。

### 3. 竖屏岛化（用户口径「竖屏没有做好同样岛化的适配」）
菜单从「岛下面浮一张 fixed 白卡」变成「surface 自己长高，菜单坐在长出来的玻璃里」，
与桌面下拉同一套机制：
- 类 `has-mobile-menu`（= `isMobileMenuOpen`）→ `height: calc(rest + var(--nav-mobile-h))`
- `--nav-mobile-h` 由 JS 实测；菜单**常驻渲染**（收起态只 `visibility:hidden`）⇒ 打开前能预量，
  与桌面预量同一套（避免首帧 height=0 那一帧「卡一下再弹开」）。ResizeObserver 兜二级下钻。
- `.nav-menu-mobile`：`position: absolute; top: var(--global-nav-rest-height); left/right: 0`，
  透明无自有材质，`overflow-y: auto` 自己滚（`.nav-menu-mobile-content` 不再套第二层滚动）。
- 底色用新的 `--nav-frost-solid: #fbfbfd`（实底）。0.97 的 `--nav-frost-bg` 在 350×340 的大面板上
  仍能辨出背后正文（实测与菜单项叠字）；小浮层透一点是玻璃，大面积透一点就是脏。

**四个坑：**
1. `top: 100%` 必须换成 `var(--global-nav-rest-height)` —— 岛长高后 100% 是新的包含块高度，
   菜单被推到岛底下面。
2. `position: fixed` → `absolute`：iOS 上 fixed 浮层展开会把文档滚回顶部
   （用户报「竖屏点开导航栏直接回到最前面」；本地 Playwright 复现不了，属真机行为）。
   另加 `pinScrollAfterMenuToggle()` 兜底（打开后下一帧比对 scrollY）。
3. `.nav-container` 基础规则是 `height: 100%` ⇒ 岛长高后导航行被拉满并居中、**浮在菜单中间**
   （实测截图菜单项从导航行上下穿过去）。必须 `has-mobile-menu > .nav-container { height: rest }`。
4. 文件后段有一条 `.nav-menu-mobile.active { display: flex }`（0,2,0），会把块级容器压成 flex 行盒。
   岛化规则里必须显式 `display: block`。

## 横屏 hover 回归 + 展开后不能滚页面（用户两连报）

### 1. 横屏 hover 自动展开「又没了」= 资格判定的宽度阈值
`DESKTOP_MINI_QUERY` 原为 `(min-width:1024px) and (hover:hover) and (pointer:fine)`。
700–1023 的**横屏**（笔记本半屏窗口、内置预览面板、平板横屏）落进「常驻长条」档，

配套两处，缺一不可：
- `style.scoped.css` 新增 `@media (orientation:landscape) and (min-width:700px) and (max-width:1023px)`
  的 mini **尺寸**（180 / 高 44 / container padding 12 / 登录按钮 padding 6 10）。
- 🔴 **`fold-nav-rail.css` 的 769–1023 规则必须排除 `.nav-mini-caps`**。那条给完整长条做
  「按内容列收窄 + 左移 gutter/2」：`max-width: min(720px, calc(100% - 24px - var(--fold-nav-gutter, 88px)))`
  = `100% - 112px`。它带 `body.page-home #unified-nav-container …`（1,2,0 起），压过 mini 的
  `#id .surface.nav-mini-caps:not(.nav-expanded)` ⇒ 实测计算值 `max-width` 直接是
  `min(720px, 100% - 112px)`、宽度 720，**mini 的 180 完全不生效**，展开后还左移 44px。
  加 `:not(.nav-mini-caps)` 后 900 档实测 180 → 720、center 450 = 视口中心 450。

护栏：`probe-nav-mini-bar` 新增场景 I（900×600）4 条断言：mini 宽 180 / hover 展开 720 /
展开后视口居中 / 点「社区」下拉能长出来且居中。现在 35/35。

### 2. 「点击展开导航栏之后没法滚动页面」
本地 Chrome **复现不出来**（桌面 1440 钉住后 wheel 600→1200→1800；竖屏 390 菜单开着
wheel 在岛内/岛外都能滚；900 宽下拉开着也能滚）。判断是 iOS 的**手势死区**：
`.nav-menu-mobile` 是 fixed 岛内的 absolute 层，内容通常不够高（292 < max-height）⇒
容器自身不可滚，而 `overscroll-behavior: contain` 又禁止把多余手势交给祖先 ⇒

## hover 热区比胶囊大 312px（用户：「hover 区域不对，我鼠标放在远处他也起来了」）

### 根因（实测，不是猜）
折叠态胶囊盒子 = 180×44 @ (750,10)。但 `elementFromPoint` 扫描发现真实热区是
**x 752..928 / y 10..260** —— 胶囊下方挂着 178×312 的**不可见热区**。
链：`.nav-menu-mobile`（visibility:hidden, opacity:0, **pointer-events:auto**）
> `.nav-menu-mobile-content`（hidden）> `.nav-mobile-main-menu`（**visibility:visible**）。
🔴 `visibility` 是**可被子元素覆盖**的：vendor 的 `.unified-nav .nav-mobile-main-menu`
写了 `visibility: visible`，于是这块内容即使祖先 hidden 也照样 hit-testable ⇒
指针进入它 = 进入 surface 的后代 = 触发 surface 的 `pointerenter` ⇒ 离胶囊 200px 也会展开。

### 两层修法
1. `style.scoped.css`：折叠态 `.nav-menu-mobile { pointer-events: none }`，`.active` 恢复 auto。
   `pointer-events` 是唯一能**整棵子树**关掉命中测试的开关（visibility 不行，后代能压过）。
2. `index.vue`：新增 `isPointerOnSurface(event)` 几何判据，`handleNavPointerEnter` /
   `handleNavPointerMove` 都先过这道（`clientX/Y` 必须落在 surface 的 rect 内）。
   防的是未来任何"子元素故意溢出到盒外"的写法再次污染热区。
   实测：把 CSS 兜底用 addStyleTag 拆掉后，JS 判据仍能独立挡住（180→180）。

修后热区 = 胶囊盒子本身（x 752..928 / y 10..52）。

### 护栏
`probe-nav-mini-bar` 新增场景 J 三条：下方 120px 不展开 / 右侧 24px 不展开 / 盒内仍展开。
判据用「宽度是否 +120 以上」而不是精确 180 —— 收起动画尾巴上的 204 不是展开，别误判。
现在 38/38。其余：mobile-menu 全部通过、optical 20/20、nav-dark ALL PASS、
type-check 绿、eslint 绿、verify:fast exit 0。

⚠️ 顺带记录：1440 档胶囊中心在 x=840 而不是视口 720 —— 这是 `landscape-rail` 按内容列
居中的既定行为（页面 tab 栏中心也在 835），不是偏移 bug。

## 影集发布「开本」Hero 动画设计稿（docs/demos/album-hero.html）

用户口径三次收敛：① 要英雄动画引导（参考 Apple / Google）→ ② 3D 可以（选了 **CSS 3D 加厚**，不上 WebGL）
→ ③ **慢速优雅、内容多，但样式简约**（黑白灰，只有照片有颜色）。

- 成品：5400ms / 4 个节拍 / 3 张照片 + 5 条写字占位线；竖屏 390、平板 768、宽卡片 1120 三档；
  可拖时间轴、0.25× 慢放、降级动效、明暗切换，URL 参数 `?paused=1&t=&w=&theme=&reduced=&tilt=` 直接截帧。
- 核心手法：hero 的「书」与表单左侧封面槽是**同一个元素**，结束用 FLIP 飞进槽位（落点实测 ±1px）；
  慢的观感靠「动作之间留 100–250ms 呼吸」，不是把 duration 拉长。
- ⚠️ 踩坑 1：**preserve-3d 里伪元素压不住子元素** —— 用 `.book::after` 做书芯时，它把封面盖成了
  一叠横线（整本书外观消失）。必须用真实 `<div class="block">` + `translateZ(-3px)`。
- ⚠️ 踩坑 2：**`<figure>` 默认 `margin: 1em 40px`** —— 照片右移 40px 溢出书页，`margin:0` 必写。
- ⚠️ 踩坑 3：宽屏给书加基准倍率 `--k` 后，FLIP 目标**不能**再除以 k：`--sc` 是相对 `--k` 的倍率，
  除以 k 会让 1120 宽度下落点只有 133px（应为 176）。正确写法 `sc = slot.width / bookRect.width`。
- ⚠️ 踩坑 4：`innerText` 不含 `display:none` 的子元素 —— 竖屏读卡片底部那句会拿到空/错值。
