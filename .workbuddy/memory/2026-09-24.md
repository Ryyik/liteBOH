## 首屏开场画打磨（承接 09-23 的返工）

用户反馈四条，全部落地：

### 1. 「往下逛逛」太贴底
`StreetSceneHero` 的 `.street-hero-content` 底部 padding 从 `clamp(28px, 6svh, 64px)`（≈50px）
提到 `clamp(72px, 17svh, 152px)`（844px 高视口下 ≈143px），落在视觉下三分之一。
贴底既像被裁掉、也压住底栏安全区。

### 2. 横屏适配（两个真问题）
- **开场画被撑出视口**：`.street-hero { min-height: 480px }` 在横屏手机（视口 390~430px 高）下
  比视口还高 → 底部提示直接被裁。加 `@media (orientation: landscape), (max-height: 560px)`
  把 min-height 放开。
- **顶部被导航栏压住**：横屏导航是**全宽横条**（竖屏是居中胶囊），原来顶部 padding 写
  `max(84px, 12svh)` 不够。改为吃 `--userspace-nav-h`（导航实测高度）：
  `max(84px, calc(var(--userspace-nav-h, 78px) + 16px))`，横屏单独 `max(64px, calc(... + 12px))`。
  横屏问候语另收窄到 `min(52%, 24ch)`、字号降到 `clamp(19px, 2.4vw, 26px)`。

### 3. 每次发布新版本都要重播开场画
一次性标记的 key 带上构建指纹：`boh-home-gate-passed:${<meta name="boh-build-id">}`。
`boh-build-id` 只由生产构建注入（`vite.config.js` 的插件 `apply: 'build'`），
**dev 下拿不到 → 退回不带后缀的 key**，所以开发与探针行为不变。
⇒ 每次发版用户再访问都会看到一次开场画；同一次部署内不会重复打扰。

### 4. 动画：不追快，追精致
- 时长 1080ms → **1200ms**（开场层），论坛层 **1320ms**（比开场层晚收 120ms，形成余韵）
- 缓动从纯 `linear` 换成两条：开场层 `cubic-bezier(0.32, 0.06, 0.36, 1)`（起步柔、收尾缓），
  论坛层 `cubic-bezier(0.16, 1, 0.3, 1)`（easeOutExpo 类，落得柔）
- 开场层退场加 `scale(1 → 1.04)`：纯平移像「贴纸被抽走」，一点推近才有镜头让开的空间感
- **三层错开**是精致感来源：① 开场画内文字按 55% 时长先退（前后景分离，用 `:deep()` 选中
  `.street-hero-content`）；② 底图 1200ms 走完；③ 论坛层 1320ms 缓落
- 底栏入场 560ms linear → **760ms `cubic-bezier(0.16, 1, 0.3, 1)`**，位移 132px → 150px

### 5. 顺带修：开场画被论坛浮层「冒头」
竖屏截图里右下角出现论坛的发帖按钮。根因：`.mobile-compose-fab` 是
**Teleport 到 body** 的（父级就是 body），z-index 1200，而 gate 当时只有 60。
修法：gate 的 `z-index` 提到 **1300** —— 高于 1200（发帖按钮）、低于 9999（导航栏）
与 10000（登录模态框），既压住论坛浮层又不挡用户点登录；同时保留
`.home:not(.home-forum-open) .home-forum-stage { visibility: hidden }` 管 stage 内那类浮层。

### 6. 底栏浮现时序（用户：封面离开时导航栏自然出现，慢一点、晚一点）
底栏的挂载从 `forumOpen` 拆出独立开关 `bottomNavReady`，加一条延迟：

| 时点 | 事件 |
|---|---|
| 0ms | 手势触发，封面开始退场（缓动起步柔，前 100ms 几乎不动） |
| 780ms | 封面走了 ~82%，底栏从下方开始浮现（挂载即播入场） |
| 1200ms | 封面卸载离场，此刻底栏浮到约一半 |
| 1800ms | 底栏完全就位 |

- 延迟 `BOTTOM_NAV_REVEAL_DELAY_MS = 780`，时长 `BOTTOM_NAV_ENTER_MS = 1100`（默认仍是 760，
  只有首页传更慢的值 → `UserSpaceBottomNav` 新增 `enterDuration` prop + CSS 变量
  `--bottom-nav-enter-duration`）
- ⚠️ **曲线踩过一次坑**：初版用 `cubic-bezier(0.16, 1, 0.3, 1)`（easeOutExpo），
  前 30% 就走完 80% 位移 —— 实测观感仍是「弹上来」而非「自然浮现」。
  换成与封面同族的 `cubic-bezier(0.32, 0.06, 0.36, 1)` 后位移才均匀铺开
  （实测 opacity 0.01→0.07→0.20→0.37→0.58→0.72→0.83→0.91→0.96→1.00）。
- 已通过过开场画的会话（sessionStorage 命中）`bottomNavReady` 直接为 true，不补浮现动画。

### 追加：cloudinaryUploads（上传队列）判定 —— 结论「摘页签、保表」

**表不是"上传队列"，是「上传归属台账」**（删图 EF 的第一道归属校验就查它：
`supabase/functions/cloudinary-delete/index.ts:167` `filterOwnedCloudPublicIds`）。表**不能删**。

**页签建议摘掉**，4 条依据：
1. 列配置是上一版语义 —— 表里根本没有 `status`/`error_message`/`retry_count`
2. `fields: []`，本来就不能编辑
3. 唯一动作 delete 是 `.from(table).delete().eq('id',..)` **硬删台账行、不删 Cloudinary 文件**
   （data-management 目录下 grep 不到任何 `cloudinary-delete` 调用）→ 删完用户合法删图会 403，**反向作用**
4. 数据没法判断该不该清（见下）

⚠️ **「孤儿」≠ 垃圾**（本轮最重要的反直觉发现）：63 行 `claimed_at is null and deleted_at is null` 里，
逐行查引用后 —— `forum` 42 个孤儿**0 个被引用**（真垃圾）；但 `hero-console` 13 个里 **4 个是首页 hero 在用的图**、
`shop-console` 2 个**全部在用**、`avatar-frames` 5 个里 2 个在用。共 **8 张线上素材被标成"孤儿"**。
根因：`markCloudinaryUploadsClaimed` 全仓**只有 3 个调用点**（`post-api.js:924`、`block-wall-api.js:104`、
`UserSpaceMain.vue:2301`），**装修台（HeroConsole/ShopConsole/AvatarConsole）没接** → 上传即永久孤儿。
⇒ 任何按 `claimed_at is null` 的批量清理都会误伤线上素材，必须先补装修台的 claim。

**清理缺口**：全库 6 个 cron 没有一条碰这张表，孤儿持续累积（5月1/6月23/7月0/8月15/**9月24**）。
该清的是 `source='forum' and claimed_at is null and created_at < now()-7d`，且必须走 EF 删文件 + 标 `deleted_at`。

## 数据管理面板列错误：修复落地 + 复验（承接上一节）

193 个写入字段全量验证约 1 分钟；Management API 有**限流**（ThrottlerException），跑太快会漏判。

## 首屏两修：底栏浮现位置偏移（真 bug）+ 退场动态感增强

### 1. 底栏浮现「位置偏移」—— keyframes 与定位方案打架（真 bug）

**实测定位**（`scripts/probes/probe-gate-bottomnav.mjs`，新增）：动画期间 `left=-175, offX=-195`
（偏出左屏半个身位），摘类瞬间跳回 `offX=0` —— 用户看到的偏移就是这 195px 猛跳。

**根因**：底栏有两套水平定位 —— 桌面（≥768px）`left:50% + translateX(-50%)`；
**移动（<768px）`left:16px/right:16px` 拉伸式，transform 只有 `scaleX()`**（bottom-nav.css 923 行媒体查询）。
而入场 keyframes `bottomNavSlideIn` 在 transform 里**写死 `translateX(-50%)`** ——
移动端上等于多平移半个身位，动画结束摘类 → 跳回。⚠️ 该 bug 在 UserSpace 首次进入同样存在（非首页特有）。

**修法（通用解）**：keyframes 改用**独立 `translate` 属性**（`translate: 0 150px → 0 0`）——
它与 `transform` 是两个独立属性、叠加生效互不覆盖，两套定位方案通吃，摘类后归零无跳变。
**教训：凡 keyframes 动 transform，必须先确认元素所有定位形态下 transform 的静态值**；
需要「只动一个分量」时用独立 translate/rotate/scale 属性。

### 2. 首屏退场动态感增强（style.scoped.css + index.vue 计时器同步）

动态感来自「更快 + 加速曲线 + 论坛层更低处追赶」：

| 参数 | 改前 | 改后 |
|---|---|---|
| 开场画退场 | 1200ms 缓出（匀速感） | **880ms 加速**（easeInQuad `cubic-bezier(0.55,.085,.68,.53)`，越走越快冲出） |
| 位移/scale/尾态透明度 | -100% / 1.04 / 0.45 | **-112% / 1.06 / 0.25**（出屏更彻底） |
| 论坛层追赶 | 40px / op 0.78 / 1320ms | **88px / op 0.35 / 980ms**（从更低处追上） |
| 底栏起步/滑入 | 780ms / 1100ms | **560ms / 900ms** |

⚠️ index.vue 的 `GATE_TRANSITION_MS` / `FORUM_ENTER_MS` 与 CSS 变量必须同步改（卸载与摘类按它计时）；
`probe-home-revamp` B8b 断言写死了时长值（1100→900），改节奏记得同步探针。
**验证**：gate-bottomnav 时间线（动画全程 offX=0.0、560ms 起步 1460ms 落定无跳变）、
