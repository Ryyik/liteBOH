用户口径「玻璃样式写得太杂」。盘点 `UnifiedNavbar/style.scoped.css`：**71 处 `rgba(255,255,255,*)` / 28 个不同 α**、23 处 backdrop-filter、57 处 hex —— 病根是**没有材质口径**，不是格式。

**已做**（全部收敛到全局唯一出口 `src/styles/common/tokens.css` 的 `--liquid-*`）：
岛常态底色 `0.66→var(--liquid-bg)`(0.72)、描边 `0.34→var(--liquid-border)`(0.65)、
投影 `0 8px 32px rgba(0,0,0,.1)→var(--liquid-shadow-sm)`、沉浸态抄了一份 0.66 字面量→同令牌。

**两条实测分层真相（写进了 CSS 注释 + §21.13 + 探针文件头）**：
1. **展开态（has-status-card 等）的底色/投影从来没生效过** —— 该规则 (0,3,0) 被带 ID 前缀的
   基础规则 (1,1,0) 整体压掉；旁边的 `height`/`border-radius` 补了 `!important` 才活，
   这两条没补 ⇒ **静默死了很久**。本轮**删掉**这两条死声明（它们比字面量更坏：读代码的人
   会以为展开态另有一份材质），展开态材质与常态统一。
2. **暗色底色/描边真源是 `styles/themes/navbar-dark.css` 的 `!important`**
   （`rgba(20,27,37,.9)` + `rgba(220,235,255,.16)`，**藏青 palette**，与 BOHAI 暗色同族），
   与 `--liquid-*` 的中性暗色**不是一套** ⇒ 刻意不并入令牌；scoped 里那条暗色规则只剩
   **兜底**职责（暗色 CSS 懒加载失败时防岛变透明）。暗色**投影**它没声明 ⇒ 仍是本文件令牌、照常生效。

**视觉差机器量化**（改前/改后逐像素）：平均通道差 **5.22/765**、最大 **25/765**、约 **33%** 像素有可感变化
（主要来自描边 0.34→0.65 与投影换档）。对比图 `debug-screenshots/nav-dequirk-{before,after}-{light,dark}-{home,forum}.png`。

**验收**：新探针 `scripts/probes/probe-navbar-tokens.mjs` **11/11**；`probe-global-search` 58/58 ·
`probe-nav-mobile-menu` 48/48 · `probe-nav-dark` ALL PASS · `npm run verify` 全绿。
