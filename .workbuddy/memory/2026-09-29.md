### 二、沉淀「重构验证协议」`docs/重构验证协议.md` + `npm run compare:builds`

**核心命题**：拆分类重构的失效是**静默的**（没报错、没测试红，只是样式不生效或事件没人接），所以只跑 `verify` 不够。协议给了 **L1–L6 六层**，每层都写明**能力与盲区**：

| 层 | 工具 | 证明什么 | 证明不了什么 |
|---|---|---|---|
| L1 静态 | `npm run verify` | 语法/类型/结构/预算 | 跨文件字符串契约、产物一致性 |
| L2 单测 | （含在 verify） | 被断言的行为 | 没被断言的路径 |
| **L3 产物** | `npm run compare:builds` | **证明「纯搬运」**（声明级逐条比对） | 运行时行为、视觉 |
| **L4 配对** | （含在 L3 工具） | CSS scope id ↔ JS scope id 配对 → 排除「样式静默不生效」 | —— |
| L5 运行时 | `scripts/probes/*` | 真实交互 | 探针未覆盖的路径 |
| L6 人眼 | 无 | —— | **必须明示为人工步骤** |

1. **文件级 = last-write-wins，没有 merge 提示**：两个会话改**同一区域**→ 后写覆盖先写；改**不同区域**能共存（Edit 是基于磁盘最新内容的精确替换）。`ProfileMain.vue` 已经中过一次 —— 他们的「猫装饰去重」和我的通知 store 改动被 `git add` 混进同一个 commit `82e4555f`，内容没丢但归因断了。
2. **全仓总量型棘轮跨会话共享**：任意会话新增 1 条警告 → 所有人 `npm run lint` 都红（上面那条实盘）。代价是「红的原因不在你改的文件里」，所以**必须有上面那个 set-diff 手法**才归因得动。
3. **我的源码守卫单测会拦并行重构**：`tests/unit/notification-store-single-source.test.js` 断言 `ProfileMain.vue` 里必须有那行 import。他们若重构掉它 → 测试红。**这是好事**（立刻发现而不是静默），但要知道「红可能来自别人的改动」。
4. **产物级验证（L3）在并行期间做不了**：L3 需要「改动前/后」两份产物做字节对比，中间任何第三方 `src/` 改动都会污染基线。本次「删死代码」按协议本该跑 L3，**因为工作区里同时有 `forum-format.js`/`SmartOverview/utils/image.js`/`activities/*.vue`/新增 `db-image-url.js` 等并行改动，只能推迟到树安静时补跑**（不能拿一个被污染的 before/after 去宣称「产物字节不变」）。
