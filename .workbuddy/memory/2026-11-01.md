## 自审发现并修掉的两个隐患（2026-11-01 下午）

### 隐患 1：`manualChunks` 用 `endsWith('.vue')` 只拆走了 JS，CSS 仍留在首屏
- **症状**：三个岛（ShareIsland / ContentDetailIsland / NotificationSuggestIsland）的 JS 已进路由 chunk，
  但 `share-island`(27 处) / `cdi-`(66 处) 仍留在首屏的 `ui-components.css` 里 —— 白拆一半。
- **根因**：SFC 的**样式子模块** id 是 `X.vue?vue&type=style&index=0&scoped=…&lang.css`，
  `id.endsWith('/UnifiedNavbar/X.vue')` **匹配不到它**，于是落到下一条通配规则被塞回 `ui-components`。
  `GlobalSearchIsland` 当时用的是 `includes('…X.vue')` 才侥幸正确。
- **修法**：统一改成正则 `/\/UnifiedNavbar\/(A|B|C|D)\.vue/`，脚本与样式子模块都命中。
- **验收**：`share-island` → `ForumMain-*.css`、`cdi-` → 路由 CSS、`gs-bar` → 搜索岛 CSS；
  首屏 245 → **242 KB**（ui-components.css 9923→7310B gz，ui-components.js 反涨 309B）。
- 🔴 **通用教训**：`manualChunks` 里按 SFC 路径匹配时，**永远用 `includes` / 正则，不要用 `endsWith('.vue')`**。
  拆完必须验证**CSS 归属**，不能只看首屏 JS 体积 —— JS 走了 CSS 没走是静默的。

### 隐患 2：切回标签页自动强刷会丢未提交内容
- **场景**：用户打完字 → 点了别处（滚动/切预览）→ `document.activeElement` 回到 `body`
  → 切走 ≥30s 再回来 → `forceCleanAndReload` 强刷 ⇒ 内容凭空消失。
  原护栏 `isTypingInForm(document.activeElement)` 只看焦点，**这种场景完全失效**。
- **修法**（`version-checker.js`）：模块级 `dirtyEditables = new WeakSet()`，
  在 `document` 上**捕获阶段**监听 `input`，只对**文本型**输入（text-like input / textarea /
  contenteditable）标记「有内容」。`blockedBy` 扩成 `typing | media | editing` 三态。
- **为什么用 input 事件而不是比 `defaultValue`**：`v-model` 程序化回填**不触发** input 事件，
  所以不会把「页面本来就有内容」误判成用户输入；比 `el.value !== el.defaultValue` 精确得多
  （后者对任何 v-model 预填表单恒为脏）。
- **为什么只收文本型**：select / checkbox 的「值」不代表未提交内容，收进来会让列表页
  一碰筛选就永久禁用自动更新。
- **测试**：`tests/unit/version-checker-auto-apply-guard.test.js`（6 例，含 3 条对照）。
  反向证明做过：注释掉 `hasUnsavedEditableContent()` 后恰好那条用例变红（`dispatchEvent` 0 次）。

### 顺带加固：弱网不主动预取
- `useGlobalSearch.js` 新增 `isSlowOrMeteredConnection()`（`saveData` / `slow-2g` / `2g`），
  只拦**空闲预取**；悬停 / 聚焦触发的 `prefetchSearchPanel` 不拦（强意图信号）。

## 首屏字节棘轮门禁：上线即红，暴露「分块组合跨平台不可复现」（2026-11-01 中午）

### 做了什么
新增 `scripts/check-first-paint-budget.mjs` + `scripts/first-paint-budget.json`，
接入 `build:ci` 末尾（ci.yml 与 deploy.yml 都跑它）、`check:ratchets` 总账、
`gate-fixtures` 的 UNTESTABLE（同 check:bundle-size 口径）。
度量口径：index.html 直接引用的本地 JS+CSS（script src / stylesheet / modulepreload），
gzip level 9，外部 URL 跳过。当前基线 248407B = 242.6KB / 13 入口。

### 🔴 核心发现：分块组合跨平台不可复现，总字节可复现
首次提交 `ca0248ef` 后**部署 Build job 直接红**（deploy 被跳过、站点没更新）：
- macOS 本地 13 个入口，app.js 18.0KB，auth-api / bag / useGlobalAiPreferences 各自独立
- Linux CI 10 个入口，三者并进 app.js（24.6KB）
- 两侧**总字节几乎一致**：242.4 vs 241.7KB
- CI 日志同时有项目自己的告警：`壳 chunk "auth-api" 在产物里找不到 —— 请同步 SHELL_CHUNKS`

**排除过**：依赖版本漂移（lock 与实装逐项一致）、`CI=true`、macOS 大小写不敏感
（全仓无大小写冲突文件）、脏工作区（干净 worktree + CI 同款 3 个 VITE_ 变量重建仍 13 个）。
⇒ **结论：分块组合不可复现，别按单文件卡棘轮；只卡总字节。**

### 教训 1：棘轮门禁的判据必须选「跨环境稳定的量」
单文件基线 = 本地绿 / CI 红。改法：只按总字节判定，单文件差值降级为失败时的
诊断输出（本次 vs 基线逐项打印）。容差 2KB 吸收两处浮动。

### 教训 2：`--update` 必须拒绝脏工作区（这次真踩了）
第一版基线是在脏工作区录的（本仓库常有并行会话在改 src/）⇒ 本地产物混着别人的
在途改动，CI 构建的是提交树，录进去必然对不上。
已加护栏：`--update` 检查 `git status --porcelain -- src public index.html vite.config.js package.json`，
非空即 exit 1 并列出脏文件；确认无影响可加 `--allow-dirty` 显式跳过。
**录基线的正确姿势**：`git worktree add --detach /tmp/wt <sha>` + `ln -s node_modules`
+ 只写 CI 同款 3 个 VITE_ 变量的 `.env` + `npx vite build` + `--update` + 拷回。

### 教训 3：部署红要立刻 `gh run view <id> --log-failed`
`gh run view --log-failed` 直接给到失败步骤原文（本仓库输出带 ANSI 色，
`sed 's/\x1b\[[0-9;]*m//g'` 清一下更好读）。deploy job 因 build 失败直接 skip，
不点进日志只看 `conclusion=failure` 会误以为 deploy 有问题。

### 既有问题（非本次引入，待办）
`SHELL_CHUNKS` 期望 auth-api / bag / useGlobalAiPreferences 是独立 chunk，
但 **Linux CI 一直把它们并进 app.js**（每次部署都打 3 条 WARN）。
影响：precache 名单靠产物反推（check:shell-precache 仍 PASS），对首屏反而少 3 个请求，
**功能性无影响**，属名实不符，后续清理时再对齐。

### 顺带
`git push` 报 `cannot lock ref ... is at X but expected Y` 时先 `git fetch` 再看
`git rev-list --count origin/main..HEAD` —— 本次是并行会话抢先推了同一条 commit，
远端其实已同步，不是失败。
