产物：`ai-config-demo.html`（仓库根，单文件零依赖）+ `scripts/probes/probe-ai-config-demo.mjs`（71 断言）。

### 本次实测出的通用坑（已写进 MEMORY.md）
1. **玻璃的底图必须放在面板背后（进 backdrop-filter），不能放在面板自己的 background-image 上** —— 后者不经过模糊，图的深色字块会直接透进正文；实测白遮罩加到 0.90 仍能看出约 8% 的字块。改法是图挂在 `.frame` 上、`.page` 只留半透底 + backdrop-filter，blur 把字糊成色块。
2. **产品浅色 `--muted-foreground: #7f8d9f` 在白底只有 3.38:1**，低于 WCAG AA 4.5（管理面板所有模式 ID / 模型 ID 都在这个色上）。原型改用 `#5a6577`（5.41:1）/ 暗色 `#a8b0bd`（7.49:1）。
3. **「模板里有 data-anno」是没牙的断言** —— 撤掉渲染逻辑它照样绿（反证实测）。必须给 chip 打 `data-anno-chip` 并按 id 对齐断言「渲染出来了」。
4. **反证要单点撤**：一次撤两处会让流程中途崩溃（元素不可见超时），跑不到反证汇总段。
5. 切 tab 只切 class 不同步 `hidden` 属性 → 两个面板同时显示（`.panel.is-on{display:block}` 特异性压过 `[hidden]`）。
6. 徽标（`.badge`）在 `1fr` 网格列里默认 stretch，移动档会被拉成一整条横带 → 要 `justify-self:start`。
7. 手动填输入框时**不能整体重绘**（光标会丢），要单独同步提交按钮的 disabled。

## 第二轮：把「配置不够明确」改掉（已完成）

用户反馈「现在的配置不够明确」。先读真实 schema 对照（`config/tables.js` 的 bohaiModels 段 + `config/fields.js` 的枚举），定位出三类根因：

### 根因 1：同一个词指了 4 个不同的东西
| 位置 | 字段 | 实际存什么 |
|---|---|---|
| 免费模型库 | `freemodels.model_id` | 供应商的模型标识，如 `Qwen/Qwen3-8B` |
| BOHAI 模型 | `bohai_model_configs.model_id` | 指向上面的外键 |
| BOHAI 模型 | `bohai_model_configs.mode_id` | 管理员自起的**内部路由键**，如 `fast`（EF 按它找配置） |
| 实验室模型 | `lab_ai_model_configs.model_id` | ⚠️ **存的是 BOHAI 的 `mode_id`**（`LabAiModelConfig.vue:74` 的 option value 即 `m.mode_id`）—— 名字叫 model_id，值却是 mode_id |

### 根因 2：编辑器按「代码结构」分组，不按人的心智
真实字段被分成 `basic / provider / params / extra` 四组。想加一个模型给用户用，要跨 4 个组；`quota_multiplier`（计费）和 `temperature/top_p`（生成）混在同一组。

### 根因 3：界面把内部枚举名直接当选项文案
- `capability`: `chat / multimodal / plan / agent` → 界面直接显示 `聊天（chat）`
- `min_tier`: **10 个扁平值**（guest/free/plus/pro/max/ultra + 4 个 coding-*）堆在一个下拉里

### 改法（都落在 demo 里）
- **模型行**：主信息（显示名 + 内部标识）／标签组（能力 · 计费「按量 ×2」· 档位）／场景引用／操作（设置 + 开关），四段分明。
- **新增「模型设置」弹窗**：按人的心智分 4 组 —— 用户会看到什么 / 它在哪能干什么 / 生成参数 / 计费与顺序；**11 个字段全部带一句说明**；平台地址改成**只读继承**展示（模型上不再有地址输入框）。
- **能力/档位换人话**：`chat → 文字对话`、`multimodal → 能看图`；10 个扁平档位收成 6 档可读阶梯（所有人 / 登录用户 / Plus 及以上 / …）。
- **场景页**：每行写「影响什么」的具体用户路径 + 可展开的场景级参数（温度/最大输出，只作用于本场景）+ 独立启停；子场景标注「需要『能看图』的模型」，能力不符时下拉里点名 + 行内警示。
- **模型统一走 `mkModel()` 工厂**：默认值集中一处，避免新加入的模型漏字段在界面上变成空白（那正是「不明确」的来源）。

### 验证
探针 88 项全绿（新增：字段说明覆盖率 11/11、地址只读继承、能力不匹配警示、场景参数可改并激活保存、倍率改 2 自动变「按量 ×2」）。
反证：撤掉「字段说明」「地址只读」「不匹配警示」三处 → 3 项精准变红，反证成立。
⚠️ 反证过程中发现我自己写的两条断言算错了：`4 → 5` 才是对的（CATALOG 新增的免费模型只有 1 个，付费的默认不勾选）—— 这反过来证明了「默认只勾免费」生效；另一条取错了 option 元素。都按实测值修正了口径。

## 第五轮：用户报「自定义为啥不能直接显示平台名？」

用户发了截图（我这边没收到图片内容，按问题本身定位）。**根因**：
`provider` 是**接入方式枚举**（siliconflow / zhipu / openrouter / **custom** / tavily / cloudinary / turnstile），
而用户填的「平台名」在 `api_key_vault.label` 字段。我上一轮左栏写成 `label: providerLabel(id)`，

**修法**：`custom` 时用密钥的 label 当平台名（1 个密钥 → 直接显示它；多个 → 显示「自定义（N 个）」）；

⚠️ **数据模型限制（不假装能分清）**：`freemodels` 只记 `provider`，**不记「属于哪个自定义网关」**
⇒ 拆成多行会让每个自定义平台显示同一份模型清单（或模型数全乱）。
要真正"每个自定义网关一行"，得给 `freemodels` 加平台标识列（或建 platform 表 + 外键）—— 属破坏性改动，需先确认。

新增 2 条守卫（custom 用 label、多网关要说明共用清单），反证 1 处成立。

## 19:10 深挖「自定义为什么只能有一个」→ 发现静默覆盖缺陷（用户问「你觉得呢」）

**用户问的是「要不要给 freemodels 加平台标识列 / 建 platform 表」，结论是：先不要，因为有更前置的阻塞。**

### 查到的真实约束（不是推测）
1. `api_key_vault` 的唯一键是 **`(provider, purpose)`**（迁移 `2026061001_api_key_vault.sql:17`），
   EF 也是 `upsert(..., { onConflict: 'provider,purpose' })`（`api-key-vault/index.ts:475`）
   ⇒ **同一平台 + 同一用途只能存在一行**。`custom` 的 defaultPurpose 是 `chat`。
2. 调用链是 `bohai_model_configs.mode_id → provider → resolveActiveSecret(provider, purpose)`
   （EF:966 / 1056）—— **provider 就是路由键**，`custom` 天然是**单槽**。
   所以「给 freemodels 加 platform_id」只改 UI 归属，**不改调用**：界面上每个网关各有模型清单，
   真跑起来全走同一个 Key —— 比现在更误导。

### 因此发现的真 bug（比「名字不显示」严重）
「添加平台」对 `custom` 再保存一次 = **静默覆盖**第一次的密钥与名字，
而界面还提示「已加密保存」。用户会以为自己在加第二个网关。

### 本节改动
- `KeysAndModels.vue`：新增 `overwrittenKey` computed（按 provider+purpose 找会被顶掉的那一行）、
  对话框内 `data-km="overwrite-warning"` 警示块点名「将被覆盖的是哪一行」、
  `submitKey` 里**先** `await confirm(...)` 再 `vault.save(...)`、

## 19:06 「偶发丢 CSS / 样式错乱」排查（成员 tab + 我的页）——只读诊断 + 复现探针，未改源码

用户报障：有概率旧缓存导致样式错乱，「感觉失去了 CSS 样式文件的加载」，尤其是成员 tab 和「我的」页。

### 架构事实（构建产物内核实）
- `cssCodeSplit:true` + `assetsDir:'static'`：**路由级 CSS 全部不在 index.html 的 `<link>` 里**，由路由 chunk 的 JS 经 `__vitePreload` 助手动态建 `<link>` 注入；SW 预缓存只放 2 个壳 CSS（index.html 引用的），其余 108 个路由 CSS 靠 runtimeCaching `/static/css/` CacheFirst（maxEntries 140 / 30 天）。
- **「我的」页**（posts tab）三个全局样式 `profile-base/profile-panels/responsive-integrations` 唯一入口 = `async-loaders.js` 的 `preloadProfileStyles()`（动态 import，调用点几乎全是 `void`）；`shell-community.css`（`.community-page-grid` 等）走 UserSpace 路由 chunk 自带的 `index-<hash>.css`。
- **「成员」分区** = `AsyncCommunity`（CommunityTab.vue，无自身 `<style>`，全靠 shell-community.css）。

### __vitePreload 助手两个决定性行为（dist 内提取证实）
① `i[url]=true` 去重标记在 fetch 完成前写入 ⇒ **失败后同会话再调用直接 resolve、永不再建 link**（切 tab 无效）；
② CSS 失败 → `vite:preloadError` → `recoverDynamicImportFailure()` 有 **30s sessionStorage 冷却**；index.html 的 link-error 监听有 `bohAssetRecovery` 一次性护栏 ⇒ **只够救前一两次**。

### 探针复现（`scripts/probes/probe-css-load-failure.mjs`，自校准差分判据，已注册 `probe:css-failure`）
- 基线：profile-base 224 条规则。
- **场景 A**（三 CSS 持续失败）：DOM 全渲染但差分非空（`.profile-page-content{padding-bottom} 40px→0px`）；恢复链刷 2 次后预算耗尽（冷却+hasRecovered），**半样式常驻**；切走再切回差分不变（去重标记吃掉重试）。
- **场景 B**（路由 CSS 失败）：`import()` 被 rethrow 炸掉 ⇒ **整个 /user-space 路由加载失败、导航被吞**（点底栏无反应，页面留原处）——比样式错乱更严重的静默故障。
- **场景 C**（瞬时失败）：强制刷新 1 次后恢复（差分归零）——恢复链有效但代价是整页重载。
- ⚠️ Playwright `page.route` **拦不到 SW 代发的请求**（CSS_PROBE_SW=allow 变体验证）：SW 激活态下故障注入不稳定，结论以 SW 隔离的受控运行体为准。

### 次要发现
- `main.js` 的 `navigator.serviceWorker.addEventListener('error')` 会**无差别注销所有 SW + 清空所有缓存**（一次 SW 异常核爆 PWA）。
- 同一失败会同时触发 index.html link-error（forceUpdate）与 vite:preloadError（forceCleanAndReload）两条恢复通道，互相 race。
- `.profile-tab.profile-home-active` 的 padding-top 被 `shell-community.css:2862`（特异性 0,4,0）刻意覆盖成 10px —— 写死「84px」判据会假红，探针改用差分。

### 修复建议（按优先级，均未实施，待用户确认）
- **P0-1** `src/main.js`：`vite:preloadError` 监听无论冷却与否都 `preventDefault()`（冷却只限刷新频率，不该让错误上抛把路由 import 炸掉）→ 治场景 B「导航被吞」。
- **P0-2** `async-loaders.js` `preloadProfileStyles`：失败后有限退避重试（3 次，绕过 `i[url]` 去重，手动建 link）+ switchTab('posts') 时等样式就绪再亮页 → 治场景 A「半样式常驻」。
- **P1** index.html link-error 监听改为只标记不导航，统一走 forceCleanAndReload 单通道；SW error 核爆改为阈值制。
- **P2** 半样式可观测：挂载后抽查关键样式，持续缺失给提示条（带重载）。
