## 核验：竖屏发帖 FAB 的挂载范围（用户问「官方 tab 除外，修好了么」）

**结论：是，已符合「只挂在内容流」的口径** —— 而且是双保险（结构 + 显隐计算式）。

结构事实（读码）：分区壳 `ForumSectionShell` 只在 4 个 feed 分区渲染 `<AsyncForum :embedded="true">`；
官方 tab 走 `#official` slot → `AsyncOfficialHeroStage`（独立面板）⇒ **ForumMain 根本不挂载，FAB 无从存在**
（FAB 是 ForumMain 模板里 `<Teleport to="body">` 的 `.mobile-compose-fab`）。
第二道闸在 `isForumComposerFabVisible`：`route.path !== '/' → false`，再 `view === '' || isForumFeedSection(view)`
（`isForumFeedSection` 只认 latest/following/news/activity；`resolveForumSection` 默认落点是 latest 不是 official）。

浏览器实测（390×844 竖屏 + 伪造登录注 pinia，`/tmp/boh-fab-scope-probe.mjs`，**10/10 PASS**，pageerror 0；
每个用例都带「页面已就绪」锚点做正向对照，锚点不就绪记 INVALID 而不是假绿）：

| 用例 | ForumMain | `.mobile-compose-fab` |
| --- | --- | --- |
| 首页默认 · `?view=latest` · `?view=news` | 挂载 | **1 个**、可见、带 `embedded-compose-fab` |
| `?view=official` · `?view=members` | **未挂载**（走 `#official` slot / 独立面板） | 0 个 |
| 我 · 方块 tab · 默认落点 | **挂载（v-show 常驻）** | **0 个** |
| 消息 · 我 posts tab | **挂载（v-show 常驻）** | **0 个** |
| AI（全屏落点） | 未挂载 | 0 个 |

**⚠️ 本轮最值钱的发现（别再踩）**：UserSpace 分区壳是 **v-show 常驻**，所以「消息 / 我」这些 tab 下
**ForumMain 仍然 mounted**（`.forum-page` 在 DOM 里）。也就是说：挡住 FAB 的**不是**「ForumMain 没挂载」，
而是显隐计算式里那道 `route.path !== '/' → false`。老代码正是靠 `/user-space` 特例 + App 级 GlobalComposeFab
来处理这段，现在收成一条路径判断 —— **将来谁把这道判断放开，就会出现「消息页钻出第二个 + 号」**。
（我第一版探针把 `expectForum:false` 当硬断言，于是这两条报 FAIL；实际是期望写错，不是实现错 ——
写探针时「挂载」与「可见/显隐」是两件事，别混成一个断言。）

## 修：头像框不跨设备同步（根因 = 同步时机只挂在「我的」页）

线上取证（Management API）先排除了「写库坏」：`authenticated` 对 `profiles.avatar_frame_url` 有 SELECT+UPDATE，
29 人空、4 人非空 ⇒ 写库链路是通的。真因是**读的时机**：

- `syncAvatarFrameFromServer()` 全仓**只有 1 个调用点**：`UserSpaceMain.vue` onMounted。
  新设备登录后不进「我的」页 ⇒ 永远不拉服务端佩戴态 ⇒ `equippedId` 保持 localStorage 的 `none`
  （他人视角读服务端 url，所以「只有自己看不到」）。
- 二级缺陷（会把症状放大成「戴着的框自己消失」）：反查用 `frame?.id || 'none'`，
  反查不到就**回落 none 并覆盖本机**。而内置清单里没有运营新增框（`frame-muh01jp3`），
  也缺被改过 url 的老框（`white-cat` 的 url 已被运营改成 Cloudinary 绝对地址）⇒ 清单没到位时必然误判。
- 三级：登出不清 `boh-avatar-frame-id` ⇒ 换号后上一个账号的框被继承、甚至被上库到新账号。

改动（3 改 2 增）：
- `src/composables/useAvatarFrame.js` —— `loadAvatarFrameData` 改 **single-flight**（旧写法 loading 时返回字符串
  `'loading'`，await 到的是状态不是结果，等于没等）；新增 `isFrameListAuthoritative()`（必须含 DB 行才允许反查）、
  `findFrameByUrl()`（去 `?v=` 全等 → 文件名兜底）、`persistFrameToServer` 失败写 `boh-avatar-frame-pending`、
  `resetAvatarFrameLocal()`、`initAvatarFrameSync()`（订阅 `SIGNED_IN`/`USER_UPDATED`/`INITIAL_SESSION`，
  **回调里 setTimeout 0 挪出栈**——supabase-js 禁止在回调里 await 其它 auth 调用）；sync 并发去重。
  新增两个本机 key：`boh-avatar-frame-owner`（换号保护）、`boh-avatar-frame-pending`（写库失败补写）。
- `src/main.js` —— `.then((m) => m.loadAvatarFrameData().then(() => m.initAvatarFrameSync()))`，同步时机单源。
- `src/views/user-center/UserSpace/UserSpaceMain.vue` —— 移除 `syncAvatarFrameFromServer` 调用与 import（避免时机依赖长回来）。
- `tests/unit/avatar-frame-sync.test.js`（15）、`scripts/probes/probe-avatar-frame-sync.mjs`（12）。
