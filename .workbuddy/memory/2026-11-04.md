## plans/038 · 搜索框与 BOH AI 合并成一颗岛（方案 + 原型，未动线上代码）

产出 `plans/038-nav-ask-merge.md` + `docs/demos/nav-ask-demo.html`（单文件原型，Playwright 实测通过）。

**方案核心**：一颗 Teleport 在 body 的独立悬浮岛（不属于导航栏），四形态：胶囊 148×40 → 输入 344×212 →
列表 352×293 → 回答 352×自适应；输入条钉在岛顶 ⇒ 四形态间 `top` 恒 68px（唯一硬视觉契约）。
动画：宽度 380ms 回弹曲线、高度 460ms 且晚 20ms 起步（先变宽再长高）。
搜索与问答共用：结果列表第 0 项恒为「问 BOHAI：<原句>」，意图只决定默认高亮不决定是否发问，
Enter 执行高亮项、⌘↵ 强制问 AI。岛内只留六件事（模型/工具/用量/会话管理全回全页）。

**用户拍板（已冻结）**：① 唤起 = 抓住导航栏向下拉、直接进对话（不是屏幕顶边 —— 那才是系统手势区；
导航栏本体是页面内手势，配 `overscroll-behavior:none` + `touch-action:none` 即可）；
② 回答态高度随字数自动扩展、有上限（短答案岛就矮）；右边缘滑动退场。
待拍板：材质（深色岛 vs 玻璃岛）、落位（居中 vs 右下角）。

**关键教训**：
- 🔴 第一版做成了「导航栏撑高的下拉面板」，用户一眼看穿「这不是岛」—— 岛的定义是**独立悬浮 + 自身形变**，
  面板是导航栏的延长。改 UI 前先对齐「它是什么」，不然尺寸调得再细都是错的。
- 🔴 问句判据词表漏了「什么时候」⇒ 「八周年的活动什么时候开始」被判成普通搜索。词表要当产品数据维护，
  不是一次性正则。
- 桌面岛**不能拉满**（一行字横跨 1000px），内容限宽 480/560 居中。
- 唤起架构硬约束：岛的壳同步渲染、结果/回答懒加载 —— 现有 `BOHAIIsland` 等 `BOHAIMain` 加载完才聚焦
  （最长 5s），键盘晚弹一步，这是「打字不顺」的根因之一，不是手势问题。
- Playwright 量 DOM 的脚本放 /tmp 会找不到仓库依赖：用 `createRequire('<仓库>/package.json')` 引 playwright。
