## 暗色竖屏二级菜单「白块」（用户：「暗色模式导航栏子菜单有白块」→「竖屏端」）

### 复现（390×844 + boh-theme=dark）
`.nav-nobile-submenu-container.active` 计算值 `background-color: rgba(255,255,255,0.85)`、
盒子 352×451 —— 一整块白板盖在深色菜单上，白字全糊。
（亮色模式同样存在，白对白看不见，所以一直没被发现。）

### 根因
vendor `unified-nav.css` 的 `.unified-nav .nav-mobile-submenu-container { background-color: rgba(255,255,255,.85) !important }`
是「菜单卡里再叠一张卡」年代的写法。岛化时我们在 scoped 竖屏块里写了
`#unified-nav-container .nav-mobile-submenu-container { background-color: transparent }`
—— **特异性够了（1,1,0 > 0,2,0），但对面有 !important ⇒ 永远输**。
「材质统一交给 surface」这件事只做了一半。

### 修法
1. 摘掉 vendor 那条的 `!important`（值保留）。scoped 的 transparent 随即生效（亮/暗都成立）。
   `check:important-budget` 是按文件棘轮 ⇒ 少一处永远合法；顺手把
   `scripts/important-budget.json` 里 unified-nav.css 145→144、style.scoped.css 50→49、total 608→606。
   ⚠️ 不要用 `--update` 重写整份基线 —— 会把并行会话文件的基线上抬，等于替别人抹掉增量。
2. 模板：`nav-mobile-submenu-container` 的 `active` 从 `expandedMenu` 改成
   `expandedMenu && isMobileMenuOpen`。桌面开下拉时它本来也会 active（桌面的下拉也写 expandedMenu），
   于是这块白板在桌面也一直存在（被上层 `.nav-submenu` 的 #1b2430 盖住）；加这道闸后桌面彻底不渲染它。

### 护栏
`probe-nav-mobile-menu` 新增 O5：`.nav-mobile-submenu-container` 的 background alpha 必须 < 0.15
（反证：把 !important 加回去 → alpha 0.85 → 立刻红）。现 53/53。
其余：mini-bar 38/38、nav-dark ALL PASS、type-check 绿、eslint 绿、important 预算 606/606。
⚠️ verify:fast 这次唯一红是**并行会话**的未跟踪文件（`src/utils/auth-storage.js`、
`src/utils/login-redirect.js` 被 router/Login 引用但没 git add），与本轮无关，别去替它 add。

## 09:30 在 Cloudflare 控制台落地缓存规则（我实际操作，非用户手动）

用 WorkBuddy 浏览器扩展接管用户已登录的 Chrome（zone `blockofhome.cn`，Free）。

已落地 4 项（均在 Cache Rules / Speed 页面，截图逐条核对）：

1. `starts_with(http.request.uri.path, "/static/")` → Edge 1 年 + Browser 1 年；
2. `/`、`/index.html`、`/404.html`、`/boot.js`、`/sw.js`、`/push-sw.js`、`/version.json`、
   `/manifest.webmanifest` → Edge 1 分钟 + Browser 绕过缓存；
3. Early Hints（原为关）→ 开；
4. Tiered Cache（原为关）→ 开（Smart Tiered Cache）。

### 🔴 控制台操作的坑（下次直接照做）

- **时长选择器是「选择或添加」combobox**：预设只到 14 天/半年。要 1 年必须键入 `31536000`
  **后从下拉里点选生成的「1 年」项**。直接键入就点别处 / 按 Esc，值会被**静默清空**且界面
  不报错 —— 直到点「部署」时才报「TTL 必填」。这一步返工了两次。
- 表单页滚动到一定位置会整屏空白（懒渲染），DOM 只能看到视口内的少数节点；
  用 `-800` 左右的小步往返回滚比大步 `+2500` 可靠得多。
- 部署按钮在页面最底部「位置位置 → 最后一个」下面，校验通过后会显示「规则验证通过」。

### 实测（Slow 4G 1.6Mbps / RTT 150ms / 禁 SW）

```
TTFB  721–772 → 646 ms
FCP   2044–2604 → 2060 ms
LCP   5664–7572 → 5716 ms
/static/  max-age=31536000 + cf-cache-status: HIT
首页      cf-cache-status: HIT（age 14/17/20，60s 一轮），浏览器侧 no-store
```

**结论要如实说**：1 年缓存的价值在**回访**（不再每 4h 回源、不再重下），首访 LCP 只小降。
首访瓶颈仍是入口链路本身（CSS 到 5.3s、入口 JS 到 5.9s 才下完），缓存命中救不了
「1.6Mbps 串行下 239KB」。

### 更正一条旧判断

「线上只发 gzip」是**方法错误**：我用 `Accept-Encoding: br, gzip` 测到 gzip 就下了结论。
实测单发 `Accept-Encoding: br` → `content-encoding: br`。CF 为同一资源存 br + gzip 两个变体，
按请求头协商。**此项无需任何操作**。

### 注意

- 「Browser TTL 绕过」会让 CF 在 HTML 响应上追加 `no-store`，但**不影响边缘缓存**
  （cf-cache-status 仍 HIT）。浏览器每导航一次重取一次 HTML，这是刻意换新鲜度的代价。
- `icons/`（含 LCP 元素 icon-512-transparent.png）**没**纳入长缓存：文件名不带内容 hash，
  硬上 1 年会让换 logo 长期不更新。要快应在构建期给图标名加 hash，而不是硬上长缓存。
- 未做整站 purge：`/static/` 全是不可变 hash 文件，过期后自然换新 TTL，强 purge 只会
  让所有人同时冷启动。
