## 登录/退出登录优化盘点（只分析，未动主体）

按用户提问做了一轮登录/退出全链路审查，结论按优先级记在这里，后续要动时不用重新挖：

**退出登录的真缺陷（未修）**
1. `utils/api/auth-api.js` 的 `signOut()` 只在 `!error` 时 `clearSensitiveLocalStorage()`；而 supabase-js 内部 `_signOut` 在请求失败分支**也会** `removeCurrentSession()`
   ⇒ 会话已删、PII（`boh_remember_email` / `username` / Cloud+ 共享相册令牌）还在 localStorage。修法：清理移进 `finally`。
2. `supabase.auth.signOut()` 默认 `{ scope: 'global' }`（GoTrueClient.js:3409）⇒ 一次退出全端下线，但账户安全面板没有「退出所有设备」，口径对用户不可见。
3. 退出无进度反馈，最坏 ~18s 空窗（解绑推送 ≤3s + signOut 写超时 15s）；reload 还会重播首页开场 gate。
4. 跨标签页：BroadcastChannel 会推 `SIGNED_OUT`，store 只 `updateLocalState(null)`，另一标签页面内容仍是旧用户。
5. 退出 = 整页 reload（实测 192ms + 白屏）。可改软重置（复用 App.vue 的 `boundaryKey` 重挂页面树）。

**登录**
6. 「记住我」名不副实：`persistSession` 恒 true + localStorage（`supabase-client.js:85-89`），取消勾选不会在关浏览器后登出；唯一效果是回填 `loginId`，而 `boh_remember_email` 又在登出清理名单里 ⇒ 正常退出后勾了也不回填。
7. 登录主路径无超时：`functions.invoke` 走 `SUPABASE_FUNCTION_TIMEOUT_MS=180000`，`withTimeout` 只用在 syncAuthState ⇒ 网络半死时按钮可卡 3 分钟。
8. 登录成功不回跳原目标（路由守卫只 `showLoginModal=true` + `next(false)`）。
9. 登录页 modal/page 两套模板逐行重复且已漂移（modal 有「注册 BOH ID」，page 没有）。

### 三条症状不是一个原因（实测）

| 场景 | 根节点出现 | 内容可见 | 数据请求 |
| --- | --- | --- | --- |
| 内容 → 我（首次） | 29ms | **3.4s** | **31** |
| 我 → 图库（首次） | 587–1006ms | — | 1–2 |
| 图库 → 周边（首次） | 597ms | 831ms | 1 |
| 各席回访 | 13–14ms | 13–14ms | 0–2 |

- **「整页重挂载」是错觉**：`probe-cloud-keepalive` 八组全绿 —— 五席来回切都复用同一实例、
  回访 0 数据请求。看到的「重挂载」是①首访数据加载（我 = 31 条）②KeepAlive 把 DOM 移回
  文档时入场动画整批重播（每次切换 33–44 个动画 `currentTime < 80ms`），且重播的主要是
  **骨架 shimmer**（`profile-forum-skeleton` / `cp-suspense-*` / `storePulse`）—— 那是加载态，不能压。
- **「切到图库卡一下」= chunk 现下现用**：点击后 0.6–1s 屏幕上零变化。
- **「我」首访 3.4s = 数据层**：31 条里约一半是重复查询（`user_follows` 计数 ×6、
  `posts id` ×4、`profiles points` ×3、`get_my_user_space_summary` ×2）。根因是「我的」在
  `UserSpaceMain.fetchUserStats` 手写了一套统计，「他人」走 `profile-api.getFollowCounts`
  （有 executeRead 缓存）——**同一页两套并行**。

### 两条踩到的坑（已写进代码注释）

- 🔴 **空闲批量预取在慢网下会拖慢当前页**：Slow 4G 下与「我」页 31 条请求抢带宽，
  「我 → 图库」反而 587ms → **947ms**。改成 `downlink >= 4 && effectiveType === '4g'` 才批量预取。
- 🔴 **预取队列不能串行 await**：上一席下载完再下一席会让首页大 chunk（3–4s）把后面全堵住。
  改成按时间铺开（每 350ms 一席）。
