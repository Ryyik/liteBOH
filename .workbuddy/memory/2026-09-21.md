→ 相对安全的一条是 `revoke insert,update,delete on all tables in schema public from anon`：写操作（点赞/发帖/抽奖/上报/装扮购买）全部需要登录，anon 无合法写路径。

**关键决策：撤权而非直接 drop** —— 对调用方效果**完全相同**（旧路径一律失败），但 `revoke` 可**一条 grant 秒级回滚**，`drop` 需重建函数体（含 IP 限流逻辑）＝高成本高错误率。所以顺序是 **撤权 → 观察 → 后续迁移 drop**。

**为什么必须撤 `authenticated`**（不只是 anon）：否则**已登录用户**可以枚举任意用户邮箱，对攻击者更便利。`public` 必须一起撤（内建 EXECUTE，只撤 anon 无效）；`service_role` **保留**。
