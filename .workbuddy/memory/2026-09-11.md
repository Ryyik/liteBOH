### Bug 1 首页下滑空白 + 卡顿 —— 根因是 WebKit bug
- **根因**：`.home-hero-row` 上的 `content-visibility: auto` 触发 **WebKit bug 321501**（2026-08 提交未修）：真实触摸滚动的子树 reveal 后保持"过期零高度布局"，整行空白且不自愈；**程序化 scrollTo 不复现**（探针全绿的真凶），配套 318216 = Safari 反复重排卡顿。GitLab 同款受害。
- **修复**：全站移除 `content-visibility: auto`（4 处：HomeHeroRow / Forum feed.css `.post-card-v2` / Profile `.public-profile-post-card` / Messages `.x-item`），各留一行注释说明原因防回加。
- **顺带简化**：HomeHeroRow 的 is-deferred 占位 + IO + 空闲预热机制整段移除，改为直接渲染全部行。理由：占位高度是估计值（实测页高 6097→6402→6277 漂移），既造成首滚跳变又叠加空白窗；7 行静态 DOM 构建只花几 ms。--[data-intrinsic] 行高镜像表随之删除（少一个"改 hero 高度须同步"的维护点）。
- 教训：**诊断"真机才复现"的渲染 bug，先怀疑 content-visibility/滚动相关 CSS**，探针测不出是因为 programmatic scroll 走了 updateLayout 特殊路径（bug 报告原话：measuring makes it disappear）。

### Bug 2 论坛官方卡详情只显摘要

### Bug 3 多图帖只能翻到第 4 张
- **根因链**：`list_forum_posts` RPC 的 images jsonb SQL `limit 4`（2026060504 四图预览迁移）→ ForumMain `prepareForumPostForDisplay` 又 slice(0,4) → `openForumImageViewer` 只拿截断数组 → 大图上限 4。角标 `+imageCount-1` 是"单封面图时代"的旧口径，4 宫格时代语义就错了（6 张应显示 +2 而非 +5；image_count=0 的旧帖回退 4-1=+3 即用户看到的"加3"）。
- **修复**：
  - prepare 保留全量 `allImages`（不截断）+ 新增 `hiddenImageCount = imageCount - 网格可见数`；
  - `openForumImageViewer` 用 allImages 打开；`imageCount > 已有数` 时异步 `getForumPostImages(postId)` 补全量，按 originalUrl 对齐保持当前图不动，回填卡片统计并 triggerRef；
  - PostCard 角标改 `v-if="post.hiddenImageCount > 0"` 显示 `+{{hiddenImageCount}}`（全部可见不显示）；
  - ForumImageViewer 加 `watch(props.images)`：补全列表替换时按原图 URL 重映射 currentIndex；
  - updateOptimisticPost 同步 allImages/imageCount/hiddenImageCount 等新字段。
- 注意 `posts.image_count` 由 update_forum_post_images RPC（2026082801）维护，老帖可能为 0——打开大图的补全逻辑不依赖它（唯一可信的全量源是 forum_post_images 表）。

- **根因**：`2026091106` 给 profiles 加 `avatar_frame_url` 列，但 `2026090803` ④ 把 profiles 的 update 收敛为「authenticated 列级白名单 26 列」、select 收敛为「anon 列级白名单」，**新列漏加权限**。equip → persistFrameToServer 用 `.from('profiles').update({avatar_frame_url})` 被列级 privilege 拒绝；该函数仅 `logger.warn` 静默吞错 → profiles.avatar_frame_url 永远为空 → 自己读 localStorage 可见、他人读服务端不可见。
- **修复**：新增迁移 `2026091107_avatar_frame_url_grant.sql`：`grant update(avatar_frame_url) to authenticated`（佩戴上库可落库）+ `grant select(avatar_frame_url) to anon`（游客也能看到、防游客列表 400/500）。db push --dry-run 干净 → --yes 已上线；`has_column_privilege` 只读验证 authed_update=true / anon_select=true。
- **用户侧自愈**：已戴框用户 profiles 仍空，权限修好后进入 UserSpace（onMounted 触发 syncAvatarFrameFromServer：库空本地有→上库）或重新点一次佩戴即可让他人可见；无需重戴。
- **教训**：加 profiles 列必须同步补列级权限白名单（update 给 authenticated / select 给 anon），否则 equip 静默失败无感知。建议 persistFrameToServer 失败改可见报错/toast，避免下次再踩。
