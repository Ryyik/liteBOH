## 数据管理面板：侧栏搜索能按「功能名」找入口（用户报障）

用户原话：「数据管理面板还是不能通过搜索来查找功能，感觉很不方便」。

### 真因（三条搜索路径没有一条能落到「功能」上）

1. 侧栏「筛选模块…」只按 `tabModules` 的 label/description 过滤 **10 个模块**
   ⇒ 搜「积分发放」「补发」「头像框」一律「无匹配模块」。而这是屏幕上最像搜索框的框，
   用户必然先试它 —— 这就是「还是不能」的直接来源。
2. 工具栏搜索框搜的是**记录**，功能名只挂在「全部表」范围下顺带出现。
3. ⌘K 自己写了一段 `for (const tab of tabs)` 匹配，**最多 3 条**、走不到独立控制台页
   （商城装修 / 资讯编辑 / 开屏管理 / 头像框），也不认别名。
   且 `切换到：模块` 那批命令按 label 过滤 ⇒ 搜功能名同样命不中。

### 改法（单一真源 + 两个入口共用）

- 新增 `src/views/DataManagement/config/function-index.js`：
  `buildAdminFunctionIndex({ role })` 把「模块 / 每个模块 tabIds 里的页签 / subNav 系统子页」
  收成一份索引，带 `denied`（与侧栏同口径：置灰可审计，不凭空消失）；
  `TAB_ALIASES` / `MODULE_ALIASES` 放「用户嘴里的叫法」（补发→积分发放、banner→广告管理、
  头像→头像框）；`searchAdminFunctions()` 打分排序（**功能 +5，排在模块前**；多词按 AND）。
  ⚠️ 只认 `tabIds` 里登过的页签：`api-keys` / `freemodels` 是「已并入密钥与模型」的过渡条目，
  列进搜索结果只会把人带到过渡页（单测锁住这条）。
- `AdminSidebar.vue`：新增 `functions` prop + 「功能」分组（模块组里已有的不再重复出现）、
  每条右侧标所属模块、↑↓ + ↵ 键盘操作、状态行「找到 N 个功能 · M 个模块」。
  跳转后清关键词（否则侧栏停在过滤态，刚打开的页看不到高亮）。
- `DataAdmin.vue`：`adminFunctions` computed + `handleFunctionClick`（按 kind 分派到
  既有的三条导航路径，不另造第四条）；⌘K 的派生候选改成吃同一份索引（上限 3 → 6），
  且关键词非空时屏蔽 `切换到：X` 批命令（避免同一个目标出现两次）。
- `AdminConsoleShell.vue`（四个独立控制台页的壳）：同一份 functions，落点用 URL 表达
  （`?section=data&tab=<id>`，`resolveInitialAdminTab` 认显式 tab）。

### 自证

### 真正的 bug（不是审美）

1. **深链 `?tab=X` 不同步 activeModule**：`/admin/data-management?section=data&tab=lotteries`
   顶栏标题写「用户管理」、侧栏高亮「用户」、模块 tab 全是用户子表，内容却是抽奖看板。
   根因在 `useDataAdminNavigation.syncModuleFromSection`：`data` 段只做「已选模块就保留，否则回 users」。
   **改成「当前表才是唯一真源」**（由 tab 反查 module）。
2. **分布条标签说谎**：写死「状态分布」，但 users/points 分的是 `role`、news/products 是 `category`、
   pointsTransactions 是 `reason`。改成按字段 label 取「角色分布 / 分类分布…」。
3. **中文界面出现 `false`**：移动端卡片直接复用 `formatCellValue`，布尔列渲染成 `false`。
4. **计费文案不通**：积分发放摘要 `给 {{ mode==='all' ? '全部' : N }} 位用户` → 「给 全部 位用户」。

### 各区针对性改动

- **顶栏**：去掉英文 eyebrow（Users / Lottery…）与重复的「新增记录」按钮（工具栏已有同一颗，条件完全一致）。
- **模块 tab 条**：`margin-bottom 15px → 0`（自己已有 border-bottom 当分隔线）、行高 42 → 33。
- **工具栏**：分布 chips 从 `width:100% + order:5` 的独占行改成同行内联 + 横向滚动
  （`flex:1 1 0` + `min-width:0`，chip 必须 `flex:0 0 auto`，否则被压成两行反而更高）；
  搜索框 `280px` 固定宽、placeholder 缩短；筛选按钮加生效条件计数 + `aria-expanded`。
- **列默认集**：新增 `defaultVisible:false` 约定，`visibleCurrentColumns` 在**没有本地列配置**时
  按它过滤（列配置面板仍能看到/勾回，「恢复默认」回到这套精选集）。ID 列 30 处全隐藏；
  users 再隐收件人/联系电话/收货地址/禁言；points 隐角色/封禁/禁言；products 隐可购/排序；
  subscriptions 隐方案代码。
- **行内操作**：非审核/非抽奖页的主操作（封禁/解封…）改「安静实心字」，悬停才出底色 ——
  原来一屏 20 颗红胶囊。布尔 badge 为假时渲染「—」且不套灰胶囊。

  跳过本条为空（「—」）的列；布尔/日期按类型格式化；主操作同样安静化。

## 需求文档 v2：确认单人维护，主轴改为「以人为轴」

站长确认：使用者只有他本人，日常维护对象 = 用户 / 商品 / 积分 / 礼物 / 订单 /

两个**代码事实**（不是推断）支撑了这次改版：

D1 改为④以人为轴；D2 **定案只保留 admin，删 moderator 死代码**（单人使用，
安全目标从「权限分配」转向「防误触 + 可回滚 + 留痕」）；新增 D11（登录诊断做到
