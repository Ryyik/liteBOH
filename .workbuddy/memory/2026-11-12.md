## 数据管理面板：侧栏搜索能按「功能名」找入口（用户报障）

用户原话：「数据管理面板还是不能通过搜索来查找功能，感觉很不方便」。

### 真因（三条搜索路径没有一条能落到「功能」上）

1. 侧栏「筛选模块…」只按 `tabModules` 的 label/description 过滤 **10 个模块**
   ⇒ 搜「积分发放」「补发」「头像框」一律「无匹配模块」。而这是屏幕上最像搜索框的框，
   用户必然先试它 —— 这就是「还是不能」的直接来源。
2. 工具栏搜索框搜的是**记录**，功能名只挂在「全部表」范围下顺带出现。
3. ⌘K 自己写了一段 `for (const tab of tabs)` 匹配，**最多 3 条**、走不到独立控制台页
   （商城装修 / 资讯编辑 / 开屏管理 / 头像框），也不认别名。
   且 `切换到：模块` 那批命令按 label 过滤 ⇒ 搜功能名同样命不中。

### 改法（单一真源 + 两个入口共用）

- 新增 `src/views/DataManagement/config/function-index.js`：
  `buildAdminFunctionIndex({ role })` 把「模块 / 每个模块 tabIds 里的页签 / subNav 系统子页」
  收成一份索引，带 `denied`（与侧栏同口径：置灰可审计，不凭空消失）；
  `TAB_ALIASES` / `MODULE_ALIASES` 放「用户嘴里的叫法」（补发→积分发放、banner→广告管理、
  头像→头像框）；`searchAdminFunctions()` 打分排序（**功能 +5，排在模块前**；多词按 AND）。
  ⚠️ 只认 `tabIds` 里登过的页签：`api-keys` / `freemodels` 是「已并入密钥与模型」的过渡条目，
  列进搜索结果只会把人带到过渡页（单测锁住这条）。
- `AdminSidebar.vue`：新增 `functions` prop + 「功能」分组（模块组里已有的不再重复出现）、
  每条右侧标所属模块、↑↓ + ↵ 键盘操作、状态行「找到 N 个功能 · M 个模块」。
  跳转后清关键词（否则侧栏停在过滤态，刚打开的页看不到高亮）。
- `DataAdmin.vue`：`adminFunctions` computed + `handleFunctionClick`（按 kind 分派到
  既有的三条导航路径，不另造第四条）；⌘K 的派生候选改成吃同一份索引（上限 3 → 6），
  且关键词非空时屏蔽 `切换到：X` 批命令（避免同一个目标出现两次）。
- `AdminConsoleShell.vue`（四个独立控制台页的壳）：同一份 functions，落点用 URL 表达
  （`?section=data&tab=<id>`，`resolveInitialAdminTab` 认显式 tab）。

### 自证

  `TAB_ALIASES` 防死词）、AND 语义、排序三档、版主权限继承。

  「模块」组各出现一次（搜「积分」看到两个「用户」）⇒ 加了去重，并补 C2 断言。
- `npm run verify:fast` 绿；`vue-tsc` 绿；改动文件 eslint 零新增（存量 16 条 warning 未动）。

### 踩到的坑

- 探针脚本必须放仓库内跑（`node /tmp/x.mjs` 解析不到 `playwright`，ESM 不吃 NODE_PATH）；
  临时脚本放 `scripts/probes/_tmp-*.mjs`（未跟踪，doc-truth 按 HEAD 计数）跑完即删。
- `check:untracked-imports` 是「漏交防线」：新文件必须先 `git add` 才绿，
  否则报「推送后 CI 构建必红」。
- `check:doc-truth` 的 AGENTS.md 字节预算只剩 56B 富余（49048 基线 / 48992 实测），
  所以本次**没有**往 AGENTS.md 的「改动→门禁」表加行，改登记到 `docs/PROBES.md`。

## 极简骨架的第一个真模块 `/admin/users-minimal`（同日，用户「可以」后落地）

### 量化基线（1440×900，改动前的 users 页签，可复现）

| 指标 | 旧面板 | 新骨架 |
| --- | --- | --- |
| 第一行数据 top | 275px（占屏 31%） | 100px（11%） |
| 首屏可交互元素 | 219 | 22 |
| 首屏文案段数 | 48 | — |
| 列数 | 11 | 4（+点/箭头 = 6 网格列） |
| 390×844 第一行 | 看不到数据（工具栏 165 + 状态条 48） | 87px |

量法：Playwright 数 `button,input,select,textarea,a[href]` 的可见项 + `.g-topbar/.g-module-tabs/.toolbar-secondary/.collection-overview` 各层高度。

### 结构

- `src/views/AdminUsersMinimal/index.vue`：**一屏一个决定轴**（模块/搜索/条数同一行）+ 4 列 + 编辑面板
  （横屏右侧、竖屏底部，同一份 DOM 靠 `@media (max-width:720px)` 折叠）。
- `src/utils/api/data-admin-profile-api.js` 新增 `fetchAdminProfiles` / `PROFILE_LIST_COLUMNS` /
  `sanitizeProfileKeyword`。写路径**复用**既有双通道（`splitProfileWritePayload` →
  `adminUpdateUserProfile` + `updateProfileRow`），没有另造第四条。
- 路由 `/admin/users-minimal`（`requiresAdmin`）。⚠️ 路径刻意不带 `-console`：
  `admin-console-wiring.test.js` 会把所有 `/admin/*-console` 强制要求登记进 tabModules。
- 未接的三个模块（积分/商品/帖子）带「旧」角标，点了落回旧面板 —— 不是死按钮。

### 踩到的坑

- `grep` shim 再次咬人：`grep -rn "a\|b" src/` 静默返回空，差点误判「`adminUpdateUserProfile` 没人用」。
  **交互式检索一律用 Grep 工具**（这条 MEMORY.md 里已有，本次又踩一次）。
- 竖屏抽屉别写死高度：82% 时「备注」与动作条之间空 200px，改成 `height:auto + max-height:86%`。
- `.um-shell` 从 980 收到 860：再宽，名字列与角色列之间会出一条 400px 空白真空 ——
  「元素少」不等于「留白多」。
- `check:doc-truth` 的数字按 **HEAD** 算，所以「新增文件 + 改 AGENTS 数字」必须同一次提交，
  否则本地必红（已按此拆成两条 commit：653/294/232/350 → 654/295/233/351）。

### 入口与静态预览（同日续）

- 旧面板 users 页签的 `⋯` 菜单加了「极简视图（实验）」→ `/admin/users-minimal`。
  **只在 `currentTab === 'users'` 时出现**：那一页只接了 users，放进别的 tab 会变成骗人的入口。
- `docs/preview-users-minimal.html`：给「不登录也能看」用的静态镜像（mock 12 行 + 可点编辑 + 横/竖切换）。
  ⚠️ 两处**必须与 SFC 不同**，否则预览会错：
  ① 宽度切换靠 `@container`（真页是 `@media`，容器宽度变了 media 不触发）；
  ② 遮罩/抽屉/toast 必须放在 `.frame` **内部**并改 `position:absolute` ——
     container query 只命中容器后代，`position:fixed` 的 body 级浮层永远拿不到窄屏规则
     （首版就是「竖屏下编辑面板铺满浏览器」的真错，截图才看出来）。
