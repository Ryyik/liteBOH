## 修掉一个既有 bug：FramedAvatar 的 scale 从未生效

- `FramedAvatar.vue` 的 prop 叫 `scale`，但 4 处调用（`AvatarFrameGrid` ×3、`AssetsHubPanel` ×1）
  传的都是 `:frame-scale` → Vue 不匹配 props，变量根本没写进 style。

- 教训：**跨组件传 prop 后要断言"值真落到布局"**，只断言"变量存在"抓不到这类静默失效。
  现在探针会量框层实际宽度（52×2.08 = 108.16px ±2.5）。

# 横屏左栏（UserSpaceSideRail）指示器几何修复 + 优化方案

参考小红书 PC 侧栏，实测 `/user-space` 横屏左栏（`.userspace-rail`）。三档：隐藏 / 88px 窄栏
（landscape+≥1024+≥600）/ 240px 宽栏（+≥1280）。实测视口 1440×900、1100×900、1024×600。

## 修掉的（一行，已反证）

`.userspace-rail-group` 是 `position: static` → 滑动胶囊指示器的 `left/right:0` 包含块上溯到
`.userspace-rail`（absolute）的 padding box，而不是 group：

| 视口 | dTop 首屏 | dLeft | dWidth |
|---|---|---|---|
| 1440×900 | −56 → 0 | −12 → 0 | +24 → 0 |
| 1100×900 | −56 → 0 | −10 → 0 | +20 → 0 |
| 1024×600 | −56 → 0 | −10 → 0 | +20 → 0 |

- **dLeft/dWidth 恒定错**（与时机无关）：指示器 239×47 vs 条目 215×47 @left12。
- **dTop 只在首屏错、切一次 tab 自愈**：挂载时读到的是 `--userspace-rail-top-h` 更新前的
  offsetTop（96，随后导航状态卡片出现 → 138 → padding 152），而 RO 只观察 group
  （尺寸未变）→ 不重算。
- 修法：`side-rail.css` 的 `.userspace-rail-group` 加 `position: relative`。一行同时修两个
  —— 指示器成为 group 子元素后，随 group 被 padding 推下而同步下移。
- 反证：`git stash push -- side-rail.css` → 三档全部复现（−56/−12/+24 与 −56/−10/+20），
  `stash pop` 后归零。
- 验证：`vite build` 通过；`probe-user-space-ia.mjs` 撤前/撤后同为 **78 PASS / 1 FAIL**，
  唯一 FAIL（点「发布」打开发布会话）是**既有问题**（与本次改动无关）。

## 未改、待拍板的建议（plans/010-landscape-rail-optimization.md）

# App 化路线咨询（只出方案，未动代码）

用户问「网站如何开发成 APP + 最低成本」。探查结论（下次别重查）：

- **PWA 骨架已全**：`vite-plugin-pwa`（vite.config.js:121，`generateSW` + `injectRegister:false`）→ dist 出
  `sw.js` / `manifest.webmanifest` / `workbox-*.js`；`main.js:63` 注册（`updateViaCache:'none'`）+ `updatefound`
  → `PWAUpdateToast`；manifest 已是 `display:standalone`、`start_url:'./'`。
- **hash 路由是最大红利**：TWA / Capacitor / 静态托管都不需要服务端 rewrite 或 navigateFallback 兜底。
- 安装入口已存在但很糙：`UnifiedNavbar/index.vue:813 createDesktopShortcut()` 用 `alert()` 引导，
  iOS 分支只有一句文案。→ 应改成自绘引导浮层。
- manifest 待补（`vite.config.js:193-211`）：`lang:'en'` 应为 zh-CN；icons 复用 1024 的 favicon.png
  声明 192/512 且 purpose `any maskable`（maskable 会被系统裁圆，需确认 logo 安全区）；
  缺 `id` / `categories` / `screenshots` / `shortcuts` / `orientation`。
- iOS 待补（`index.html:35-58`）：只有 180 apple-touch-icon，缺启动图 → 冷启动白屏。

**成本分水岭在支付**：走 PWA / TWA（不加原生壳）→ 现有 Supabase 订阅 + Web 支付完全不动；
一旦上 iOS 原生壳（Capacitor），会员属数字商品被 App Store 3.1.1 强制走 IAP，抽 15-30% 且撕裂现有账本。
上国内 Android 商店还要软著（代办 300-1000 元 / 30-60 天）+ 域名 ICP 备案 + 隐私政策（已有 `隐私政策.md`）。
→ 给出的最低成本路径：**A（PWA 达标，0 元 1-2 天）→ B（Bubblewrap/TWA 打 APK 官网二维码自分发，0 元 2-3 天，
唯一成本是 JDK17 + Android SDK 一次性环境）→ C（Capacitor 上架）按需再议**。
