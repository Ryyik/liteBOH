### 📌 追问核实：国内安卓（华为/荣耀/vivo 等）到底有没有办法（2026-09-22）

### 🐛 用户实测报「registerPasskey is not a function」——根因与防御（2026-09-22）
- **不是弹窗代码的 bug，也不是 dev 限制**。根因链：`supabase.auth.registerPasskey` 是 **supabase-js 2.105+ 才加入**的 experimental API；项目 **09-21（6.3.3，提交 `44469ded`）才升级到 2.116.0**；而 **Vite 给依赖预构建产物（`node_modules/.vite/deps/`）下发 immutable 强缓存头** → 用户浏览器缓存的还是升级前的旧版 supabase-js → 运行时方法整个不存在 → TypeError。
- 排查中排除的可能：配置没错（守卫 `assertPasskeyExperimentalEnabled` 检查的就是单数 `experimental.passkey`，项目已开）；磁盘与 Vite 缓存里也确认是 2.116.0 且含该方法 → 问题只在**浏览器侧的模块缓存**。
- ⚠️ **⚠️ 上条结论已被推翻（更正）**：用 Playwright 全新无缓存上下文复现了同样的错误 → 不是浏览器缓存。**真根因：dev server 是在 supabase-js 升级（09-21）之前启动的，运行中 Vite 的依赖预构建产物一直是旧版**（服务 URL 带 `?v=becf36fc` 的旧产物，缺全部 passkey API）；后来 npm install 更新了源码与磁盘上的 `.vite/deps` 文件，但运行中的 server 内存 metadata 仍服务旧内容。**修复 = kill 旧进程 + `rm -rf node_modules/.vite` + 重启**。重启后实测：组件实例 `registerPasskey = function` ✅，点击后报 "Auth session missing!"（预期——预览页是假登录态，说明链路走到服务端会话校验了）。
- **方法论教训（比结论更重要）**：排查「方法不存在」类问题时，**别先怪浏览器缓存**——正确套路是①用「对比组件实例 vs 新建实例的原型方法集合」确认差异范围（本次：组件缺 22 个方法全是新版 API）；②「直接 import 预构建产物文件」二分定位是产物坏还是选项坏；③「浏览器里用组件同款选项 createClient」排除选项问题（本次全部 function → 锁定模块本身）；④对比两实例原型差异后，`performance.getEntriesByType('resource')` 里**同一个 deps 文件出现两个 URL（带 hash / 不带 hash）**就是「运行中 server 的产物缓存过期」的铁证。另：macOS BSD grep 不支持 `\|`（与 zsh 的坑同源），多模式要用 `grep -E`。
- **用户侧解法**：硬刷新（Cmd+Shift+R）/ 无痕窗口；不行则重启 dev server（重新预构建后 deps URL 的 hash 会变，浏览器自然拉新）。极端情况删 `node_modules/.vite` 再重启。
