## 发帖草稿：改为「单草稿」模型 + 修掉跨宿主不同步（用户定稿）

用户原话：「我只希望改成一个草稿的设定，就是云端草稿，不要再有多草稿系统了…你把东西删掉然后退出不保存那就是等于草稿删除了，你下次进来就是云端的草稿」。

**产品语义（定稿，别再改回去）**
- 一个用户只有**一份**草稿；云端 `forum_post_drafts` 为准，本地 localStorage 只是缓存/离线兜底。
- 打开编辑器 / 打开草稿面板即看到这份草稿（面板打开时走一次 `restorePostDraft` 对账云端）。
- 内容删光后关闭 = 删除草稿；弹「是否保存」选「不保存」= 删除草稿；发布成功也删。
- 多版本（`*_versions`）整套移除：storage 层 API、`FORUM_POST_DRAFT_VERSION_LIMIT`、
  面板版本列表、`restorePostDraftVersion`、对应 CSS 全删；旧 key 由 `purgeLegacyDraftVersions()` 主动清理。

**顺带修掉的真实缺陷（都有守卫/反证）**
1. 双宿主（首页无 keepAlive + UserSpace keepAlive & v-show 常驻）各持一份 `newPost` ⇒ 旧稿复活/覆盖新稿。
   修法：同标签页广播 `FORUM_POST_DRAFT_CHANGE_EVENT`（**不能用 storage 事件**，同 tab 不触发自己的），
   按 `hostId` 挡回声，接收方只在「编辑器内容仍等于上一份草稿」时才动 newPost。
2. `restorePostDraft({ preserveLocalEdits })`：KeepAlive 唤醒 / 重新打开编辑器时不覆盖未保存输入。
3. beforeunload 判据从 `isMobileComposerOpen` 换成 `isEditorDirty()`（= 编辑器 ≠ 已存草稿）⇒ 桌面内嵌编辑器也有刷新保护。
4. 只有图片没有文字时点「保存草稿」以前会**删掉**草稿（草稿存不了图）；现在保留原草稿 + 弹提示。
5. 登出/换账号不清内存副本 ⇒ 上一账号草稿残留给下一个账号；新增 `resetComposerEditorForAccountSwitch()`（只清内存，不删云端）。

  用户当场否掉（「日期顺序还是横着看的舒服」）。**已回退，别再往 columns 走。**

## 22:55 两个报障收口：充值弹窗去模糊 + 赞助页纯白

用户报：「充值积分的弹窗不要有模糊，赞助页面是纯白的」。两件事其实是**两个独立根因**，
一个在层级，一个在切换机制 —— 都在样式层，都不是数据。

**① 充值弹窗「有模糊」的真身是遮罩没铺满。**
`.ah-qr-overlay` 是 `position: fixed; inset: 0`，但它挂在 `.ah-page` 里，而 `.ah-page` 与宿主
`.tab-page` 的入场动画（`userspace-subpage-in … both` / `profile-panel-fade`）收尾后
computed `transform` 仍是 `matrix(1,0,0,1,0,0)` —— **单位矩阵也算 ≠ none**，照样建立包含块。
实测 1440×900：遮罩只有 1131×600 @(275,0)，右侧与底部整条露底；用户看到的是「页面没被压暗 +
边上一圈原样」，读起来就像「弹窗是半透明的/有模糊」。
修法：`<Teleport to="body">`。连带把 7 条暗色覆盖的前缀从 `.user-space-page[data-theme='dark']`
改成 `html[data-theme='dark']`（节点已经不在页根里，旧前缀一条都匹配不上 → 暗色下弹窗会变白卡）。
`backdrop-filter` 同时全部归 `none`，遮罩改实色 `rgba(15,23,42,.34)` / 暗色 `rgba(0,0,0,.62)`，
卡片改不透明 `#fff` / `#1c1e24`。

**② 赞助页「纯白」是 `<transition mode="out-in">` 永久卡死。**

之后只渲染一个注释节点 —— 内容区一片空白，浅色下就是「整页纯白」。
