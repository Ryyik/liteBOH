### 三条踩过的坑（下次直接引用）

1. **`height: auto` ↔ 长度不可过渡**。所以展开态高度由 JS 量一次写进 `--bottom-nav-shell-h`；只用 `getBoundingClientRect` + 挂 `resize`，**不能用 ResizeObserver**（收起动画全程尺寸在变，RO 会把中间态写回去形成自激）。
2. **圆直径不能由条高反算**：条高是内容撑的（icon 17 + gap 3 + 标签行高 22.8 + padding 14 + border 2 = 75）。现在球固定 60，宽高都走过渡，所以严格相等。
3. **暗色 CSS 是懒加载的**（`theme-css-loader`）：探针里手工改 `data-theme` 读到的仍是明色，必须写 `localStorage['boh-theme']='dark'` 让 themeManager 自己切。

## 切页「闪一下」与唤岛「卡一下」（同日第二轮，已修）

### ① 切页闪：路由级 200ms 淡入已移除

- 实测（PerformanceObserver + 逐帧采样 `.route-fade-enter-*`）：**每一次跨路由切换**都给整页加了一次
  opacity 0→1；而缓存页 DOM 本来就是复用的（`probe-cloud-keepalive` 0 请求），等于主动闪一下。
  深色页上是「从透明闪出底色」，浅色页上是内容先消失再浮现。
- 处理：删掉 `App.vue` 的 `<Transition name="route-fade">` + `style.css` 里的 `.route-fade-*`
  （2026-11-04 加的 P0-1 那版，它自己的注释就写着「不生效的最坏表现 = 退回瞬切」）。
- 复测：三次切换 `fadedCount=0`；`图库→我` 的 scrollY 从 0 恢复成 600（顺带修好了回顶）。
- ⚠️ **`/`（首页）与 `/shop` 仍不在 keepAlive 白名单**，每次进都是重挂 + 8 次请求（探针 D 组实测）。
  这两席要不要一起缓存是产品口径问题（首页常驻 30s 轮询会变成后台轮询），未擅自改。

### ② 唤岛卡：三个结构性原因

- **RO 每帧重入**：开岛时 surface 高度在 300ms 里逐帧变化 ⇒ nav 的 ResizeObserver 每帧回调
  `measureTop`，而它内部是「读 rect → 写 class/变量 → 再读 rect」= 每帧 2~3 次强制同步布局。
  改成 `scheduleMeasure()`（rAF 合并）+ 动画窗口 `morphUntil` 内让路 + 末尾补一次尾测。
- **mount 任务里 3 次强制布局**：`measureTop` 里卡片的 `getBoundingClientRect` 提到**所有写操作之前**
  一次读掉（profile：`getBoundingClientRect` 38.8ms/70 次）。
- **键盘与长高动画并发**：`BohIslandAnswer.onMounted` 立刻 `input.focus()` ⇒ iOS 键盘弹起 + 视口变化
  + 岛 max-height 重排全叠在同一帧。改为 **340ms 后**再聚焦（= 300ms 长高动画 + 余量）+ `preventScroll`；
  `UnifiedNavbar` 的 focusInput 兜底同基准（只是兜底，不抢跑）。
- 复测（6× CPU 降速，rAF 帧间隔）：长任务从 2 个（67~100ms）降到 1 个（69~71ms）；**4× 降速下长任务 0 个**。
  剩下那一个是回答面 UI 的挂载成本，要再降只能做两段式挂载（先壳后内容），未做。

## 性能建议全落地（提交 7b5242f0 / 0f7870b8）

产物级前后实测（1.6Mbps/RTT150/CPU4×，SW blocked，各 3 轮中位）：
- `/` LCP 8.89→7.72s、1027.0→719.5 KiB、158→145 请求
- `/user-space?tab=community` LCP 9.10→7.64s、979.6→659.2 KiB、145→130 请求

做法与**关键机制**（下次别再踩）：
- **`?url` 顶层静态 import 也是静态边**：`import x from 'pkg/dist/x.js?url'` 会让 Rollup
  把 `?url` 与包本体打进同一个 chunk ⇒ 19.5 KiB 压缩库进了首屏闭包。改成函数内
  `await import('...?url')` 才真正断开。**看产物要查 `from"./chunk.js"`，不能只看包名。**
- **「只读状态/判定」的静态 import 会把整条链带进来**：`content-moderation` 与论坛预载守卫
  都只需要冷却状态/两个判定，却静态 import `image-moderation-pipeline` ⇒
  pipeline + forum-image-moderation + nsfw 兜底链全被拖入。抽出 `moderation-cloud-state.js`
  （纯状态+判定，只依赖 logger）后两处各改 import 即可，状态仍是 ESM 单例。
  实测：论坛流不再拉那两个 chunk（7.4 KiB），压缩库不再随路由加载。
- **favicon 重复请求的修法是收敛声明，不是改缓存头**（GitHub Pages 不吃 `_headers`）：
  5 条声明→1 条 32×32，实测一次切页 `×3/24.9KiB` → `×1/3.0KiB`。
- **manifest 图标默认进 SW 预缓存**（vite-plugin-pwa `includeManifestIcons` 默认 true）：
  4 张 / 36.2 KiB 只在「添加到主屏」时用，却和 LCP 抢带宽。关掉 + 补 `/icons/` CacheFirst。
- 新门禁 `check:first-paint-closure`（源码级 4 条 + fixture）。**写门禁的第一版正则
  `import\s+[^;\n]*?from` 跨不过多行 import ⇒ 注入违规却不报**，改成
  `staticImportSpecifiers()`（`[^;]*?`）。**任何源码级门禁都必须先做一次「注入必红」自证**。
- `check:first-paint-budget` 在我动手前就已超基线 2.4 KB（本次自付 +1.0 KiB）。
  基线要在**干净树**上 rebaseline；脏工作区 update 会把并行会话的增长错误归因。

取舍（要写进后续对话）：去掉 `/ai-chat` 空闲预取后，**手机首次唤岛**多付 152.9 KiB
（BohIslandAnswer 8.2 + useChatEngine 115.5 + markdown 29.2，一次性）。
