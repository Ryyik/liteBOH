## 「灵动首屏」下拉动画：现状探查 + 优化方案（只探查，未改任何代码）

### 现状机制
`views/Home/index.vue` 是「阈值触发器」而非「跟手拖拽」：wheel 累加 deltaY / touchmove 取绝对位移 / 键盘计数，
达 `SWIPE_TRIGGER_DISTANCE=28` 直接调 `enterForum()` → 一次性播 880ms 退场（gate 上移 -112% + blur 12px）
+ 980ms 论坛落定（translateY 88px→0 + blur 12px→0）+ 560ms 后底栏 900ms 浮入。
全程无 progress 变量、无回弹、无释放速度判定。

1. `.home-forum-stage` 顶部 24px 圆角（style.scoped.css:130-131）**亮色下不可见**：stage `#ffffff` == `--boh-page-bg #ffffff`；暗色（stage `--boh-bg-secondary` vs page `#16120e`）才看得见。

4. `gateRef` / `gateEnterBtnRef` / `forumStageRef` 三个 ref 声明后从未使用（无 focus 逻辑、无 stage 测量）。
5. 阈值冲突：`StreetSceneHero` 用 `scrollY > 24` 撤提示，`index.vue` 用 28px 触发退场 → 提示 320ms 淡出未走完就被 `homeGateContentExit` 接管，观感是「闪一下」。
6. **reduce 时序不同步**：动画被压到 300ms，但 `GATE_TRANSITION_MS(880)/FORUM_ENTER_MS(980)/BOTTOM_NAV(560+900)` 计时器不变 → gate 淡完后仍盖着 ~580ms「空窗」。

8. 横屏左栏 `body.page-home:has(.home-gate) .userspace-rail{display:none}` → gate 卸载后左栏**瞬现**（display 切换无过渡）；且左栏让位只在 1024px+ 生效。
9. `@keyframes homeForumStageIn` 的 fallback `1320ms` 是历史残留（实际由 980ms 变量驱动），易误读。
10. 手势层健壮性：`handleWheel` 不排除 `event.ctrlKey`（触控板捏合缩放会灌 wheel）与横向 `deltaX`，且 passive 监听下**底层文档真的在滚**（gate 是 fixed 不占位），用户下拉时画面静止但 scrollY 在涨 → 「跟手」感知为 0。

## 用户实测反馈修复：「下滑整个页面直接卡住了」（紧急，已修）

### 复现与根因
写临时诊断脚本（`scripts/probes/_tmp-diag-home-pull.mjs`，跑完已删）实测：
- 轻滑 120px → `--gate-p=0.12` → **弹回 0**，页面纹丝不动；
- 连滑 6×120 = 720px 才到 `p=0.72` → 提交。
根因是**门槛与行程都太保守**：`0.22 × 1.25 屏(1000px) = 250px` 才提交，而一次滚轮只有 ~120px、
触控板轻滑更少 → 用户「滑一下没反应，再滑又弹回」＝体感卡死。

### 四处修复
1. 门槛/行程：`PULL_FULL_DISTANCE_RATIO 1.25 → 0.85`、`PULL_COMMIT_PROGRESS 0.22 → 0.10`
   → 门槛 ≈ 68px（vh 800），一次滚轮（~0.18 进度）即进；「只轻拨一下」仍会弹回，可反悔性没丢。
2. 滚轮静默期 `140 → 160ms`：正常滚轮节奏的间隔多在 150ms 内，让它们算作同一次手势才能累积。
3. 回弹时长 `settleMs 780 → 420ms`：没进论坛那次手势要尽快回位，否则下次滑动在跟残留动画抢（入场仍旧 1400ms 慢速长，用户要的「慢速」只针对入场）。
4. **解锁不再依赖 rAF 补间链**：加 `unlockTimer` 硬计时器（`pullMs + 150ms`）兜底 + 补间回调里提前解锁（取先到者）；并把解锁时机从「对焦动画结束」提前到「落位（p=1）」，少锁 760ms。

### 结构性加固（防「整站永久滚不动」）
- **wheel / touch 从 `window` 移到 `.home-gate` 元素上**（模板 `@wheel` / `@touch*`）。
  window 上的 `passive:false + preventDefault` 是全局副作用 —— 一旦监听泄漏（HMR / 异常卸载 /
  teardown 被抛错中断），整站永久滚不动，用户只剩关页面。挂元素上由 Vue 卸载时自动清理。
  只剩键盘留在 window（无 preventDefault 全局风险）。
- CSS 侧加 `touch-action: none` 作为拦住底层滚动的第一道防线（第二道是事件层 preventDefault）。

`probe-home-gate-pull.mjs` 扩到 **50 条，50/50 PASS**，新增的守卫直接锁住这次的问题：
- C1/C2 轻拨 40px 时进度确实在动（`gateY=-47`）→ 「滑了没反应」不再回归；
- D7 落定后 `html` 的 inline overflow 已清空；D8 真实滚轮能滚起论坛（`scrollY=600`）→ 「卡住」不再回归。
`probe-home-forum-rail.mjs` 21/21 PASS；门禁（!important 预算 1319/1319、first-paint、liquid-glass、views）全绿。

## 过渡改成「Apple 式揭开浮层」（用户反馈「一点都不自然」）

### 问题
旧实现是「两页互相对滑」：开场画上移一屏 + 论坛从视口下方 100vh 升上来 —— 那是 push 新页面的语言，
两头都在动、谁也不在原地，所以不自然。用户点名的参照是「Apple 通知栏下滑进桌面」那种「浮层盖在桌屏上」。

### 改法（`Home/style.scoped.css`）
- **论坛层＝桌面**：`transform: scale(1 + (1 - --forum-p) * 0.02)` —— 一直在原位，只做极轻归位。
- **开场画＝浮层**：`translateY(calc(--gate-p * -14%)) scale(1 - 0.07p)` + `border-radius: 28px*p` + `overflow: hidden`
  + opacity 后段淡出。位移刻意不做满屏（走满一屏是「换页」，缩着走才是「揭盖」），缩小后四周露出下面一直在的桌面。
- 删掉 `.home-gate-backdrop`（暖米色背板）—— 那是「卡片从下方升起」时代的衬底，新模型不需要。
- 删掉 `.home-forum-stage` 的 `visibility: hidden` 与 `gate-pulling` 类：桌面本来就在视口里，
  顺带让论坛图片懒加载 IO 在开场画期间就能开始工作。
- `style.scoped.css` 里不能再有 `.home-gate` 的第二份定义（本轮踩过一次：先插了新 stage 块却没删旧块）。

### 探针同步（`probe-home-gate-pull.mjs` → 50/50 PASS）
A3/A4/A5、B4/B5/B7、C5/C6、D5/D6、E3、F3/F4、I4/I5/I6 全部按新模型改写；
新增 **I5 明确禁止再出现「一屏位移（100vh）」的换页式 transform**、I6 断言「圆角只属于浮层」。

## LQIP 与云图缓存（用户反馈「刷新之后帖子列表图片加载失败，详情正常，偶发」）

### 诊断：本地未复现，但锁定了两个真问题
实测 54 张卡片图 / 251 个图片请求 / **0 失败 / 0 慢请求**；「已通过开场画」与「开场画下滑进入」
两种路径数据一致 → **与本轮首屏入场改动无关**。但：
- LQIP（原 `f_auto,q_auto:low,c_fill,w_72,h_54,e_blur:1000`）实测 **8s 仍未 complete**
  → 弱网下它才是「空白」的主因；详情页走原图（无小尺寸 transformation）所以「详情正常」。
- `.image-post-thumb` 在拿到 `is-loaded` 前 `opacity: 0`，外壳 `::before` 是**无限转圈**
  → 只要 load 事件不来就是「永远转圈 + 空白」＝用户判定「加载失败」。

### 三处修复
1. **转圈 3.2s 静默超时兜底**（`views/Forum/styles/feed.css`）：给 `.image-post-thumb-shell::before`
   加第二条「0s 时长 + delay + forwards」动画当纯 CSS 定时器 → 不管加载成没成，3.2s 后转圈自行消失。
   reduce 偏好下全局把 animation-delay/duration 压成 0，天然不会出现转圈，无需特判。
2. **LQIP 压到极限**（`utils/api/forum-format.js`）：`w_72,h_54,q_auto:low` → `w_32,h_24,q_1`
   → 单张从 KB 级降到几百字节（它本来就被 CSS `blur(18px)` 罩着，尺寸变化观感无差别），先到概率大得多。
3. **云图两条运行时缓存**（`vite.config.js` 的 runtimeCaching）：
   · 带 `e_blur` 的 LQIP → **CacheFirst**（一次之后零网络）
   · 其余 `/image/upload/` 正文图 → **StaleWhileRevalidate**（刷新即本地秒显 + 后台静默更新；
     不用 CacheFirst 是为了避免「同 publicId 覆盖上传后长期显示旧图」）
   → 直接对症「刷新之后图片加载失败」。

### 顺带合并双源
`FORUM_LIST_IMAGE_TRANSFORM` / `_SM` / `_MD` / `_LQIP_` / `_DETAIL_` 这 5 个常量曾在
`utils/api/forum-format.js`（数据层）与 `views/Forum/forum-config.js` **各写一份**（值相同）——
现在只留数据层那份，`forum-config.js` 改为 re-export，调用方 import 路径不变。

### 关于「把 LQIP 内联成 data URI」：没做，原因如下
LQIP 是**每张图各自**由 Cloudinary 按 publicId 实时生成的极小模糊版，**不是一批固定资源**，
无法「一次性生成并维护到静态 HTML/CSS」里。真内联只有一条路：DB 存 base64
（上传时前端 canvas 生成 16×12 → 写入 `forum_post_images` 新字段 → 历史图片还得跑回填脚本）。
而 SW 缓存达到的效果等价（二次访问零网络往返）、零迁移、零回填 —— 所以先走 SW。
若日后仍要真内联，落地路径已明确：加字段 + 上传链路写入 + PostCard 优先读，缺失时回落远程 LQIP。

## 三调：行程加长 + 时长再放慢 + 入场逻辑抽成 composable（用户三点要求）

### 1. 行程加长（`Home/style.scoped.css`）
浮层 `translateY(-14% → -36%)`、`scale(0.93 → 0.90)`、圆角 `28px → 32px`，

`pullMs 1400 → 1900`、`focusMs 760 → 860`、`navEnterMs 1200 → 1400`；
**回弹保持短（460ms）** —— 「慢」只用在入场，不用在「拒绝你」的时候。
跟手行程 `PULL_FULL_DISTANCE_RATIO 0.85 → 1.0` 屏（门槛随之 ≈80px，一次滚轮仍够）。

### 3. 入场逻辑抽离成 composable（用户要求「整理一下避免屎山」）
- 新建 `src/views/Home/composables/useGatePull.js`（445 行）：GATE 标记读写、跟手参数、
  时序表、滚动锁三保险、进度写入与补间、释放决策、三源手势、reduce 分身、底部导航浮现联动。
- `src/views/Home/index.vue`：**778 → 403 行**，入场只剩「解构 + 接线」，
  顶部注释写清了「改门槛/时长去 composable、改观感去 CSS」。
- 边界刻意划干净：composable **不碰任何 DOM ref**（`--gate-p`/`--forum-p` 由模板绑到根元素 style），

- 抽离后 `homeRootRef` 曾被一起删掉导致 `no-undef`，已补回并在注释里说明它为什么不属于入场逻辑。
- 生命周期：页面 `onMounted → mountGatePull()`、`onBeforeUnmount → unmountGatePull()`。

## 五调：浮层「没走完不许透视」（用户反馈「滑到一半就半透明，能看到下面内容了，但卡片还没走完」）

原 `opacity: calc(1 - var(--gate-p) * 1.15)` 是**线性淡出** —— p≈0.87 就全透，
于是拖动中段整块浮层变成磨砂玻璃，观感是「没走完就漏了」。

改成 clamp 分段：`opacity: clamp(0, calc((1 - var(--gate-p)) * 5), 1)`
→ p ≤ 0.8 恒为 1（完全不透明），只有最后 20% 才从 1 降到 0；
配合 easeOutExpo 的后段极缓，这段淡出本身也跑得从容。

⚠️ 不要改回线性算式 —— 「拖到一半就能透视到底下」是被明确否掉的观感。
探针新增 **B9**：走到一半时 `gateOpacity === 1`（守住这条）。

## 论坛搜索的现状审查（用户问「还能优化什么」）—— 结论：中文基本搜不到

### 实现链路（摸清了）
前端 `ForumMain.vue`：`searchQuery`（输入实时值）→ 350ms debounce（`SEARCH_DEBOUNCE_MS`）→
`applySearchFromInput()` → `searchKeyword`（生效词）→ 取数时作为 `pagination.searchQuery` 传给
RPC `list_forum_posts`；竞态用 `requestSeq !== forumFetchSeq` 兜住。
高亮：SQL 侧 `ts_headline(... StartSel=[[, StopSel=]])` → 前端 `renderSearchExcerpt` 把 `[[...]]`
换成 `<mark>` 再 DOMPurify 白名单（`ForumMain.vue:2573`）。

### 致命问题：分词配置是 `simple`
- `posts.search_vector` 是 **generated column**：
  `setweight(to_tsvector('simple', title),'A') || setweight(to_tsvector('simple', body),'B') || setweight(to_tsvector('simple', author_username),'C')`
  （`supabase/migrations/2026050702_forum_title_counts_like_rpc.sql:16-22`，GIN 索引在 :24）
- 查询侧：`bp.search_vector @@ websearch_to_tsquery('simple', v_query)`，排序 `ts_rank_cd`
  （`supabase/migrations/2026091106_avatar_frame_url.sql:226-251`）
- **`simple` 不切中文**：汉字是 word 字符、段内无分隔 → 整段中文成为**一个词元**。
  `to_tsvector('simple','今天去海边玩了，天气很好')` → `'今天去海边玩了':1 '天气很好':2`；
  搜「天气」= tsquery `'天气'` ≠ `'天气很好'` → **不命中**。
  即：中文只有「输入的词与帖子里被标点/空格隔开的那一整段完全相同」才搜得到。
- 全局没有用过 `pg_trgm` / `pgroonga` / `zhparser` ✓ 没有任何子串兜底。
- 同源影响：`ts_headline` 也用 `simple` → 中文高亮位置同样不准。

### 方案（按成本）
1. **pg_trgm + ILIKE 兜底**（最小改动、推荐先做）：装 `pg_trgm`，给 `title/content` 建
   `gin (… gin_trgm_ops)`，查询侧改成 `全文命中 OR content ILIKE '%kw%'`，trgm 索引能吃 ILIKE。
2. **pgroonga**（Supabase 支持该扩展）：真正的 CJK 分词 + `pgroonga_highlight_html`，
   但要重建向量列与查询侧，改动大。
3. `zhparser` / `pg_jieba`：Supabase 装不上，排除。

### 另外三个具体可修点
- **相关度会被排序档盖掉**：`case when v_has_query and v_sort = 'latest' then ts_rank_cd(...)`
  → 有关键词时切到「最热」就变成纯热度排序，相关度丢失。建议：有搜索词时**恒以相关度优先**。
- 无最小查询长度保护（单字查询）。
- 前端：搜索词没有「清除」按钮（只有 tag chip 有 ×）；无结果计数/历史/⌘K；
  搜索不写 URL（有意设计，记忆里有「实时输入不许写 URL」）→ 若要可分享，只在「回车/点搜索钮」时写 `?q=`。

### 凭据问题（阻塞实测与迁移）
`security find-generic-password -s "Supabase CLI"` 取到的值打 Management API 报
`JWT could not be decoded` → 当前无法跑 SQL 验证 / 无法走 Management API 迁移。
要动 DB 侧（方案 1/2）得先解决这个 token。

## 追加：搜索开启光效（岛的**边缘**一圈暖光，一闪即散）

### 需求对齐的教训（重要）
用户最初描述「光效波及整个岛，一闪」。我用 AskUserQuestion 确认了范围（整个岛）与形式
（用户选「从点击处向外扩散」），据此做成了**内部径向渐变填充**——做完用户说
「我想要的是点击之后岛的边缘会有一圈光效」。
**教训：视觉动效的文字沟通歧义极大。「范围 × 扩散方向」两个维度都确认过，仍漏掉真正的形态意图
——边缘描边（rim light）与内部填充（fill glow）是完全不同的实现。下次这类需求应该先给
2-3 个形态的快速原型/示意图让用户挑，再动手。**

### 三轮迭代（全部由定格截图驱动）
1. **纯白内部光** → 结构断言全绿但**截图里完全看不见**。根因：浅色下岛是
   `rgba(255,255,255,.66)` 白玻璃叠白页（等于白），白叠白对比度为零
   （用户的猜测「是因为都是白色吗」是对的）。
2. **暖金内部光**（环状波前）→ 可见了，但定格峰值像「一块金色蒙版」、文字被染黄；调薄后可接受，
   但形态仍不是用户要的。
3. **用户澄清「边缘一圈」→ 换描边方案**：`border: 2px solid 暖金` + 三层 box-shadow
   （贴边 1px / 近晕 20px / 远晕 46px）+ `inset` 内辉光 + `border-radius: inherit`。
   动画只动 opacity（12% 峰值 → 100% 归零），**不逐帧重算 box-shadow**（大面积重绘）。

# 「问 BOHAI → AI 岛当前不可用」根因：导航栏可见性判据两套且不同源

用户截图报「AI 岛当前不可用，请稍后再试」。

## 定位链（每层都验过）

1. 文案唯一来源 `ForumMain.askBohai` → `showIsland.ai()` 返回 falsy
2. `useIsland.ai()`：`aiOpener` 未注册，**或** `aiOpener(options) !== true`
3. `aiOpener` 由 `UnifiedNavbar` 的 setup 顶层 `registerIslandAiOpener(...)` 注册，
   `onUnmounted` 时注销为 `null` —— 即**导航栏一卸载，AI 岛就没宿主**
4. opener 内部 `if (!isBohaiIslandAllowed.value) return false`，即 `useGlobalAiOverlay.canOpen`
5. `canOpen` 原来**只有两条**判据：`route.name === 'AiChat'`、`route.meta.hideNavbar`
6. 而 `App.vue` 是 `<UnifiedNavbar v-if="showGlobalNavbar" />`，`showGlobalNavbar` 有**六条**判据

→ **漏了 4 条**：`?embed=desktop`、`?from=userspace*`、
`/user-space?tab=profile&view=…`、`/user-space?tab=settings&view=…`。
这些路由上导航栏已经卸载（`aiOpener = null`），但 `canOpen` 仍说「可以」→
`showIsland.ai()` 静默返回 false —— **必然失败，却被文案说成「请稍后再试」的偶发**。

## 修复（单源化 + 文案）

- 新建 `src/utils/global-navbar-visibility.js`：`isGlobalNavbarVisible(route)` = 六条判据的**唯一真源**
- `App.vue.showGlobalNavbar` = `computed(() => isGlobalNavbarVisible(route))`
- `useGlobalAiOverlay.canOpen` = `route.name !== 'AiChat' && isGlobalNavbarVisible(route)`
- `askBohai` 失败文案改为「当前视图隐藏了顶部导航栏，AI 岛打不开 —— 到首页或完整论坛页再问 BOHAI。」
