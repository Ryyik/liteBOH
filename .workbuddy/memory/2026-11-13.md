## 21:20 调试彩光「真的和输入框一样吗」——逐项对齐（第 4 版）

用户质疑「你确定和思考状态的那个长得一样嘛」。**结论：上一版不一样**，机制同构但三处可感知差异，
读完两份 CSS 逐项比对后改掉：

| 项 | BohBeam（输入框） | 旧 debug 版 | 现版 |
|---|---|---|---|
| 环宽 | 1px | 4px | 2px |
| 上边色斑占边长 | 46%（3 个合计 408px / 880px） | **72%**（922px / 1280px） | ≈46%（19vw+12vw+14vw） |
| 描边层高光 conic | 有（54%→78%） | **缺**（整层挪进 blur 的 ::before） | 有（照抄停靠点） |
| 窗口 mask | 30%→95% | 22%→97% | 30%→95% |
| 亮度 | `--boh-beam-stroke-o`（浅 0.9 / 暗 0.48） | 写死 0.95 + brightness 1.12 | `calc(令牌 × 1.5)` |

三条关键认知（别再走回头路）：
1. **「一样」＝同机制 + 同占边比例，不是同一串像素值**。BohBeam 原样铺满全屏只剩右上角一点橙（实测两次）。
2. **色斑要按「占边长百分比」缩放**，不是等比放大整体：尺寸放大 1.4 倍的同时边长也放大 1.45 倍，
   亮段占比反而更满 ⇒ 变成彩色灯带。按 0.63 倍收缩后，顶边才回到「一小段光」。
3. **描边层的高光 conic 不能省**。它是「光带上有锐利亮点」的来源；挪进 blur 层只剩柔光，
   观感立刻变「糊」。BohBeam 三层结构里描边层是 `色斑 + 高光` 两层 background 叠加。
4. 预览页必须写 `data-boh-theme="dark"`，否则令牌走浅色档（0.9），暗色效果会被误判。
