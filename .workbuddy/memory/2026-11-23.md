## 新增：`docs/demos/boh-film.html` —— 纯前端绘制的「伪视频」宣传片

需求原话是「用 HTML 写一个 Apple 和 OpenAI 风格的宣传片」，澄清后确认为**自动播放的伪视频**
（不是滚动叙事单页）。产出单文件 HTML，56KB，零依赖、零外部资源（照片除外）。

### 结构
- 9 幕 / 62.4s，`SCENES` 表定义 `{id,label,dur}`，`start` 累加得出时间轴。
- 一个全局 `t`（秒）驱动所有画面，`requestAnimationFrame` 循环里 `renderAt(t)`。
  **没有用 setTimeout 串联，也没有用 CSS animation delay 接力** —— 那样一暂停/跳帧就全错。
- 每帧逐元素算样式写进去，所以空格真暂停、←→ 真跳章、进度条真能拖。

### 关键设计决策
- **硬切**，不做过渡。网页爱淡入淡出，真片子是直接切 —— 这是最像视频的一招。
- **一个镜头只讲一件事**。每幕只允许一个亮点，其余全静止（Apple 的产品片规则）。
- **图形语言唯一**：像素苹果由 12×11 字符网格 `drawCells()` 画出，和麦块格共用同一套格子。
- **照片是唯一放开颜色的地方**（灰度→彩色），其余全黑白 + 像素红 `#e01f26` 点睛。
- **声音用 WebAudio 现场合成**，零音频文件：低频 drone（55/82.4Hz + 粉噪）+ 切幕噪声 tick / 低频 thump。

### 实测踩到的坑（按惨烈程度）
1. 🔴 **CSS 闭合括号错位 ⇒ 整段样式静默失效**。用脚本剪切媒体查询块时把 `#stage{}` 的
   `}` 一起搬走了，导致其后所有规则落进 `#stage{}` 内部变成无效声明。表现：
   `#cv` 的 `position:absolute` 丢失 → `computedStyle` 显示 `static` → 画布不参与合成 →
   **截图永远全黑，但 `canvas.toDataURL()` 内容完全正确**。排查花了很久，因为
   直觉会怀疑 canvas / GPU / mix-blend-mode，而真因是 CSS 括号。
   诊断手法：逐字符数 `{}` 找到 depth<0 的行，再看 `#cv` 的 computed position。
   **教训：用脚本改 CSS 必须校验括号平衡（`css.count('{') == css.count('}')`）**。
2. 🔴 **`cqh` 在 `container-type:inline-size` 下无效**，会回退到视口高度。写
   `max(16px, 5.4cqh)` 在 219px 高的竖屏舞台上算出 45px，比标题还大。
   舞台恒为 16:9 ⇒ 只需用 `cqw`，比例与横屏一一对应。
3. 🔴 **`grid` 的 `1fr` 在 `width:max-content` 容器里会塌成极小值**（实测 46px），
   把描述整段挤到标题上。改用 `flex` + `gap`。
4. 🔴 媒体查询写在样式表中段会被后面同优先级的基础规则整块盖掉 →
   **表现为「改了媒体查询但页面毫无变化」**。竖屏覆盖块必须放样式表末尾。
5. 首次点击舞台「开声音」和「暂停」叠在同一个手势上 ⇒ 用户点一下想开声音，片子停住，
   看起来像「播放坏了」。用 `consumeFirstGesture` 吃掉紧随的 click。
6. 场景切换瞬间全黑（绘制函数 0.3s 后才首帧有内容）。修法：动画起始时间给**负值**
   = 硬切入动作中间（真片子的常用手法），并把飞行中的亮度地板从 14 抬到 26。
7. 片尾只压暗 42% 就结束，观感是「画面突然停住」。改成真淡出到黑。

### 自证方式
- 全片每 0.5s 采样 125 个点，用 `getImageData` 统计非背景像素 + 检查 DOM 文字可见性，
  断言**无空帧**。
- 逐幕 3 个时间点截图 + 联系表肉眼过。
- 竖屏 390×844 九幕全部做 `getBoundingClientRect` 越界检测（对舞台矩形）。
- 交互 7 项：空格暂停/恢复、←→ 跳章、拖动、R 重播、竖屏尺寸、无 pageerror。
- 真实播放时每 2s 读一次时间码，断言单调递增且能跨幕。

### 遗留
- 照片走相对路径 `../../src/assets/images/*.webp`，从 `docs/demos/` 打开才有效；
  若日后要独立分发，需把 3 张图内联或改绝对路径。
- 声音默认静音（浏览器手势限制），首次点击舞台自动开。

## 版本更新「不弹窗、不通知」+ 现场接续（2026-11-23，用户定稿）

### 决定与理由
用户问「你觉得弹窗必要吗」→ 结论：**不必要，应删掉而非改造**。三条论证：
1. 用户点「立即更新」与系统静默执行的都是同一个 `forceCleanAndReload(remoteBuildId)`，
   **结果完全相同** ⇒ 问了不产生任何决策差异。
2. 「新版本」三字**不携带决策依据**；系统掌握上传/焦点/播放/脏输入四项状态，用户不知道
   ⇒ 把判断权交给信息更少的一方是推卸，不是体贴。
3. 通知是**掩盖副作用**而非消除副作用（回顶/展开收起/白屏）。
用户进一步确认：「所以更新弹窗就不做了，也不做通知了」——连轻量提示也不要。

### 实测踩出来的两个真坑（都写进代码注释了）
1. 🔴 **硬重置会覆盖正确的 scrollY**：`recoverStaleLanding` 发生在新文档刚加载时
   （`scrollY=0`、`docH` 只有一屏 800），照常采集会把上一次的 600 覆盖成 0 ⇒ 比不接续更糟。
   修法：`captureUpdateContinuity({ preserveExisting: true })`，scrollY 为 0 且同 hash 时沿用旧值。
   证据：`window.name` 抓到 `yAtCapture:0, docH:800`，而切换前实际 600px。
2. 🔴 **路由 scrollBehavior 会把我们按回去**：它对跨路由恒返回 `{top:0}`，且在挂载后执行。
   修法：改「一次落位」为**持续看守**（ResizeObserver 盯文档高度 + 每帧核实际 scrollY，
   被按回就再滚回去，连续 30 帧稳定才收工）。`RESTORE_DEADLINE_MS` 2.5s → 8s
   （内容分批到达：800 → 1093 → 3144）。

### 探针（两条，职责分离）
- `probe-silent-update.mjs`（6）：零弹窗（MutationObserver 全程记，不能只看末尾）、
  无 UI 监听、空闲 20s 静默切换、采集发生、无 JS 异常。
- `probe-update-continuity.mjs`（4）：带记录重载 ⇒ 精确复原到 700px、用后即焚、
  hash 不符不套用、过期不套用。
- ⚠️ **探针环境固有局限**：伪造 version.json + index.html meta 但伪造不了 SW 预缓存里的
  index.html ⇒ 判定「落地失败」⇒ 必进硬重置 ⇒ 位置归零。所以「切换后仍停在原位」是
  **永远不可能通过的假断言**，拆到 continuity 探针里单测。

## 二次改版（同日）：改为**纯白背景 + 黑色文字 + 丰富动效**

### 动效清单（这是本次的核心交付）
1. **种子**：一个黑点 → 横向拉成一条线 → 文字逐字从线里升起来（带 blur）。
2. **生长**：canvas 绘制，一格 → 2×2 → 3×3 → 5×5 网格线，逐线生长。
3. **名字**：逐字 mask 升起 + **字距从 0.28em 收到 -0.028em** + 细线从中心展开。
4. **年轮**：年份数字滚轮 + 描述逐字升起 + 底部进度线。
5. **我们**：照片 `clip-path: inset()` 自下而上擦除 + 内部图片反向缩放缓推。
6. **日常**：三组三级 stagger（编号淡入 → 标题 mask 升起 → 说明右滑入）+ 竖线 scaleY 生长。
7. **问问**：光标按时间轴打字 + 边框变实 + 回答逐字带模糊浮现。
8. **八年**：大数字 easeOutQuint 滚轮 00→08 + 三条陈述依次右滑。
9. **收尾**：像素苹果从中心向外逐格弹出 + 品牌字升起 + 整块上浮淡出。

### 这一轮踩到的坑（都已实测确认）
1. 🔴 **滚轮类动画必须"大部分时间是整数行"**。`pos = raw` 直接线性滚，窗口里永远露着
   相邻项的半截字（截图上是年份下面一排「— — — —」，其实是下一年的字顶）。
   修法：行内前 72% 锁整数，最后 28% 才 easeInOut 过渡。
2. 🔴 **`splitChars` 会 `innerHTML=''`**。先插小方块再 splitChars，方块会被清掉；
   反过来先 splitChars 再 insertBefore，方块又不在 chars 数组里 → 动画不驱动它，
   表现为「只有一个小黑块、后面文字全不出来」。正确顺序：先建方块 → splitChars →
   再把方块 insertBefore 回去，并用独立变量持有。
3. 🔴 **canvas 图形要按窄屏额外缩放**。canvas 逻辑坐标恒 1600×900，竖屏舞台只有 219px 高时
   图形按比例缩小、但 DOM 文字用的是 cqw（跟舞台宽），两者比例不再匹配 ⇒ 片尾 logo
   压到文字上。加 `appleScale = r.width < 640 ? 0.76 : 1`。
4. 🔴 **滚动窗口高度必须 = 行高**，否则 translateY 算出的位移让整列溢出画框。
5. 🔴 年轮幕「左列(年+线+序号) / 右列(描述)」两列 flex 居中时，**描述对准的是整块左列的
   中心**，而数字滚轮中心比它高 40px。改成两行结构（main 行只有年+描述同轴，foot 行放线+序号）。
6. 🔴 **越界检测要排除被 `overflow:hidden` 祖先裁切的元素**，否则滚轮列里的所有行
   都会被误报。第一版检测报了 6 组假阳性。
7. CSS 尺度：1436px 宽舞台上 `4.2cqw` 只有 60px，整块 331px —— 在 16:9 画框里显得很小。
   年轮 11.6cqw / 日常 6.4cqw / 数字 22cqw 才有分量。

### 二次返工：矢量树 → 精细化像素风

第一版是 SVG 渐变 + 贝塞尔树冠，被判「画风太粗糙」；改像素画后又要求「精细化」。
最终形态：`data/tree-pixels.js` 纯函数生成 100×120 格像素画（字符串 v-html 注入），
UI（按钮 / 卡片 / 弹窗 / 星点 / 雪花）全部改成像素语义。

**范式**：对齐 `views/Home/components/halloween-scene.js` —— 整数格、`shape-rendering="crispEdges"`、
硬色带代替渐变、确定性种子随机。整幅画 ~1700 个 rect，单测锁了 < 4000 上限
（万圣节场景曾铺到 6.9 万，首屏直接卡死）。

**视觉评审当场发现的坑**：
1. 🔴 **天空不能画在 SVG 里**。页面背景是整屏硬色带，SVG 再画一份会在容器边缘露出一块
   「贴上去的矩形」—— 两边分段位置对不齐，桌面版一眼就能看出来。
2. 🔴 **光晕 alpha 太低会变成脏斑**。低 alpha 暖色叠深蓝 = 灰褐圆，像污渍而不是光；
   近圈必须 ≥ 0.5，且用暖白不用暖黄。光晕形状必须逐行算半宽的像素圆，**不能用矩形叠**。
3. 🔴 **挂点要按「剩余人数 / 剩余行数」均摊**，只按容量放会让 8 个人全塞进最宽的底行；
   行偏移要同时受 `stepX` 与 `size` 约束 —— 只看 stepX 时两人一行会算出上百像素偏移、挂到树外。
4. 🔴 **雪地三档色 + 只在树根 ±14 格堆高**：整条纯白会在容器边缘切出直角；远景雪丘若填到
   画布底部，会在树脚露出一条把树「架在半空」的深蓝横带。
5. 像素风三条硬规则：圆角 0、阴影无模糊（只允许实心偏移块）、渐变只允许硬色带。
   连 `backdrop-filter` 也去掉 —— 毛玻璃柔边与像素画放一起立刻露怯（顺带消掉 liquid-glass 违规）。
6. 挂饰仍是 HTML（头像裁剪 / 头像框 / hover 浮名），改成方形挂牌 + 双层硬描边；
   `v-html` 注入的节点吃不到 scoped 样式，动画类必须走 `:deep(.px-*)`。
