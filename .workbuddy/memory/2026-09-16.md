### 本次踩到的新坑（重要，已同步 MEMORY.md）
1. **跨域 mock 必须发 `Access-Control-Expose-Headers: Content-Range`**。`Content-Range` 不在 CORS 安全列表里，浏览器不会把它交给脚本 → supabase-js 的 `count` 恒为 null → `delete({count:'exact'})` 被判「不存在或无权限」而回滚。探针 `page.on('response')` 看得到该头（CDP 层不受 CORS 限制），极易误判为「请求成功但没生效」。
2. **`Content-Range` 的格式与状态码**：DELETE 无 `.select()` 时真实 PostgREST 返 204；mock 用 200 + 空 body 会让 supabase-js 去 `JSON.parse('')` 而报错。稳妥写法：200 + `content-range: 0-0/1` + 合法 JSON body。
3. **`onErrorCaptured` 返回 false ⇒ window 收不到 pageerror**。所以"没有 pageerror"是边界生效的**证据**，不能当失败判据；判据应是"边界卡片正文里带出了原始错误信息"。
4. **Vue 事件处理器里 rejected Promise 走 `app.config.errorHandler`，不会变成 unhandledrejection**（main.js:281 已设置）。探针想抓这类错误必须包 `app.config.errorHandler`，且要等它被赋值后再包（我在 `#app.__vue_app__` 出现后包，仍抓不到 —— 该链路待查，但本轮不阻塞）。
5. **等待选择器别用 `[class*="x"]`**：`[class*="memory"]` 会被祖先 `.shared-memory-page` 自己命中，等于没有等待。要精确用 `.memory-card` / `.empty-state`。
6. **就地切主题验证暗色比"重载 + 复现崩溃"稳**：`document.documentElement.setAttribute('data-theme','dark')` 即可重算 token；走 reload 路线会因 boot 时序不同而复现不出崩溃。实测标题 `rgb(29,29,31) → rgb(245,245,247)`。
7. 触发真实渲染崩溃的可靠姿势（不篡改组件）：`localStorage['boh_health_persist']`（S11 的固定 key）写入 `profile: null` → Health 页模板读已持久化的空 profile → `Cannot read properties of null (reading 'heightCm')`。这条同时实证了 S11 与 S16 的交叉风险。

## 心理专家角色 §16「规则不遗忘机制」（用户点出：重点是说清规则 + 保证 AI 不会忘）

用户："重点是告诉AI规则，并且保证AI不会忘记" → 独立成章（方案 §16），这是整套设计的工程命门。

**丢规则的三条真实机制**：
1. **注意力稀释** — system 里规则段越长，相对权重越低；前 3 轮守"一次只问一个问题"，第 8 轮问出三个。
2. **历史被压缩** — `MAX_HISTORY_CONTEXT_CHARS=12000`（chat-engine-config.js:27）+ 自动整理产出 `contextSummary` 注入 `<conversation_summary>`（useChatEngine.js:1841-1845）。**长访谈必然触发**，第 3 轮那句关键原话会被压成"用户提到有例外情况"。
3. **状态不在提示里** — `askedCount`/`ladderingDepth`/`coverage` 若只在前端 JS，模型看不见，规则自然失效。

**结论：写得更狠没用，要靠「每轮重建 + 状态注入 + 代码守门」。** 好消息第 1 层现成：system 每轮从数组重新拼装（useChatEngine.js:1847-1853）。

**五层防线**：
1. 每轮重建 system（现成，不动）
2. **注入 `<interview_state>` 状态块**：轨道/轮次/覆盖地图打勾/深度/上次摘要/已采集原话/假设数。固定 ≤400 字符，登记 `CONTEXT_CATEGORIES.SYSTEM_PROMPT`（useChatEngine.js:1827-1838）。**模型几乎从不正确数轮次，所以进度必须喂。**
3. **规则分三层**：L0 硬护栏（一次一题/不给选项/危机短路/不暴露术语，4 条）· L1 行为规则（接住再问/钩具体词/深度≤2/说"不知道"就换小）· L2 情景规则（**按状态由代码选 1-2 条注入**，如深度≥2 → "本轮禁止再追问，必须反映"）。全量注入 = 没注入。
4. **末尾锚定**：`finalPrompt` 是 messages 最后一条（useChatEngine.js:1973-1979），注意力最高。结尾放三行「本轮唯一动作 + 当前状态」。
5. **代码守门**：生成前注入（L2）／生成后校验（选项句式、一轮 `？`>1、术语泄露）。

**最易忽略的一条**：`expertState.evidence`（原话摘录）必须**独立于历史摘要**保存并经状态块每轮注入，报告只从 evidence 取原话。否则历史一压缩，报告的依据就没了。摘录规则：每轮新增 ≤1 条、只存可追问的具体原话、上限 8 条。

**重试策略的取舍**：术语泄露 → 记录 + 剥离重生成一次（破坏"被理解"姿态，值得多花一次调用）；多问/选项 → **只记录不重试**（重试打乱节奏且用户已看到打字过程），先用数据判断频率再决定是否升级为硬拦截。

## 心理专家角色 · 实战校准（六级对话失败案例）★重要

**逐条病症**：
| AI 提问 | 病 |
|---|---|
| 你目前最担心的**具体是什么方面**？ | 问卷句式，换任何话题都能套 |
| 如果没达到预期，你认为**会采取什么行动**？ | **要方案**：该追"考不过意味着什么"，跳到"你打算怎么办" |
| **了解到你**感到压力，**并且**打算再考一次。那么…**有没有**哪些环节… | 复述冒充接住 + 双问题 + "有没有"封闭式 |
| 你**通常会**用什么方法来应对？ | "通常"=问习惯不是经历；又在要方法 |
| 当你感到无法应对时，你**通常会做些什么**？ | **同一个问题换个说法再问一遍**（用户已说"没法应对"） |

**根因两条**：① **规则抽象、缺判定与示例**——prompt 写了"钩住具体词""接住再问"，模型把"接住"理解成"复述"，也不知道该钩哪个词；② **助手惯性**——基础模型默认"理解问题→给方案"，正面要求压不住，必须明令禁止。

**改法（已落地 `psychologist.js`）**：
- 四类禁问问句**黑名单**：`你通常会…` / `你会采取什么行动` / `具体是什么方面` / `了解到你…，并且…`
- **接住 ≠ 复述** + 判定标准："如果只是把他刚说的词换个顺序再说一遍，那就是复述，删掉它直接问问题"
- **三组正反对照示例**（考不过呗 / 背单词好难坚持 / 没法应对），"没法应对"那组标注"换个说法再问一遍是最容易被察觉的失礼"
- **硬指标**：一个问题 ≤30 字；一轮只允许一个问号
- **访谈期绝不给建议**（不许"你可以试试/建议你/不如…"）

**通用原则（已沉淀进方案 §17.5）**：**规则告诉模型"要什么"，示例才告诉它"不要什么"。** 描述性规则必须配齐三样：可判定的边界 + 至少一组正反对照 + 出现即违规的黑名单。

**附带结论**：轻量模型（fast）跟不上多规则协议 → `startPsychAnalysis` 已自动升到 pro（找不到 pro 时保持原样，未登录不报错）。

## 心理专家角色 · 第二次实战（分手那次）★关键教训：示例会反向污染

用户第二次贴来真实对话（话题：分手），说"还是没什么用"。**比第一次更糟**，且暴露了我自己造成的 bug。

**症状**：
- **举例式给选项出现 4 次**：「比如是某个具体的场景，或者是一种特别的情绪？」「比如是感到难过、失落，还是身体上有什么反应，比如心跳加速？」「比如找人倾诉、运动、或者做些别的事情？」「是亲密的朋友、家人，还是其他特定的人？」→ 用户开始回单词（「难过」「朋友」），对话退化成勾选题。
- **编造用户心理**（最伤人）：用户只说「朋友」，AI 扩展成「**那些一直陪伴你的老朋友**」（"老""一直陪伴"是用户没说的）；用户只回「然后呢？」，AI 替他编了一整段「朋友会给你建议，有时候只是静静地听你说话，这种被理解的感觉对你很重要」。
- **上一轮刚拉黑的句式照用**：「你**通常会**通过什么方式来排解情绪？」
- **Health 数据被注入**：对话里反复出现「来源 BOH Health 数据」→ 健康连接器被命中（难过/情绪/心情触发 `HEALTH_TRIGGER_KEYWORDS`），**sandbox 还没接线**，实证了检索隔离的必要性。

**根因（我的错）**：上一轮我写的「✓ 正确示例」是
> ✓「考不过」——你是已经考过一次没过，**还是**觉得这次也悬？

**这个"好例子"本身就含「还是」，等于在教模型用二选一句式。**→ 通用教训：**给模型的示例必须自查是否含被禁的模式（安全示例会反向污染）。**

**已改（`psychologist.js`）**：
1. 修示例反污染：两个含「还是」/双问句的 ✓ 例子改成单问句（用 python 正则定位行再 replace，避开中文引号匹配问题）。
2. 新增**第五类禁问：举例式选项**，铁律「问题里出现『比如』『例如』『还是』『或者』就算违规」。
3. 新增**【只能用他说过的话】**（不编造铁律 + 判断标准「把他写的每句对照他的原话」）与**【他只回了一个词时】**（不许换维度，把那个词展开）。

**新增 `src/views/BOHAI/expert-roles/guards.js`（守门器，纯函数）**：检测 4 类违规（举例式选项 / 一轮多问 / 术语泄露 / 访谈期给建议）+ 生成重写指令。**不做"编造"的自动检测**——那需要语义判断，正则误报会伤正常回答（假阳性比漏检更糟）。测试 15 项（样本全部取自两次真实对话的原句，含"引号内『还是』不误报"）。

## 对话质量探针（probe-psych-dialog-quality.mjs）+ 额度耗尽事故

用户："你能不能帮我来跑对话质量测试？比如你来和AI对话" → 写了「扮演来访者逐轮对话并自动判分」的探针。

**探针设计**：9 轮剧本，**每轮针对一项具体能力**（给具体事件 / 回一个词 / 说不知道 / 绝对化 / **递出例外** / 自我矛盾 / 表达不适 / 主动换话题 / 要求出报告）。判据直接 `import` 产品里的 `guards.js`（测的就是产品真正用的标准），再加"是否钩住上一句"（`expectHook` 关键词命中）与"重复上一问"（二元组相似度）。

**首次试跑（额度尚存时）抓到两个真问题**：
1. **轮 3 完全重复了轮 2 的提问**：我回「烦。」→ AI 问 X；我回「不知道，想不起来了。」→ AI **又问了一遍 X**。这正是用户上次被气到的那类。"我不知道"这种输入最容易被换个说法重问。
2. **每轮回答后都挂一句「未检索到相关站内资料，以上回答基于通用知识」** —— sandbox 主动关闭检索后，兜底逻辑误判成"没找到资料"。心理访谈里出现这句很出戏。

**已修**：
- `guards.js` 新增 `VIOLATION_TYPES.REPEAT` + `similarity()`（二元组重合率）+ `REPEAT_SIMILARITY_THRESHOLD = 0.7`，**算硬违规**（触发重写）。阈值取高是防误报——正常承接本来就会复现几个词，误报会让守门频繁重写（多一次调用 + 明显延迟），比漏检更伤。`detectViolations(text, { prevReply })` 第二参数，向后兼容。接线处传 `session.messages[messageIndex - 2]?.content`（当前 assistant 之前最近的一条）。
- `useChatEngine` 检索兜底提示：`psychInterviewActive` 时不加那句尾巴。
- guards 测试 15 → **20 项**全绿。

**⚠️ 事故：把用户今日 BOH AI Token 额度跑完了**
前 4 轮试跑 + 完整 9 轮 → 额度耗尽。更糟的是**第 2 轮之后全是「服务暂时繁忙 / 今日额度已用完」，却被当成 AI 的回答评分**，汇总"8/10 有问题"里 **7 个是假的**（错误提示逐字相同 → 被判"重复上一问"）。

**两条硬教训（端到端真实调用的通用规则）**：
1. **评分探针必须识别错误响应并立即中止**，否则报告全假。已加 `ERROR_PATTERNS`（服务暂时繁忙/额度已用完/请稍后重试/网络异常…）+ `aborted` 状态 + 汇总里显式说明中断轮次不计入。
2. **跑真实调用前先评估额度消耗**（轮数 × 2，因为守门命中会重写多一次调用），并先跟用户确认。9 轮看着不多，加上试跑就爆了。

**探针的能力边界（重要）**：它能测的是**机械规则**（一轮多问 / 给选项 / 重复上一问 / 泛化提问 / 给建议 / 是否钩住关键词 / 报告结构）。**测不了"问得聪不聪明"** —— 后者只有真人（或另开一个模型做评审）能判断。所以最终质量还是要靠用户点着试。
