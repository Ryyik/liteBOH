## BOHAI 积分倍率设计审查（只读 CLI 查库，未改任何代码）

三层倍率真源：`bohai_model_configs.quota_multiplier`（模式：fast=0 免费模型 / Air=3 / Code=5 / Ultra=10 / gemini=15）→ `ai_quota_config.points_multiplier`（档位折扣 plus .95/pro .90/max .85/ultra .80）→ `ai_pricing_config`（1 积分=100 万 billed tokens，日烧上限 20 分，**已启用**）。公式 = ceil(total×模式倍率)×档位倍率/1M，小数计量满 1 扣整（`profiles.ai_points_fraction`）。

**🔴 实锤 bug：档位折扣在结算时从未生效。** 预扣 `reserve_ai_points` 收档位倍率（有折扣），但 vault `logTokenUsage` → `settle_ai_points(p_multiplier: quotaMultiplier)` 传的是**模式倍率**（api-key-vault/index.ts:1929、调用点 1183/2307），pointsMultiplier 根本没进结算 → 会员按全价被扣，而订阅页 `PLAN_AI_POINT_MULTIPLIERS` 与 AiQuotaSidePanel 都在宣传折扣（宣传与实现两套数字）。线上函数体已核对确认。修法：reservePointsForQuota 成功时把档位倍率挂到 quota 对象，结算传 `quotaMultiplier × pointsMultiplier`（两个调用点都要）。生产尚无 ai_usage 流水（bug 还没咬到人，属潜伏）。

其余发现：① 折扣幅度 0.95~0.80 在 1M/分汇率下不可感知（一条 gemini ≈0.04 分，5% 折扣攒 400 条才差 1 分）——要么拉大梯度要么砍展示；② vault `MODE_TOKEN_MULTIPLIERS{pro:2,max:3,ultra:4}` 与 SQL fallback 是僵尸配置（这些 mode_id 线上已不存在，现在叫 Air/Code/Ultra/gemini），注释还写着 keep aligned；③ 定价阶梯不自洽：Ultra 上游 openrouter/free（免费）却挂 10×，比 Code 5× 贵一倍、min_tier=free，同免费上游的 fast=0 差 10 倍无解释；④ 面板「今日已耗」只统计整分流水（pointsUsedToday），尾数 ai_points_fraction 不可见 → 低用量用户永远看到 0 以为没扣费；⑤ earn 侧签到 5 分/笔，cap 20/天 ≈ gemini 500 条，风控参数合理。另核实：0 倍率三端一致（2026092906 已把 SQL 下限 greatest(0.1→0)，0=免费模型不占额度不扣分，仓库与线上一致）。

### 8 条逐条取证后的结论（全部为真问题；其中「Tab 未改」与「资产 tab 没出现」同根）

1. **发帖遮罩「消失了一半」** — 根因不是模糊描述的那种：`replies-responsive.css` 里
   `.mobile-composer-overlay` 写的是 `height: calc(100dvh - var(--kb-inset))`，
   一旦 `--kb-inset` 量出偏大值（真机键盘高度），遮罩只剩半屏、下半屏**露出底下的论坛页面**。

   修法：高度恒为 `100dvh`，改为 `padding-bottom: calc(env(safe-area-inset-bottom) + var(--kb-inset))`
   用内边距抬升。**抬升靠内边距、不靠减高度** —— 这是可复用的判据。

## 第四轮：Cloud+ 图库改成「真机相册式」网格

用户先问「是那种直接连接在一起的网格？类似真实的手机相册」，确认后「开始改吧」。

**接手前的实际状态**（并行会话已做完大半）：`.album-tile-grid` 已是 `display:grid` + 月份分组
（`.album-month-list/group/heading`，标题吸顶）+ 照片格 `.gallery-tile` / 文字格 `.tile-paper`。
≤640px 已是 `repeat(3, minmax(0,1fr))` + `gap:2px`。**差的只有「真机味」三条**：

| 项 | 改前 | 改后 |
|---|---|---|
| 圆角 | 桌 12px / 手机 6px | **0**（`gallery-tile` + `tile-paper` 都归零） |
| 通栏 | 左右各留 16px（像嵌在白卡里） | ≤640px 用 `margin-inline: calc(-1 * var(--cloud-gutter))` **通栏贴边** |
| 缝隙 | 桌 8px / ≤900 6px | 桌 **4px** / ≤900 与 ≤640 **2px** |

**过程中做的三个判断**：
1. **缝隙用 2px 而不是 0**：iOS 相册本身就是「2px 背景色薄缝」不是真零缝。给 0 只能靠 1px 描边
   模拟分隔，深色主题下描边显脏，而且**末行残缺时露底色块**（grid 背景技巧的通病）。
2. **纸片格去掉 border**：2px 缝里相邻两格各带 1px 描边会叠成 2px 深线，与照片格的白缝不是同一种
   分隔；改成纯浅底（`--apple-bg-secondary`）区分。
3. **横向留白抽 `--cloud-gutter`**：通栏要拿它做负 margin，和 `.cloud-shell` 的 padding 必须同值，
   不让 16px 在文件里出现两遍。
4. 顺手把**骨架屏改成同形方块**（原骨架还是旧卡片网格的「圆角卡 + 日期/标题/正文行」，
   数据到达时会从圆角高卡突变成直角方格，闪一下）。

**自证**（390×844 / 1280×900，mock 14 条数据，因为探测账号 0 条内容）：
竖屏 `cols=128.656×3` `gap=2px`、网格 `w=390 == 视口` `left=0 rightGap=0`（通栏成立）、
每格 `129×129` `radius=0px`；桌面 6 列 `gap=4px` `radius=0px`；两档 `overflowX=false`（负 margin 没撑出横向滚动）。
`npm run verify` EXIT=0；lint 183/183；2276 测试全过；dark-tokens 2865/2865（本次是纯改颜色变量，计数未动）。

## 第五轮：Cloud+ 竖屏顶栏修复 + 设置/分享页液态玻璃与极简排版

### A. 顶栏工具行（用户截图报障「筛/选」「刷/新」竖排 + 蓝按钮被切）

根因链（390×844 实测，三条连锁，**同一处 `flex-wrap: nowrap` 引发**）：

| # | 现象 | 机理 |
|---|---|---|
| ① | 搜索框只剩 **30px**（内部 input 宽 0），placeholder 与输入全不可见 | 工具行强制一行，`.gallery-search-field { flex: 1; min-width: 0 }` 被压到极限 |
| ② | 「筛选」「刷新」文字折成三行（h=69）→ 竖排「筛/选」 | 这两个是 `.refresh-btn`，**没有** `white-space: nowrap`（`.primary-btn` 有） |
| ③ | 「＋新建」right=**518**（视口 390），右半边被祖先 `overflow` 裁掉 | 继承本档 `.primary-btn { width: 100% }`（**在 ≤640 块，不是 ≤900**，见 style.scoped.css:2895）又自带 `flex-shrink: 0` |

修法：工具行折两行（搜索框 `flex: 1 0 100%` 独占第一行，三个按钮第二行 `flex: 1 1 0` 平分），
全部补 `white-space: nowrap`，工具行里把 `.primary-btn` 还原成 `width: auto`。
⚠️ 那三条 `width: 100%` 是给 `.toolbar-actions` 两列网格的「分享/保存」用的，**不能**全局删，只能局部还原。

### B. 设置页 / 分享页改成液态玻璃 + 极简排版

用户原话「分析页面和设置页面」——Cloud+ 底栏其实只有 `内容/分享/设置` 三席，**没有「分析」**，
按「分享」页理解并同步做了。改动：4 个卡片挂 `.liquid-glass`；存储条去掉自己的「蓝→白」渐变实底；
≤900 与 ≤640 两处 `.sidebar-card { background: var(--apple-bg-secondary) }` 加 `:not(.liquid-glass)` 让位；
圆角统一到 `--liquid-radius-lg`(28)。排版：删掉 3 条同义文案（分享页「只有拿到令牌的人可以查看」
说了三遍）+ 设置页重复的额度说明（与存储条 hint 同义），配额卡 hint 整条删除。

**四条实测教训（已写进 AGENTS.md / PROBES.md）**：
1. **玻璃只能挂 `.liquid-glass` 基础类**：`--subtle/--strong/--inset` 变体在 ≤768px 被 liquid-glass.css
   强制 `backdrop-filter: none` + `var(--liquid-bg-strong)`（近实白），竖屏下等于没有玻璃。
2. **scoped 特异性 > 全局类**：`.sidebar-card[data-v-x]`(0,2,0) 高于 `.liquid-glass`(0,1,0)，
   所以任何 `background:` 都会把玻璃盖回去。**症状是「backdrop-filter 生效了但卡片还是 #f5f5f7」**
   —— 我第一次就踩了，靠「递归遍历 styleSheets + el.matches」才定位到是 ≤900 那条（不是我以为的 ≤640）。
3. **白底上玻璃不可感知**：白玻璃 + 纯白底 = 白，只剩阴影，卡片边界反而比原来的浅灰实色卡更弱。
   故给 `.cloud-page::before` 铺一层极淡环境光（`color-mix(in srgb, var(--apple-blue) 11%/6%, transparent)`）。
   `isolation: isolate` 是必需的，否则负 z-index 伪元素掉到 body 背景之下、整层不可见。
   色值走 `color-mix` + 既有 token → 暗色棘轮计数不变（2865/2865）。
4. **Cloud+ 整页零暗色适配**（既有缺陷）：`.cloud-page` 把 `--apple-*` 全套硬编码成亮色，
   文件里 `[data-theme="dark"]` 出现 0 次 → 暗色下这页本来就是「亮页面」，
   连带 **顶栏标题被 UserCenterPageHeader 的暗色规则改成白字、落在白底上不可见**。
   所以玻璃在暗色下**主动退回**页面实色底（不能跟着 `--liquid-*` 切暗，否则变成「亮页面里嵌深灰卡」）。
   正解（补一整套暗色 token）属独立一轮。
