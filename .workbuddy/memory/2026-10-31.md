## 坑：`.git/hooks/pre-commit` 被留成**指向临时目录的悬空软链**

`ls -la .git/hooks/pre-commit` → `-> /private/var/folders/…/T/boh-prepush-XXXX/scripts/git-hooks/pre-commit`，
临时目录早被清掉 ⇒ `test -e` 为假。git 执行提交时直接报
`cannot run .git/hooks/pre-commit: No such file or directory`，看起来像「钩子挂了」，其实是装错了。

成因：某次 prepush/门禁自检把钩子**软链到临时检出**做实验，实验结束没还原。
判据就一条：`test -e .git/hooks/pre-commit || echo 悬空`。
修法（也是新环境的标准装法）：`rm -f .git/hooks/pre-commit && cp scripts/git-hooks/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`
—— 必须是**实体副本**，不要软链回 scripts/（钩子会被 git 之外的工具改写，软链会反向污染仓库）。

### 🔴 反证「触发器函数不检查 EXECUTE 权限」的正确姿势

收权前必须证明不破功能。**用 postgres 测等于没测**（owner 永远有 EXECUTE）。做法：

```sql
begin;
set local role authenticated;
set local request.jwt.claims = '{"sub":"<author_id>","role":"authenticated"}';
insert into public.posts (content, author_id, status) values ('…', '<author_id>', 'approved');
reset role;
select p.id, (select count(*) from public.mail_outbox m where m.post_id = p.id) from public.posts p …;
rollback;
```

三个坑：
1. 不加 `request.jwt.claims` 会被 `enforce_forum_post_rate_limit` 以 `NOT_AUTHENTICATED` 拦掉
   —— 报错看着像「触发器坏了」，其实是另一道门。
2. **不能按 `content` 数行**：`sync_forum_post_text_fields`（BEFORE INSERT）会把正文改写
   （实测被加上 `【无标题】\n` 前缀）⇒ `where content='…'` 恒 0，会误判成「没插进去」。要按 `returning id` 数。
3. `authenticated` 对 `mail_outbox` 没有 SELECT ⇒ 诊断查询必须在 `reset role` 之后跑，
   否则报 `42501 permission denied for table mail_outbox`，同样会误判成收权把功能弄坏了。

实测结论：以 `authenticated` 身份插入**不报 42501**，且 AFTER 触发器真的写了 2 行账本 ⇒ 前提成立。

## 🔴 push 被代理拦：`Connection closed by 198.18.0.46 port 443`

`198.18.0.0/15` 是 TUN 模式代理的 fake-IP 网段 ⇒ DNS 把 `github.com` 解析成假 IP，
SSH 直连被代理端直接关掉（`fatal: Could not read from remote repository`，看着像没权限）。
**跟沙箱无关**，沙箱内外一样；`ssh -T git@ssh.github.com` 也会同样失败。

绕法（本机 Clash 混合端口 7890）：让 ssh 走 HTTP CONNECT 隧道，不再碰 fake-IP 路由。

```sh
git -c core.sshCommand="ssh -o ConnectTimeout=20 -o ServerAliveInterval=10 \
  -o ProxyCommand='nc -X connect -x 127.0.0.1:7890 %h %p'" push origin main
```

注意：**第一条命令仍可能失败**（`Connection closed by UNKNOWN port 65535`，代理掐长连接），
重试 1–2 次即通 —— 不要因为第一次失败就判定通道不可用。
先用 `ssh -T -o ProxyCommand=... git@github.com` 单独验通道（返回 `Hi <user>!` 即通）再 push。
⚠️ 别把 ProxyCommand 写进 `.git/config` 或 `~/.ssh/config` 持久化：代理端口是动态的，换环境会静默挂掉。

**`ssh -T` 通 ≠ `push` 通**。`ssh -T` 一次就成功，但 `git push` 连续 3 次 `Connection closed by UNKNOWN port 65535`。
第四次加 `-vvv` 才看清：**其实通了** —— 尾部 `read failed: Broken pipe` 是通道收尾噪音，
真正的判据是 `debug1: Exit status 0` + `To github.com:... 66a8f4cc..9731579b  main -> main`。
⇒ **push 失败时先 `GIT_SSH_COMMAND="ssh -vvv ..."` 看 tail 40 行，别凭一行 fatal 就断定不通**；
`Broken pipe` / `channel is dead` 出现在收尾阶段是正常的（GitHub 侧先关 channel）。

## 🔴 `npm run prepush` 会把 `.git/hooks/*` 改成指向临时检出的软链

**可复现，三次实测（22:14 / 22:17 / 22:19）**：每跑一次 `npm run prepush`（含 pre-push 钩子里的
`--quick`），`.git/hooks/pre-commit` 与 `pre-push` 双双变成
`-> /private/var/folders/.../T/boh-prepush-XXXX/scripts/git-hooks/pre-commit`；
worktree 跑完被删 ⇒ **软链悬空** ⇒ 之后任何 commit 报 `cannot run .git/hooks/pre-commit`，
push 报同样错。`scripts/prepush.mjs` 里**没有**建钩子的代码（只有 `node_modules` 那处 `symlinkSync`），
`grep -r "hooks/pre-commit|symlinkSync|core\.hooksPath"` 也只在文档里命中 ⇒ 是外部工具（IDE/客户端）
在临时检出上装钩子，**不是仓库代码的锅，改 prepush.mjs 治不了**。

纪律：**每次跑完 prepush 或 push 之后，先查钩子再干活**：
```sh
ls -l .git/hooks/pre-commit .git/hooks/pre-push          # 看到 `->` 就是悬空了
rm -f .git/hooks/pre-commit .git/hooks/pre-push
cp scripts/git-hooks/pre-commit scripts/git-hooks/pre-push .git/hooks/ && chmod +x .git/hooks/pre-*
```
**不能**用 `git config core.hooksPath scripts/git-hooks` 一劳永逸：那会接管 hooksPath，
让 `.git/hooks/post-commit`（Qoder tracker）静默失效 —— AGENTS.md 刻意不用 husky 就是这个原因。

## 🔴 `check:doc-truth` 是**提交树**口径，改数字必须按「提交之后」的树算

`trackedCount()` 走 `git ls-tree -r --name-only HEAD` ⇒ 数的是 **HEAD 树**，不是工作区。
后果（本日实证）：把 284→285 时，新增的 `data-admin-page-tab-wiring.test.js` 和两个 src 文件
还在**未跟踪**状态 ⇒ HEAD 树里看不到 ⇒ `verify` / `verify:fast` 全绿，**一提交数字整体上涨**
（285→286、588→590），`prepush` 立刻红，而且报错在「提交树」上，容易被误读成「源码有问题」。

纪律：**动 `src`/`tests` 文件数量的提交，先算「提交后的树」**：
```sh
git ls-tree -r --name-only HEAD -- tests | grep -c '\.test\.js$'   # 提交前先 +1 心算本次新增
```
或提交后立刻 `node scripts/check-doc-truth.mjs` 复核再 prepush。
（`--update` 类基线同理：一律在提交树口径上做。）
