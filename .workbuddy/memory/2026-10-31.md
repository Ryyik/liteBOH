## 论坛动效「从哪来，回哪去」：方案定稿 `plans/035-forum-motion-continuity.md`

只写方案，未动代码。用户 2026-10-31 拍板「按慢速做」⇒ 节奏表以慢档定稿
（morph 进 640 / 出 480，局部块 240–600，**即时反馈 120–160ms 不参与放慢**）。

读码得到的四条硬事实（改动前必须知道）：
- `--pd-enter-from` 是**死变量**：`style.scoped.css:26` 写着承接方向，全仓没有 JS 写过它。
- `App.vue:452-468` **刻意没有路由级 `<Transition>`**（实测类名从未被加上）⇒ 只能 CSS/WAAPI + JS 传参，别想 shared-element。
- 列表在导航时**卸载**（KeepAlive 只覆盖 `meta.keepAlive`）⇒ 返程目标卡片在详情离场那一刻还不存在，
  纯 CSS 无解，必须 App 级 morph 层接住尾帧（或改 overlay 承载详情）。
- 论坛/详情**完全没用** `tokens.css` 的 `--duration-*`：时长硬编码 4 套（1900/1500/480/340），
  所以「整体放慢」在改之前无处下旋钮。

实施顺序建议：P0（tokens + `utils/motion.js`，视觉零变化）→ P1（局部交互，不碰路由，覆盖 80% 体感）
→ P2 入场 morph → P3 返程 morph（`SharedMorphLayer` + `forum:anchor-ready` + 400ms 降级）→ P4 横屏弹窗。

三项结构决策已拍板：① 返程上 `SharedMorphLayer`（唯一主路径）；② 横屏弹窗也走 morph；
③ 统一按压基线（`.boh-press` / `.boh-press-sm`）。
