## 变焦能力口径（写进代码注释了，这里只记结论）

- 网页**拿不到物理焦段**（没有 focalLength 之类的 capability）。多摄在系统层
  是 logical camera：多颗物理镜头合并成一颗，App 只提交 zoom ratio，切镜由
  OEM HAL 完成。所以能拿到「合并后的连续范围」，拿不到「有几颗镜头」。
- `zoom.min < 1` 是唯一能确证的光学信号（超广角并入逻辑相机）。
- `zoom.max` 常是**数码**上限（128× 这类）⇒ 封顶 `MAX_USABLE_ZOOM = 10`，
  且只有 `rawMax ≤ 10` 时才把真实上限单独列一档（4.3× 有意义）。
- **iOS Safari / Firefox 完全没有 `zoom` 约束**（`getCapabilities()` 里没这个
  字段），iPhone 上 0.5×/3×/5× 一律用不上，只能数码。平台限制，无 workaround。
- 不要用 `enumerateDevices()` + `deviceId` 切镜头：iOS 只给前后各一路；安卓
  能列多个但 label 不含焦段，且切设备要重建流（黑屏 + 丢 zoom）。

## 🔴 scoped CSS 对 `document.createElement` 创建的元素无效

相机「过片」动画的副本是 `createElement('img')` 建的，写了
`.boh-cam__fly { position:absolute; width:46px; height:46px; left/top: JS 算 }`，
**全部不生效**：Vue 的 `data-v-*` 属性只在模板编译时写入，动态创建的元素没有它，
`.boh-cam__fly[data-v-xxx]` 匹配不上。表现是 `<img>` 按整屏宽渲染、停在 (0,0)，
用户看到「屏幕左边闪过一片画面」而不是「一张小卡飞进口袋」。

- 判据：`getBoundingClientRect().width` 等于容器宽（390）而不是声明值（46）。
- 修法：动态元素的**尺寸/定位/外观全部走内联 style**；class 只留作测试钩子。
- 连带：`.boh-cam__fly` 的 CSS 块已删并留注释，别搬回去。

## 🔴 `position: fixed; left: 50%` + `width: auto` 的可用宽度只有一半

图库选择条「全选/取消」文字竖排的真因（不是字体、不是 flex 配置）：
`left: 50%` 时 shrink-to-fit 的 **available width = 视口宽 - left = 195px**（390 视口），
而「已选 N 张 / 取消全选 / 取消 / 删除」需要约 270px ⇒ flex 把按钮压到
min-content，中文逐字竖排（实测「取消」被压成 15px 宽、36px 高）。

- 修法：`width: max-content` + `max-width: calc(100vw - 24px)`，并给子项
  `white-space: nowrap`（竖排比溢出更难读）。
- 通用判据：fixed + 只给 left 不给 width 的居中浮层，**可用宽度永远只有一半**。

## `navigator.share()` 可能永不 resolve

「存到本地」优先走系统分享（唯一能进相册的 Web 路径），但 share() 在用户划走
面板/系统不响应时可能一直挂起，`isSaving` 卡 true ⇒ 按钮永久 disabled（实测）。
必须 `Promise.race([share(), timeout(15s)])`，超时按「已交给系统」处理、
**不要**再退回下载（会重复存一遍）。

## INS 滤镜参数（2026-11-06）

中文「INS 风」＝降饱和 + 提对比 + 干净灰调，对应 IG 的 **Ludwig**，不是
Clarendon（提饱和）。`brightness 1.03 / contrast 1.16 / saturate 0.82`，
冷灰 overlay 0.12，grain 0.04 / vignette 0.03（全表最低 —— 有颗粒或暗角就变胶片）。
离屏渲染实测：饱和度 0.374→0.334、lumaStd 0.227→0.243。位置紧跟 CCD。
