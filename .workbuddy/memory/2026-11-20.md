### ① 分享丢链接的真因
`navigator.share({ title, text, url })`：部分系统面板目标（微信「发送给朋友」、
部分安卓机型「复制」）**只读 `text`、丢掉 `url`**。修法：把链接拼进 `text`
（`标题 · 奖品\n<url>`），两条通道（原生 share / 剪贴板降级）拿到的文本都自带 URL。
—— 这是通用坑，站内其他 `navigator.share` 调用（ContentDetailIsland / MBTI）同款隐患。

  删掉了面板里的 `LotteryDetailSheet` / `joiningId` / `message` / `lottery-toast` 一整套。

## 全站文字分享收敛到 buildSharePayload（同日第二部分）

「分享丢链接」不是抽奖独有，站内三处文字分享都有：
- `ContentDetailIsland`（新闻/活动详情岛）：text 只有标题，降级复制**只写裸 URL**。
- `MBTI`：原生 share 的 text 不带链接，只有降级路径手拼过 `\n${url}` —— 两通道两份文案。
- 抽奖详情：上一提交是就地手拼。

**统一真源**：`src/composables/useShareTarget.js` 的 `buildSharePayload({title, text, url, summary})`
⇒ 返回 `{title, text, url}`，**text 恒以 `\n<url>` 结尾**（url 为空时不拼、不出 undefined）。
优先级：text → summary → title。**任何调用点都不许再手拼分享正文**。
`Camera` 的 `navigator.share({files})` 是分享文件，未动。

守卫：`tests/unit/share-payload-link.test.js`（8 条**直接调函数**的行为断言，不做字符匹配）。

### ⚠️ 踩到的坑：prettier 整文件重排 → 提交被放大到 410 行
`ContentDetailIsland.vue` 与 `MBTI/index.vue` **在 HEAD 上本来就不符合 prettier**
（实测 `prettier --check` 对 HEAD~1 版本报 warn）。只要一提交这两个文件，lint-staged
必定整文件重排 ⇒ 语义 6 行的改动变成 192+/162+，还污染 blame。
处置：`git reset --soft HEAD~1` → `git restore --staged .` → `git checkout -- <两个漂移文件>`
→ 只用手工 Edit 精准重做 → 重新提交（结果：钩子仍会重排，这是**该文件既有漂移的必然代价**，
不是本次改动没收敛；提交前我确认过改动只有 6/7 行）。
教训：**碰「本来就不合规」的漂移文件时，先 `git show HEAD:<file> | prettier --check` 预判**，
否则没法区分「我改了 6 行」和「我顺手格式化了 200 行」。
