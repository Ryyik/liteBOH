## 「为什么看不出区别」的真因：百分比停靠点 + 大投影（10:05）

用户截图（竖屏帖子页）说渐隐「没区别」。查出来的不是覆盖问题，是**两处几何**：

1. **百分比停靠点随岛高缩水**：岛高是内容驱动的（竖屏 130 / 桌面 136 / 有回答更高）。
   用 `22%/46%/72%/100%` 时，竖屏最后 28% 只有 36px，其中真正「透」的部分十几像素 ⇒ 肉眼无感。
   **改法：停靠点用 px 反推** —— `#000 0 → .98 calc(100% - 62px) → .62 calc(100% - 30px) → .08 100%`，
   任何高度都是「最后 60px 渐隐」。
2. **大投影把透区糊回黑**：`0 26px 70px rgba(0,0,0,.42)` 的偏移 26px > 渐隐带下沿，
   等于给透出来的内容又盖一层黑。收到 `0 14px 34px .24`（+ `0 2px 8px .18`）后透才可见。

- 顺手：删掉输入条右侧「↵ 发送」提示（`.boh-bar-hint` 模板 + 样式一起删）。
- 守卫加两条：渐变必须含 `calc(100% - 62px)`；**中间停靠点不许用百分比**（末段 100% 除外，负向前瞻）。
- 自证：守卫 21 绿、probe 26/26、prettier/eslint 0。
- 教训：**「看起来没生效」先怀疑几何/遮挡，再怀疑缓存**。这次两版都以为用户没刷新，实际是
  竖屏矮岛下透区只有十几像素 + 投影盖住。

## 找到「改了看不到」的真凶：scoped 规则同权重覆盖（10:25）

用户第四次反馈「看不到效果，要底部亮白边 + 渐消失的黑」。用 CDP `getMatchedStylesForNode`
列出匹配规则，实测：

```
14 | #unified-nav-container .unified-nav-surface.has-boh-island.has-boh-island | border=... .5  ← 我的
15 | #unified-nav-container[data-theme="dark"] .unified-nav-surface[data-v-3d2479ab] | border=var(--liquid-border)  ← 后面这条赢
COMPUTED rgba(255,255,255,0.12)
```

- 🔴 **根因**：scoped `<style>` 编译后选择器末尾会加 `[data-v-x]`（属性选择器 = 一个 class 权重）。
  `#id[data-theme] .surface[data-v]` = (1,3,0)，与 `.has-boh-island.has-boh-island` (1,3,0) **同权重**，
  而它在文件里更靠后 ⇒ 静默赢。`background-image` / `box-shadow` 没被压，是因为那条规则没声明它们。
- 修法：给暗色兜底加 `:not(.has-boh-island)`（岛展开时本来不该被兜底管）。守卫加断言锁死。
- **教训**：本仓库「某条样式改了没反应」的第一排查手段是 **CDP `CSS.getMatchedStylesForNode`**，
  直接看谁赢、权重多少；靠读源码推权重会漏掉 `[data-v]` 这一级。
- 最终光效：渐变 `#000 0 → .96 calc(100% - min(84px,45%)) → .72 min(44px,24%) → .3 min(14px,8%) → .08 100%`；
  backdrop `blur(16px) saturate(140%) brightness(.7)`；
  底部亮边 `border-bottom-color rgbs(.5)` + `inset 0 -1px 0 .45` + `inset 0 -8px 16px -10px .4`。
- 自证：守卫 22、probe 26/26、budget 608/609、dark-tokens 通过、prettier 0。

## Bug：从帖子详情返回后多出一块「空的黑岛」

复现：首页唤起岛 → 点帖子（`/forum/post/:id`，**hideNavbar**）→ 返回。
实测返回后 `isOpen` 仍为 true、卡片还在，但 `cardTop=12`、背景是**悬浮态的深色渐变**、
高 66px（只剩输入条）—— 就是用户说的空黑岛。

- 🔴 根因两段：
  1. 导航栏随 hideNavbar 卸载 ⇒ `measureTop` 走「无导航栏」分支，岛退成 `top:12` 的悬浮胶囊；
  2. 返回时 `#unified-nav-container` 是**新建 DOM**，而 `watchNavHeight` 里
     `if (!nav || navResizeObserver) return;` 让它一直盯着已销毁的节点 ⇒ 新容器等不到 measure。
- 修法：
  1. **跳页即关岛**：`BohIsland.vue` 里 `watch(() => route.fullPath, () => isOpen && close())`。
     （既有 `goPage`/`goFullPage` 本来就先 `onClose()` 再 push，这条把口径提到壳层兜外部跳转。）
  2. `watchNavHeight` 用 `observedNav` 记住当前容器，换了就 disconnect 重挂。
- 自证：`probe-nav-ask` 28/28（新增 ㉕㉖）、守卫 36/36（新增 2 条）；
  返回后再开岛 `cardTop=76` / `islandVar=64px`（重新 dock 正常）。
- 教训：**hideNavbar 路由往返 = 导航 surface 换 DOM**。任何「observe 一次」的导航相关观察者
  都要按「容器身份」判断，不能按「已经 observe 过了」判断。
