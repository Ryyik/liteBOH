HkNumberField 失焦逻辑缺陷：无法清空数值；空值下失焦会静默写入最小值 0
src/views/Health/components/HkNumberField.vue:121-136 · src/views/Health/components/HkLogSheet.vue:72-77
证据：onNumberInput 对空串故意不 emit（注释「等失焦/提交再处理」），但 onNumberBlur 只钳制 props.modelValue（旧值），从不读取输入框当前文本：
const onNumberBlur = () => {
  const clamped = clampToStep(props.modelValue)   // 旧值；清空时仍是旧值
  if (clamped !== null && clamped !== props.modelValue) emit('update:modelValue', clamped)
  emit('change', clamped) }
// clampToStep(null)：Number(null)=0 → 被钳到 min
影响（两个变体）：① 已有值 → 清空 → 失焦：值回弹旧值，用户永远无法置空；② HkLogSheet 专门用 null 表示「未记录」（72-77 行，注释明确「不再用假默认值冒充数据」）→ 打开输入框不输入直接失焦：clampToStep(null) 把 0 钳到 min，静默写入 睡眠 0h / 0 步 / 0 杯——恰好违背该设计初衷。
修复建议：blur 时读取 numEl.value：空串则 emit update:modelValue 为 null；否则再走钳制。
验证方式：通读组件全文 + 两个父组件的 draft 初始化，确认 null 草稿可达（HkBodySheet 经 ?? 170/60 兜底不可达，HkLogSheet 直接可达）。
