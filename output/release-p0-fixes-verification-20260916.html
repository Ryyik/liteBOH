三、过程中纠正的两个假象

假象一：探针「全绿」，但其实两条断言永远不会红。
第一版把「未抛 ReferenceError」写成断言，撤掉修复后它照样通过 —— 因为那种写法把 ReferenceError 也一并吞掉了。两个教训：
① 无差别兜底 catch { return null } 会把编程错误一起吞掉，用户仍只见「点了没反应」且监控收不到；已改为按错误特征分流，其余 throw err。
② 断言「没有错误发生」远不如断言「行为正确」可靠，已把那两条换成报告真正要求的验收项（编辑/删除各成功执行一次、失败回滚）。
假象二：删除接口「请求成功但列表不更新」。
排查后是探针自己的 mock 缺了一条响应头。Content-Range 不在 CORS 安全列表里， 跨域下浏览器不会把它交给脚本，supabase-js 的 count 恒为 null， delete({ count:'exact' }) 就被判成「不存在或无权限」而回滚。 更阴的是 page.on('response') 在 CDP 层看得到该头，日志一片正常。 修法是 mock 里加 Access-Control-Expose-Headers: Content-Range。
