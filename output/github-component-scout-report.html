Open Source Scout Report

方块之家（BOH）开源组件探查报告

基于当前项目的技术栈与产品定位，从 GitHub / npm 生态中筛选可直接集成的开源组件与插件， 按推荐优先级分档，逐项给出仓库链接、核心能力、契合点、集成可行性、收益与替代方案。

采样日期 2026-09-14 评估候选 46 个 采纳推荐 18 个 数据源 GitHub API · npm registry 项目版本 BOH Beta 6.1.1

01结论摘要

扫描结果指向四类最值得投入的方向：长列表性能、工程卫生自动化、 停更依赖替换、校验规则单一源化。这四项的共同特征是——不需要改动架构， 但能同时缓解项目已知的历史痛点。

三个最关键的发现
  • 全仓没有任何虚拟滚动实现（0 处命中）。论坛、消息中心、活动墙都是「分页 + 全量渲染 DOM」，这是当前最明确且修复成本最低的性能缺口。
  • html2canvas@1.4.1 已停更 4 年（最后发布 2022-01-22），而它承载的是海报生成 / 分享卡这条传播链路——属于需要主动替换的技术债。
  • 项目自建了 11+ 个弹层组件且历史上出现过滚动锁残留、焦点回收、层叠顺序问题；无头原语库能把这一类问题整体消掉，同时不触碰现有视觉体系。

02项目画像与集成约束

选型建议的边界条件——不满足这些前提的组件一律没有进入推荐清单。

维度现状对选型的影响
技术栈 Vue 3.5.24 · Vite 7 · Pinia 3 · Vue Router 4（hash）· Supabase · TS 渐进接入 必须原生支持 Vue 3.2+ 且提供 ESM / TS 类型；不支持 Vue 2 遗留方案
模块解析 moduleResolution: bundler 可用 exports 子路径（如 virtua/vue），不会被 node 模式卡住
包体积闸门 单 JS chunk ≤ 800KB，dist 总计 ≤ 30MB（check-bundle-size.sh） 图表 / 高亮 / 编辑器类必须按需引入 + 异步 chunk，禁止整包 import
样式体系 玻璃单一源 --liquid-*；组件 scoped；禁用 :global()／全局 :deep()；!important 有棘轮预算 优先「无头 / 无样式」库；自带整套皮肤的库接入成本会显著抬高
质量门禁 check:views / check:structure / check:liquid-glass / check:important-budget 已进 build:ci 新增工具应能挂进同一条门禁链，而不是另起一套流程
测试现状 E2E 探针（probe-*.mjs）极丰富，单测偏少 补测试类依赖的收益高于新增 E2E 能力

产品定位 方块游戏文化社区：论坛 / 新闻 / 活动 / 商城积分 / 订阅会员 / AI 助手 BOHAI / 管理后台 / PWA 优先级向「内容消费链路 + 运营后台 + 增长传播」倾斜

核心功能

替代 / 注意

04选型注意事项汇总

以下五点若不守住，前文所有收益都会被抵消。

1. 体积：任何新库都不许进主 chunk

单 JS chunk 闸门 800KB、dist 30MB 是硬约束。图表、高亮、编辑器、PDF 一律走 defineAsyncComponent + 动态 import；引入前先用 rollup-plugin-visualizer（已装）看清增量。

2. 真相源：新库不能变成「第四处定义」

这是本项目最容易踩的坑。具体红线：① zod schema 与现有手写校验并存 → 必须择一迁移；② vue-query 缓存与 Supabase Realtime 订阅并存 → 必须显式 invalidate；③ reka-ui 与 floating-vue 的 Tooltip 功能重叠 → 二选一；④ 可观测性不要同时上报两套系统。

3. 样式：无头优先，别引入整套皮肤

项目玻璃体系单一源 --liquid-*，且禁用 :global() / 全局 :deep()、!important 有棘轮预算。自带整套皮肤的库（Element Plus / PrimeVue / Vuetify 等）接入后会与现有体系正面冲突，本报告已全部排除；shadcn-vue 虽可用，但要注意其 Tailwind 使用习惯与项目「Tailwind 仅 preflight」的现状差异。

4. 交互冲突：虚拟滚动 × 列表动画 × 拖拽

virtua（绝对定位 + 尺寸测量）、auto-animate（FLIP transform）、vue-draggable-plus（DOM 重排）三者共用同一列表时会互相破坏定位。规则：同一列表只选一种增强方式；虚拟列表内不要叠加 FLIP 动画。

5. 维护状态：区分「停更」与「稳定」

npm 发布距今久 ≠ 不可用。html2canvas（2022 年停更、且还在被依赖）属于需要替换；comlink（2024 年停更但 API 极简稳定、周下载 190 万）属于可接受；headlessui（28.7k★ 但 Vue 侧停滞）、exceljs（2024-12 后无发布）属于谨慎引入。判断标准是「是否还有未修复的活跃缺陷」与「是否有同类活跃替代」。

评分口径：契合度 5.0 = 直接命中已确认的痛点且与定位强相关；4.0–4.5 = 明显补强但非阻塞；3.0–3.5 = 场景化，需要时再取。 维护健康 5.0 = 近一周内有提交 + 高下载量 + 活跃发布节奏；4.0–4.5 = 活跃或高采用度；3.5 及以下 = 发布放缓、issue 偏多或社区规模有限，引入前需评估替代方案。

未纳入本报告的类别：自建体系已覆盖且无明显缺口的领域（日期处理、图标、状态管理、PWA、图片裁剪压缩、验证码、Markdown 渲染、XSS 净化）未重复推荐； 自带整套 UI 皮肤的组件库（Element Plus / PrimeVue / Vuetify / Naive UI）因与现有 --liquid-* 玻璃体系冲突而整体排除。
