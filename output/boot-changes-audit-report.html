P2骨架的暗色分支是死规则，且暗色用户首帧整屏白闪

实地逐帧实测（probe-verify-boot-changes.mjs，暗色 boh-theme=dark）
首帧 t=41ms  : theme=null  bootBg=rgb(255,255,255)  bodyBg=rgb(255,255,255)  hasBoot=true
t=87ms       : theme=dark  hasBoot=false（骨架已被 Vue 清空）
骨架存活 2 帧，其中处于暗色主题的帧数 = 0
根因

src/main.js:288 先 app.mount("#app")，主题管理器 themeManager.init() 在 src/main.js:310 才执行；src/utils/theme-manager.js:89 此时才 setAttribute('data-theme', theme)。骨架 <style> 里的 4 条 html[data-theme="dark"] … 规则依赖该属性，因此在首帧必然拿不到。

影响
  • 暗色用户（localStorage['boh-theme']='dark'）在骨架窗口看到整屏 #ffffff，随后切黑 —— 骨架窗口越长（弱网正是骨架的目标场景）白闪越明显。
  • 4 条暗色规则 从不生效，属死代码：后续维护者会误以为暗色已被处理。
修复方案（推荐 A）

A（推荐，一处内联脚本，顺带修掉全站暗色 FOUC）：在 index.html 的 <head> 最前、骨架 <style> 之前插入最小内联脚本：读 localStorage.getItem('boh-theme')，'system' 时用 matchMedia('(prefers-color-scheme: dark)') 解析，命中 VALID_THEMES（light / dark / home-cat / anniversary-mc）就用自身，然后立即 document.documentElement.setAttribute('data-theme', t)，并把 html 背景设成对应底色（#ffffff / #0a0a0f）。themeManager.init() 之后会用同一份 localStorage 再设一次，语义一致、无冲突。

B（兜底）：若不想在 index.html 增加脚本，则删除骨架里 4 条暗色规则，明确「骨架恒为浅色」，至少不留死规则与误导。

验证：node probe-verify-boot-changes.mjs → 首帧 theme 应为 dark、bootBg 应为 rgb(10, 10, 15)。

P2骨架的「假导航胶囊」与真实导航栏几何、视觉都不一致

实测对比
骨架 .boh-boot-nav   : 720 × 72 @ (left 280, top 10)  圆角 999px  背景 rgba(0,0,0,.05)
真实导航栏(默认态)    : 1280 × 72 @ (0,0)              无圆角      白底 + 1px #f0f0f0 底边
真实导航栏(滚动后)    : 860 × 58（unified-nav.css 的 .scrolled 规则，圆角玻璃胶囊）

另外：正常网络下骨架只存在 2 帧（41→87ms），说明真实导航栏（ui-components 在预缓存内）几乎与骨架同时到达 —— 假导航的"占位"作用非常有限。

影响

加载窗口出现「居中灰色胶囊 → 全宽白色条」的形态跳变；比起不画导航，一个与真实 UI 不一致的假控件反而更容易被用户察觉。

修复方案（需视觉拍板）

A（推荐）：删除 .boh-boot-nav 及其 CSS，骨架只保留主体三点 spinner。导航栏交付给已有预缓存的 ui-components（实测 87ms 就位）。收益：少一个假控件、少 4 处需维护的几何常量。

B：对齐默认态 —— 全宽、height: 72px、border-bottom: 1px solid #f0f0f0、无圆角、白底（暗色 #0a0a0f + 同亮度分隔线）。

验证：probe-verify-boot-changes.mjs 输出的「→ 几何差」一行；方案 A 应打印 null，方案 B 宽度差应为 0。

P2骨架文字色跨语义层混用；index.html 内联样式是门禁盲区

证据
  • 骨架 .boh-boot-text：浅色 #8b9098 = --liquid-text-tertiary（浅）；暗色 #a1a1a6 = --liquid-text-secondary（暗）—— 而 tertiary 的暗色值是 #8a919c。同一元素明暗两档取了不同语义层，暗色偏亮一档。

修复方案

① 把 #a1a1a6 改为 #8a919c（与浅色档同为 tertiary）。

② 新增门禁 scripts/check-boot-skeleton-tokens.mjs：断言骨架里登记的色值 === tokens.css 对应 token 的值（同一份「色值 → token 名」映射表），并断言骨架 <style> 在文档中早于任何 <link rel="stylesheet">（防止将来被挪到全局 CSS 之后而失效）。挂到 build:ci。

验证：故意改错骨架一个色值 → 门禁必须报错。
