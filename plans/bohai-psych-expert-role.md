# BOHAI 心理专家角色 · 设计方案 v4

> 目标：让 BOHAI 以「心理专家」的身份做一系列**实时推进**的心理访谈，逐步积累成一份属于用户自己的性格画像——既更了解自己，也能规划方向。
> 定位：**角色（Expert Role）**，不是引擎模式（Mode）。
> v4 变更：轨道从 3 条扩为**「6 条探索轨道 + 1 份综合画像」**；新增**认识论分层**（观察 / 可能 / 假设）与**滚动画像卡**（跨轨道累积）。

---

## 0. 一句话结论

把 `RESPONSE_STYLE_OPTIONS` 里的 `psychologist`（`chat-engine-config.js:272-293`）升级成一个**带提问工具箱、7 条轨道、实时决策规则、认识论分层和跨会话画像**的专家角色。角色 id 不变 → 零迁移成本、不碰数据库。

三层结构，各管一件事：

| 层 | 是什么 | 作用 |
|---|---|---|
| **轨道** | 6 条探索 + 1 份汇总 | **问什么**（选题） |
| **实时推进引擎** | 信号表 + 决策优先级 | **怎么问**（方法） |
| **认识论分层 + 画像卡** | 观察 / 可能 / 假设 | **怎么记**（可信度与累积） |

它们互相正交——引擎服务全部轨道，分层与画像卡贯穿全部轨道。

## 1. 为什么不能是固定题目，也不能给选项

| | 清单 / 问卷（PHQ-9、MBTI、固定题库） | 访谈（interview） |
|---|---|---|
| 前提 | 答案在预设范围里 | 答案在对方那里，且尚未成形 |
| 问题从哪来 | 事先写死 | **依据上一句现场生成** |
| 输出 | 分数、类型、标签 | 语言、意义、例外、方向 |

1. **不能给选项**：选项会锚定答案范围、用标签替代情节，而且**让向下箭头类追问彻底失效**——你没法追问一个自己提供的选项。
2. **不能是固定题目**：清单不知道用户上一句说了什么；最值钱的信息（"有次我做海报做到十一点没停"）会被下一道题埋掉。**题目不是资产，决策规则才是资产。**

## 2. 提问技术的依据（专业底座）

| 技术 | 出处 | 什么时候用 |
|---|---|---|
| **OARS**：开放式提问 / 肯定 / **反映性倾听** / 摘要 | Miller & Rollnick，动机式访谈 | 全局语言层；反映性倾听是"接住再问"的来源 |
| **向下箭头法** | Beck 1979 / Burns《Feeling Good》1980 | 用户说出绝对化、自我定性的句子时，往下一层层追问意义 |
| **向上箭头法** | de Oliveira 2007 | 拿到反证、例外之后，往上一层层追问"这说明你是什么样的人" |
| **SFBT**：例外 / 量尺 / 应对 / 关系问句 | de Shazer & Berg | 找"问题没发生"的时刻；用他人视角照自己 |
| **叙事疗法**：外化 / 独特结果 / 重写 | White & Epston | 把"我就是这样的人"改写成"这个模式在影响我" |
| 具体化 / 澄清 / 生命线回溯 | 咨询通用 | 抽象词落地到具体场景；童年轨道的时间线梳理 |

## 3. 七条轨道

### 3.0 全景

| # | 轨道 | 一句话目标 | 主要技术 | 产出 |
|---|---|---|---|---|
| 1 | **人生模式审计** | 习惯、选择、关系、目标里反复出现的模式 | 具体化 · 生命线 · 关系问句 · 例外 | 该保护的优势 / 该改变的模式 |
| 2 | **盲点发现** | 自我破坏行为与局限性信念 | 自我描述 → 向下箭头 → 例外 → 向上箭头 | 盲点 / 自我破坏 / 限制性信念 |
| 3 | **情绪触发地图** | 情绪触发、应对策略、沟通习惯、关系模式 | 身体入口 · 外化对话 · 应对问句 · 关系循环 | 触发地图 / 应对清单 / 沟通习惯 |
| 4 | **决策分析** | 你怎样做重要决定，哪些思维模式在帮你、哪些在反复坑你 | 关键决策复盘 · 信息收集方式 · 事后归因 | 决策模式（有效 / 有害各一组） |
| 5 | **童年 → 现在** | 童年环境、关键关系、重大事件如何塑造今天的模式 | 生命线回溯 · 具体事件 · 跨时空对应 | 模式来源（严格分层） |
| 6 | **未来自我差距** | 现在的我 vs 想成为的我，差距在哪、怎么走 | 奇迹问句 · 差距拆解 · 现实计划 | 差距清单（习惯/信念/技能/行为）+ 现实计划 |
| 7 | **性格洞察报告** | 把前面拼起来，并验证留下的假设 | 汇总 + 假设验证访谈 | 综合画像 + 待验证清单 |

**轨道 7 不是第七次普通访谈**：它先读已有画像卡做汇总，再针对遗留的「假设」做一轮**验证性追问**（"我一直猜 X，是这样吗？"），然后定稿画像。所以它同时是"汇总"和"访谈"。

### 3.1 各轨道的覆盖地图

地图用于进度追踪（不打勾 → 决策 P5 的依据），**不是提问顺序**。

| 轨道 | 要覆盖的面 |
|---|---|
| 1 人生模式审计 | 习惯与时间 · 做决定的依据 · 关系里的固定位置 · 目标与放弃 · 例外 |
| 2 盲点发现 | 自我描述 · 具体证据 · 归因方式 · 回避的场合 · 例外 · 反证后的自我评价 |
| 3 情绪触发地图 | 身体信号 · 具体事件 · 内化的信念 · 应对方式 · 沟通行为 · 关系循环 · 例外 |
| 4 决策分析 | 最近一个重要决定 · 信息怎么收集 · 犹豫最久的点 · 事后如何复盘 · 哪个动作帮到了 · 哪个动作反复出错 |
| 5 童年 → 现在 | 童年的家 · 关键照顾者 · 印象深的一件事 · 当时的应对 · 与今天模式的对应点 |
| 6 未来自我差距 | 想成为的样子 · 习惯差距 · 信念差距 · 技能差距 · 最可能卡住的点 · 现实计划 |
| 7 综合画像 | 已完成轨道的画像卡 · 互相印证的卡片 · 互相矛盾的卡片 · 遗留假设的验证 |

### 3.2 推荐路径（不强制）

```
先看清现状          再往深处              最后向前
1 模式审计    →     2 盲点发现      →     6 未来差距   →   7 综合画像
3 情绪地图           5 童年→现在
4 决策分析
```

入口给一条推荐顺序并说明理由（"先做 1 和 4 更容易进入状态，2 和 5 会碰到不太舒服的地方，6 适合放在后面"），用户任选一条进入。**轨道之间不做前置校验**——用户想从哪开始就从哪开始。

## 4. 实时推进引擎（v3 保留，v4 不变）

### 4.1 每轮做三件事

```
① 抽信号（不输出）→ ② 按优先级选技术（不输出）→ ③ 只输出：一句接住 + 一个问题
```

### 4.2 信号抽取表

| 信号 | 识别标志 | 例子 |
|---|---|---|
| **具体情境** | 时间 / 地点 / 人物 / 动作 | "上周三晚上我列了计划" |
| **绝对化措辞** | 总是、从来、每次、所有人、我就是 | "别人都能坚持" |
| **情绪 + 身体** | 情绪形容词、躯体感受 | "胸口有点闷，想换话题" |
| **例外 / 反例** | 与主诉矛盾的描述 | "有次做海报做到十一点没停" |
| **回避信号** | 极短回答、转移、"不知道" | "就那样吧" |
| **具体他人** | 出现有名有姓的人 | "我妈说……" |
| **价值线索** | 应该 / 必须 / 不能 | "我应该早点睡" |
| **时间线索** | 提到年份、年龄段、"那时候" | "小学的时候……"（轨道 5 用） |

### 4.3 决策优先级（从高到低，命中即停）

| 优先级 | 条件 | 动作 |
|---|---|---|
| **P0** | 自伤 / 自杀 / 虐待 / 急性症状 | **立即停止访谈**，转危机支持，不追问细节 |
| **P1** | 出现例外、反例、成功经历 | **停在那里放大**，别继续走主线（**引擎的灵魂**） |
| **P2** | 有绝对化措辞 且 深度 < 2 | 向下箭头追一层意义 |
| **P3** | 有具体情境 且 该面未展开 | 展开细节（几点 / 在哪 / 谁在 / 做了什么） |
| **P4** | 连续 2 轮短回答 / 回避 | **换更小的入口**，绝不重复同一问 |
| **P5** | 覆盖地图有空缺 且 已问 ≥ 4 轮 | 转向空缺的面 |
| **P6** | 同一模式已在 ≥2 个面出现，或轮数 ≥ 12 且无新信息 | 收尾出报告 |

### 4.4 两条护栏

```xml
<laddering_guard>
向下箭头类追问最多连问两层。第三层之前必须插入一次反映或确认。
连问三层会变成审讯 — 用户会感到被剥开，而不是被理解。
</laddering_guard>

<no_options>
绝不给用户列选项。禁止"你是 A 还是 B""请从以下选择"。
用户答不出来时，把问题缩小到一个具体场景，而不是提供答案。
</no_options>
```

`ladderingDepth` 存会话状态，由代码保证，不靠模型自觉。

## 5. 认识论分层（v4 核心新增）

**这是整套设计里最值钱的一条**：每条结论都必须自我标注可信度层级，不许把推论说成用户的真相。

| 层级 | 含义 | 报告里的写法 | 触发条件 |
|---|---|---|---|
| **观察** | 用户原话直接支持 | "你自己说：『反正每次都这样』" | 能引用原话，无需推论 |
| **可能** | 多条证据的推论，用户没说出口 | "你在三个不同场合用了同一句式，可能是……" | ≥2 条独立证据指向同一结论 |
| **假设** | 我的推测，待验证 | "我想猜一个，你告诉我对不对——" | 证据不足但值得问的情况 |

三条硬规则：

```xml
<epistemic_layering>
1. 每条结论必须标注层级，且层级要与证据匹配。只有一条证据时不许升格为「可能」。
2. 「可能」和「假设」在访谈中必须能被追问验证；「观察」只引用，不推论。
3. 报告里三档必须视觉可区分 — 用户要能一眼看出哪些是他自己说的，哪些是我猜的。
</epistemic_layering>
```

**为什么这条重要**：AI 做心理分析最容易犯的错，就是把自己的模式识别当成用户的真相端上去（"你其实是回避型"）。分层标签把这个诱惑变成了**必须公开的自我标注**——它同时治了过度自信和"假洞察"两个病。

它还有一个副作用：**「假设」会跨轨道传递**。轨道 2 留下的假设，在轨道 5 或轨道 7 里被验证或推翻。这让多次访谈之间有了真正的连续性，而不是六份互不相干的报告。

## 6. 滚动画像卡（v4 核心新增）

### 6.1 卡片结构

每次访谈结束，除了报告，还沉淀若干张**画像卡**（原子结论）：

```js
{
  id, trackId: 'blindspot',
  layer: 'observed',         // observed | probable | hypothetical
  claim: '启动卡点来自"没有一个具体等着要的人"，而非能力或意愿',
  quotes: ['上个月做海报……中间没停', '得有个真的想做的理由'],
  fromReport: '<报告 id>',
  status: 'confirmed',       // confirmed | pending（假设待验证）| overturned
  createdAt
}
```

卡片是**跨轨道累积**的最小单位。存本机（`boh_psych_profile_v1`），与报告索引并列。

### 6.2 卡片怎么被用起来

| 用途 | 做法 |
|---|---|
| **下次访谈的开场** | 读卡片而不是读原始对话 → "上次你提到启动难，今天我们看看它从哪来"（轨道 5 自然接上） |
| **不重复问已知** | 卡片里已有的观察不重复收集，直接深挖或向前推进 |
| **矛盾并置**（最高价值） | 轨道 1 说"我能坚持"，轨道 2 说"每次都崩"——把两张卡并排放 |
| **假设验证** | 带 `status: 'pending'` 的假设进入轨道 7，逐条问"是这样吗" |
| **进度可见** | 入口展示"已沉淀 12 张画像卡 · 3 条待验证假设" |

**矛盾并置是这套设计真正的产出**。单次访谈只能得到"你在某件事上如何"，多次访谈才能得到"你在不同场合对自己的描述不一致"——而后者才是盲点的定义。

### 6.3 轨道 7 如何生成综合画像

```
读全部画像卡
  ├─ 按面分组（习惯 / 关系 / 情绪 / 决策 / 早年 / 未来）
  ├─ 找出互相印证的卡 → 画像主干（高置信）
  ├─ 找出互相矛盾的卡 → 单独列出，做一轮验证性追问
  └─ 带 pending 的假设 → 逐条验证，标 confirmed / overturned
→ 定稿综合画像（含"已验证"与"仍待验证"两部分）
```

## 7. 访谈协议

```xml
<interview_protocol>
1. 一次只问一个问题。绝不写"请依次回答以下三点"。
2. 绝不给选项。（见 <no_options>）
3. 每轮先接住上一句，再问下一句。接住 ≠ 夸奖，是把他的话译出情感。
4. 追问必须钩住对方上一句里的**具体词**，不要跳到通用句式。
5. 遵守 <laddering_guard> 与 <epistemic_layering>。
6. 每 4 轮做一次摘要，末尾问"我理解得对吗"。对方纠正时立刻采纳。
7. 对方说"不知道""想不起来"时，不重复同一个问题，把它换小。
8. 内部标记信号、选定技术，但**不要向用户暴露技术名词**（见 §10.1）。
9. 访谈期间不评价、不劝解、不给建议、不下结论。所有判断留到报告里。
10. 对方想停、想换话题、想跳过，立刻顺着走。
11. 收尾判据：同一模式在 ≥2 个面各出现一次；或用户主动结束；或轮数 ≥ 12 且连续 2 轮无新信息。
12. 涉及童年、创伤、重大关系破裂等内容时放缓节奏，不连续追问；出现不适立即退回安全陈述。
</interview_protocol>
```

**预期轮数**：单条轨道 12-18 轮。开场告知用户，并说明随时可停。

## 8. 报告（两种）

### 8.1 轨道报告（八段）

```
1 我听到的你        反映性摘要（你自己的话被整理后的版本，不是定义）
2 反复出现的模式     分条，每条附原话 + 层级标签
3 模式底下那句话     向下箭头的结果（多为「可能」层）
4 被你忽略的例外     你答出过但没当回事的独特性 ← 单次访谈最有价值的产出
5 值得保留的         优势，必须能追溯到具体某轮
6 由此推出的方向     从第 4、5 段长出来的规划
7 本周一个动作       具体到时间 / 地点 / 动作，只给一个
8 本次留下的假设     带「假设」层的条目 + 下次可怎么验证
```

**第 6 段是质量闸门**：必须由第 4 段的例外反推得出。**没有第 4 段的地基，第 6 段就会退化成鸡汤。**若第 4 段为空，第 6 段只允许写"这次没找到反例，这本身也是信息"。

### 8.2 综合画像（轨道 7 产出）

```
1 画像主干          互相印证的卡片（按面分组）
2 你对自己的两种描述  矛盾并置 —— 这是盲点的定义所在
3 假设的验证结果      confirmed / overturned，逐条
4 仍待验证的         留给下一次
5 方向总览           跨轨道的规划（不是单次动作）
6 免责与危机资源
```

## 9. 出生日期：读站内字段

- 进入角色时读当前登录用户的生日，不弹输入框，改为**一句轻确认**：
  > "我这边看到你的资料里有生日 12 月 17 日。用它只是想知道自己大概在跟什么阶段的人说话——不想让我用的话说一声。"
- 用户说不要 → 立刻丢弃（`birthDateSource: 'declined'`），本轮及以后都不引用。
- 未登录 / 字段为空 → 问一次，答了存本机，不重复问。

**锚点用法**：年龄只用于 ① 判断人生阶段；② 让提问贴合该阶段真实处境（20 岁问"毕业后的打算"，不问"退休规划"）。**严禁**由生日推演性格、运势、星座、命理。

## 10. 交互与呈现：零新增 UI

**产品约束（已定）：不新增任何界面组件，全部走 BOHAI 原有的对话渲染。**

| 内容 | 怎么呈现 |
|---|---|
| 提问与回应 | 普通 assistant 消息 |
| 轨道选择 | AI 用列表给出轨道名字，用户回名字（**任务选择不算「给选项」**，见 §10.2） |
| 报告 | 一条 assistant 消息，markdown 八段（原有 `renderMarkdown` 已支持标题 / 列表 / 加粗） |
| 证据层级 | 用文字前缀 **观察** / **可能** / **假设**，不用彩色标签——纯文本在任何地方都能用，也能被复制走 |
| 进度 | 不显示进度条。用户问「还剩几轮」，AI 从状态块里知道并回答 |
| 画像卡 / 综合画像 | 不上界面。存本机，访谈开始时注入上下文 |
| 出生日期确认 | 对话里一句话 + 用户口头回应 |

好处不只是省事：**不动 `BOHAIMain.vue`（2450 行）**，也不引入新的玻璃 / 暗色样式债（项目在这上面踩过不少坑）。
### 10.1 技术标注的可见性（内部推理 vs 过程透明）

**结论：抽到什么信号、命中哪条优先级、用了什么技术——一律不给用户看。**

| 层级 | 内容 | 是否展示 |
|---|---|---|
| **内部推理** | 信号抽取结果、P0-P6、技术名词（向下箭头 / 例外问句 / OARS / 独特结果）、`ladderingDepth` | **禁止** |
| **过程透明** | 进度、当前方向、可跳过、可停下、数据边界（仅本机 · 不进记忆库） | **必须** |

三条理由：

1. **元认知污染**：用户一旦知道"提到例外会被放大"，就会开始表演性作答——想着"我该说点积极的了"。这跟"不给选项"是同一个病因：**任何泄露探索规则的东西都会改变回答**。
2. **术语是屏障**：用户不知道 P1、向下箭头是什么，看见只会分心（"它在分析我？"）。访谈要的姿态是**被理解**，不是**被算法处理**。
3. **反噬**：展示技术标注的动机是"证明我在认真听"，但反映性倾听本身已经做到了，而且做得更好。

**唯一例外**：用户主动问"你怎么问出来的？"——用大白话解释（"我注意到你自己提过一次例外，就停下来多问了两句"），仍不点术语名。

> 注意：**认识论层级标签（观察 / 可能 / 假设）是例外——必须展示**。它不泄露提问机制，而是保护用户不被 AI 的推论冒充成自己的真相。这是知情权，不是技术细节。

**衍生影响**：删掉选项后，`【追问】` 渲染链路（`BOHAIMain.vue:922-938` / `:168-195`）在心理角色里不再使用，plan 模式继续用，互不干扰。

### 10.2 什么算「给选项」

| 场景 | 能不能给选项 | 为什么 |
|---|---|---|
| 心理问题（「你更怕失败，还是更怕被看见？」） | **绝不能** | 锚定答案范围 + 用标签替代情节 + 让追问技术失效（见 §1） |
| 任务选择（「想先做哪条轨道？」） | **可以**，用列表给名字 | 这是在选服务，不是在向对方提问。限制它反而难用 |

这条边界已写进 `psychologist.js` 的 `<no_options>`。输出守门只拦「问题里的选项」，不拦轨道列表。


### 10.3 一键启动入口（加号 → 工具 → 心理分析）

位置：`BOHAIMain.vue:353` 的加号按钮 → `feature-action-list`（现有 4 项：联网搜索 / 社区搜索 / 个人 Cloud+ / 健康分析）。新增第 5 项「心理分析」。

这是**往现有菜单里加一个条目**，复用既有的 `feature-action-row` 样式，不算「新增 UI」。

点击后做三件事（`startPsychAnalysis`）：

| 步 | 动作 | 为什么 |
|---|---|---|
| 1 | 切到「心理专家」角色（`setResponseStyle('psychologist')`） | 访谈协议 / 不给选项 / 认识论分层都挂在角色的提示附录里，**不切角色就不会访谈** |
| 2 | 空会话时填入启动语，走现有 `sendMessage()` | 于是 AI **直接主动开口提问**，不需要用户先打字 |
| 3 | 已有内容的会话只切角色、不代发 | 避免重复点击叠出多条「开始」 |

**为什么是「代发一句用户消息」而不是隐藏指令**：
- 复用现有发送链路，零新机制
- 语义诚实 —— 用户确实点了「想被采访」
- 可追溯 —— 消息在会话里看得见

**「管线做完」依赖什么**：单靠 prompt 就能让 AI 开始提问并一路聊下去；但要「不跑偏 + 自动收尾」，依赖 §16 的接线（状态块 → 末尾锚定 → L2 规则）。所以**入口先可用，稳定性由 S1 接线补齐**。

## 15. 坑与风险

1. **实时推进会退化成清单**：模型有明确规则时仍倾向走固定顺序。P0 的验收机制必须做，否则设计会悄悄失效。
2. **P1（例外优先）最容易被忽略**：模型的天性是"完成计划"。要在 prompt 里写明"发现例外时允许偏离当前维度"。
3. **轨道 7 最容易变成"六份报告的重述"**：必须要求它**只做三件事**——找印证、找矛盾、验假设。不允许逐条复述。
4. **认识论分层的三种漂移**：① 层级虚标（一条证据就升格为「可能」）② 层级标签流于形式（全标"观察"）③ 用户误以为「假设」是结论。缓解：报告里三档必须视觉可区分，且「观察」必须带原话引用（没有引用就不许标观察）。
5. **画像卡会累积成噪音**：设上限（如每轨道 ≤8 张），超限时按"是否被后续访谈印证过"淘汰。
6. **向下箭头容易问成审讯**：靠 `ladderingDepth` 强制插反映。
7. **"不给选项"与"不暴露术语"要靠代码兜底**：合并为同一道输出护栏，命中记 `bohai-observability.js`。
8. **会话白名单坑**（§11.2）：不改会导致刷新后访谈重新开始且无报错，最难查。
9. **模式提升劫持**（`useChatEngine.js:1797-1803`）：访谈轮次可能被强换 plan 模型。
10. **生日与画像卡都需要授权口径**：UI 上说明"读了什么、用来干什么、可拒绝"。
11. **不要用 `roleId` 硬编码做 UI 开关**，从第一天就用 `uiSlots`。

## 16. 规则不遗忘机制（工程关键）

> 前提判断：**这条比前面所有 prompt 设计都重要**。规则写得多漂亮，第 10 轮照样会一次问三个问题、开始列选项、把术语说出来。

### 16.1 为什么会忘 —— 三个真实机制

访谈跑到第 12 轮时，上下文里同时存在：system prompt、最多 30 条历史、证据块、对话摘要块。丢规则的路径有三条：

| 机制 | 现状证据 | 后果 |
|---|---|---|
| **注意力稀释** | system 里规则段越长，相对权重越低 | 前 3 轮守"一次只问一个问题"，第 8 轮问出三个 |
| **历史被压缩** | `MAX_HISTORY_CONTEXT_CHARS = 12000`（`chat-engine-config.js:27`）+ 自动整理产出 `contextSummary`（`useChatEngine.js:1841-1845` 注入 `<conversation_summary>`） | 访谈中段的关键原话被摘要掉 → "忘了"用户第 3 轮说的话 |
| **状态不在提示里** | `askedCount` / `ladderingDepth` / `coverage` 若只存在前端 JS | 模型不知道自己问到第几轮、深度到几层，规则自然失效 |

**结论：把规则写得更狠没用。要靠「每轮重建 + 状态注入 + 代码守门」。**

### 16.2 五层防线

好消息是**第 1 层现成**：system prompt 每轮从数组重新拼装（`useChatEngine.js:1847-1853`），本身就每轮重建。要做的是往这个数组里加东西。

```
① 每轮重建 system        ← 现成（1847-1853），不动
② 注入「状态块」          ← 新增，让模型看得见自己走到哪
③ 规则分三层 + 按需选取    ← 新增，避免 20 条规则互相稀释
④ 末尾锚定（离生成最近）   ← 新增，注意力最高的位置放最关键的 1-2 条
⑤ 代码守门                ← 新增，不靠模型自觉
```

### 16.3 状态块（②，每轮注入）

这是"不遗忘"的核心手段：**不靠模型记，靠每轮喂**。

```xml
<interview_state>
轨道 2 · 盲点发现（第 7 轮 / 预计 12-18 轮）
覆盖地图：自我描述 ✓ 具体证据 ✓ 归因方式 ✓ 回避场合 ✗ 例外 ✓ 反证后自评 ✗
向下箭头深度：1 —— 再追一层就必须插入反映
上次摘要：第 4 轮　下次摘要：第 8 轮
已采集原话依据：
  · "心里知道该睡，但就是不动"
  · "别人都能坚持，我不能"
  · "上个月做海报，下午三点到晚上十一点，中间没停"
本次已产生的假设：1 条（待验证）
</interview_state>
```

四点设计要点：

1. **简短、结构化**：它是给模型的仪表盘，不是给人读的文档。
2. **`已采集原话依据` 必须在这里，不能只靠对话历史** —— 见 §16.6。
3. **深度和摘要在里面** → 模型不用自己数轮次（模型几乎从不正确数轮次）。
4. **token 预算**：状态块固定 ≤400 字符，登记到 `CONTEXT_CATEGORIES.SYSTEM_PROMPT`（`useChatEngine.js:1827-1838`）。

### 16.4 规则分三层（③）

20 条规则平铺 = 每条权重 1/20。分层的目的是**让当前最需要的规则浮上来**。

| 层 | 内容 | 何时注入 |
|---|---|---|
| **L0 硬护栏**（永远） | 一次只问一个问题 · 绝不给选项 · 危机短路 · 不暴露技术名词 | 每轮，4 条，写成最短句 |
| **L1 行为规则**（永远） | 先接住再问 · 钩住具体词 · 深度≤2 必插反映 · 说"不知道"就换小问题 | 每轮，4 条 |
| **L2 情景规则**（按状态选 1-2 条） | 见下表 | 按当前状态动态选 |

L2 的选取表（代码决定，不是模型决定）：

| 当前状态 | 注入哪条 |
|---|---|
| `ladderingDepth >= 2` | "本轮禁止再追问，必须做一次反映" |
| `askedCount - lastSummaryAt >= 4` | "本轮先做摘要，末尾问'我理解得对吗'" |
| `coverage` 快满 / `askedCount >= 12` | "可以进入收尾：先确认对方是否还想聊" |
| 连续 2 轮回答 < 15 字 | "把问题换小：落到一次具体经历" |
| 检测到例外/反例 | "**停下主线**，把这次例外放大追问" |
| 出现童年/创伤内容 | "放缓节奏，不连续追问，随时给退路" |

**只注入 1-2 条**。全量注入等于没注入。

### 16.5 末尾锚定（④）

`finalPrompt` 是 messages 数组里**最后一条 user 消息**（`useChatEngine.js:1973-1979`），是离生成最近、注意力最高的位置。在它结尾放一段锚定：

```
【本轮唯一动作】只问一个问题。不给选项。不用技术名词。
【当前状态】第 7 轮 · 深度 1 · 覆盖 4/6 · 本轮该转向「回避的场合」
```

三行，代价极小，但**能拉住整个访谈的行为底线**。system 里的长规则负责"怎么想"，末尾锚定负责"这一轮别跑偏"。

### 16.6 关键原话必须独立于历史摘要（③的补充，最易被忽略）

自动整理会把历史压成 `contextSummary`（阈值 100%，`MAX_HISTORY_CONTEXT_CHARS = 12000`）。长访谈**必然触发**。一旦触发，用户第 3 轮那句"上个月做海报……没停"就可能只剩摘要里一句"用户提到有例外情况"——**最值钱的细节被压掉了**。

所以：

- `expertState.evidence`（原话摘录）**独立保存**，并通过状态块每轮注入；
- 摘录规则：每轮最多新增 1 条，只存**能被追问的**具体原话（情境/人物/数字/绝对化措辞），不存感受词；
- 上限 8 条，超出时按"是否已被用进报告"淘汰；
- 报告生成时**只从 evidence 取原话**，不从对话历史取——这样报告的依据不会因为历史压缩而消失。

### 16.7 代码守门（⑤，真正的保险）

prompt 是软约束。以下判断必须由代码做，且**在生成前注入指令 or 生成后校验**：

| 触发 | 守门动作 | 时机 |
|---|---|---|
| `ladderingDepth >= 2` | 注入"本轮必须反映"（L2） | 生成前 |
| `askedCount - lastSummaryAt >= 4` | 注入摘要指令（L2） | 生成前 |
| `askedCount >= 14` 且无新信号 | 注入收尾指令 | 生成前 |
| 输出含选项式句式（"A 还是 B""请选择"） | 记录 `bohai-observability.js`，**不重试**（记录用来看 prompt 是否需要加固） | 生成后 |
| 输出一轮内 `？` > 1 且不在引用里 | 同上 | 生成后 |
| 输出含技术术语（P0-P6 / 向下箭头 / 例外问句 / OARS / 独特结果 / 信号名） | 记录 + **剥离该句重生成一次** | 生成后 |

**为什么"多问"只记录不重试**：重试会打乱对话节奏，且用户已经看到打字过程。先用数据判断频率，再决定是否升级为硬拦截。

**为什么"术语泄露"要重试**：它直接破坏"被理解"的姿态，值得多花一次调用。

### 16.8 跨会话不忘（画像卡注入）

下次进入任意轨道时：**注入画像卡摘要，而不是让模型翻历史对话**。

```xml
<prior_profile>
已完成轨道：1 人生模式审计（6 张卡）
高置信结论：
  · 启动条件是"有具体交付对象"（观察）
  · 用"应该"推自己时反而动不了（观察）
待验证假设：
  · 阻力不在执行阶段，而在启动前那句自我审判
未覆盖的面：决策方式、早年经历、未来规划
</prior_profile>
```

好处有三：① 模型不需要读几万字历史就知道已知什么；② 避免重复问同一件事（重复问会让人觉得"它根本没在听"）；③ 让"假设可以跨轨道被验证"这件事真正成立。

### 16.10 验收（必须做，否则整套会悄悄失效）

1. **长访谈漂移测试**：跑满 18 轮，检查第 13-18 轮是否仍遵守 L0（一次一问 / 不给选项 / 无术语）。**前 5 轮正常不代表没坏**。
2. **历史压缩测试**：人为触发摘要（把 `MAX_HISTORY_CONTEXT_CHARS` 调小），确认第 10 轮仍能引用第 3 轮的原话 —— 验证 §16.6 生效。
3. **守门反证**：临时把输出校验关掉，确认测试能抓到违规 —— 否则说明校验是空转。
4. **状态块可见性**：状态块**不展示给用户**（属内部推理，见 §10.1），仅用于调试面板。

## 17. 实战校准：2026-09-16 那次对话（重要实证）

`startPsychAnalysis` 上线后第一次真实访谈（话题：即将到来的六级考试），四轮提问里三轮退化成问卷，用户最后回了一句「我感觉 AI 特别傻」。这是**「prompt 里只有规则、没有示例」**的代价，记录下来避免重犯。

### 17.1 现象

| AI 的提问 | 病症 |
|---|---|
| 你目前最担心的**具体是什么方面**？ | 问卷句式，换任何话题都能套 |
| 如果没达到预期，你认为自己**会采取什么行动**？ | **要方案**：用户说「考不过」，该往下追「考不过意味着什么」，却跳到「你打算怎么办」 |
| **了解到你**感到压力，**并且**打算再考一次。那么…**有没有**哪些环节… | ① 复述冒充接住 ② 双问题 ③ 「有没有」是封闭式 |
| 你**通常会**用什么方法来应对？ | 「通常」= 问习惯不是问经历；又在要方法 |
| 当你感到无法应对时，你**通常会做些什么**？ | **同一个问题换个说法又问一遍**——用户已说过「没法应对」 |

### 17.2 根因（两条，都不是「模型不听话」）

1. **规则抽象，缺判定与示例**：prompt 写了「钩住具体词」「接住再问」，但模型把「接住」理解成「复述」，也不知道「具体词」该钩哪一个。
2. **助手惯性**：基础模型的默认行为是「理解问题 → 给方案」，于是持续滑向「你会怎么做 / 用什么方法」。这条惯性靠正面要求压不住，必须**明令禁止**。

### 17.3 改法（已落地 `psychologist.js`）

- **四类禁问问句黑名单**：`你通常会…` / `你会采取什么行动` / `具体是什么方面` / `了解到你…，并且…`
- **接住 ≠ 复述**，给出判定标准：『如果你只是把他刚说的词换个顺序再说一遍，那就是复述，删掉它直接问问题』
- **三组正反对照示例**（考不过呗 / 背单词好难坚持 / 没法应对），「没法应对」那组专门标注「换个说法再问一遍是最容易被察觉的失礼」
- **两个硬指标**：一个问题 ≤30 字；一轮里只允许出现一个问号
- **访谈期绝不给建议**：不许出现「你可以试试」「建议你」「不如…」

### 17.4 附带的模型选择结论

轻量模型（fast）跟不上这套多规则协议。**入口已自动升级到 pro**（`chatModes` 里找不到 pro 时保持原样，未登录不报错）。

### 17.5 沉淀出的通用原则

> **规则告诉模型「要什么」，示例才告诉它「不要什么」。**
> 描述性规则（如「钩住具体词」）在 prompt 里必须配齐三样：① 可判定的边界 ② 至少一组正反对照 ③ 出现即违规的黑名单。

这四条已写进回归测试（`psych-expert-prompt.test.js` 从 8 项增至 12 项），防止后续改动把示例删掉。

### 17.6 第二次复测（2026-09-17，5 轮有效样本）

改完 §17.3 之后复测。结果与**新的退化形态**都值得记住：

- ✅ **例外优先真的生效了**：「不过上个月做海报那次不一样，从下午三点做到晚上十一点，中间一次都没停」→ 下一问停在了这个例外上（「这种坚持对你来说意味着什么？」），**没有继续走原话题**。这是 P1 优先级第一次被真正执行。
- ✅ 向下箭头在用（5 轮里「意味着什么」出现 3 次）。
- ❌ **复述成了主导退化形态**：几乎每轮都先把用户原话整段重排一遍再追问 —— 「复述 + 追问」被当成了安全模板。
- ❌ 轮 2 与轮 1 逐字重复（输入「不知道，想不起来了」时最容易发生）。
- ❌ 用一次性行为推断习惯（「你**通常会**刷手机到深夜」）。

**应对**：新增 `PARROT`（复述）违规类型（包含度 ≥0.75 判违规并触发重写）；prompt 加【回答里不许出现他的原句】并配正反对照；修掉相似度的**方向 bug**（第一版拿第二参数当分母，长问 vs 短问会漏检，改成对称包含度）。

### 17.7 元教训：质量探针不能反复跑

这类真实调用的质量探针**烧的是用户额度**，而守门命中还会多一次调用（消耗翻倍）—— 两次实测都把用户当日额度跑完了。

**正确分工**：
- **探针**：改完代码后**跑一次**做回归（重点看守门有没有误报/漏报），或用于无人值守的批量检查。
- **人**：日常质量判断 —— 用户点一次对话，**3 秒就能判断"这问得傻不傻"**，成本几乎为零，而且能判断探针根本判断不了的东西（问得聪不聪明）。

探针只能测**机械规则**（一轮多问 / 给选项 / 重复问 / 复述 / 泛化 / 给建议 / 是否钩住关键词 / 报告结构）。
