## 二、已修：指示器几何错位（P0，一行，已验证）

### 症状（实测）
- **横向恒定错**：指示器 239×47 @ left=0，激活条目 215×47 @ left=12 → 左偏 12px、宽 24px、右端顶住栏右发丝线。
- **纵向仅首屏错**：首屏 `translateY(96)` 而条目实际 top=152 → 上浮 56px；**切一次 tab 自愈**（切后 dTop=0）。

（窄栏同形：87 vs 67、left 0 vs 10、首屏上浮 56px。）

### 根因（同一处）
`.userspace-rail-group` 是 `position: static`：

1. 指示器 `left:0 / right:0` 的包含块不是 group，而是上溯到最近的定位祖先 `.userspace-rail`（`position:absolute`）的 **padding box** → 横向按栏全宽铺开，而不是按条目宽度。
2. `offsetTop` 读数同样以 rail 的 padding edge 为基准，而 rail 的 `padding-top` 由 `--userspace-rail-top-h` 驱动（导航岛实测高度，首屏会从 82→138 跳），指示器只在 `onMounted` / `currentTab` 变化 / RO(group 尺寸) 三类时机重算 → 首屏那次算早了，且 group 尺寸没变所以 RO 不补。

### 修法
`side-rail.css` 的 `.userspace-rail-group` 加 `position: relative`（附注释说明它为指示器提供包含块）。
加完后指示器成为 group 的子元素，group 被 padding 推下时它同步下移 → 纵向不再需要手动补同步。

### 实测（修复前 → 修复后）

| 视口 | dTop 首屏 | dLeft | dWidth |
|---|---|---|---|
| 1440×900 宽栏 | −56 → **0** | −12 → **0** | +24 → **0** |
| 1100×900 窄栏 | −56 → **0** | −10 → **0** | +20 → **0** |
| 1024×600 | −56 → **0** | −10 → **0** | +20 → **0** |

切 tab 后同样为 0（不再需要"自愈"）。

### 反证
`git stash push` 撤掉该行 → 三档全部复现（−56 / −12 / +24 与 −56 / −10 / +20），`stash pop` 恢复后归零。
→ 断言非空，修复确为该因。

## 四、结构性建议（P2）

- **C1 矮窗紧凑档**：`min-height` 600–700 区间，10 项 × 59 = 679 必然溢出，且 `.userspace-rail-group--footer` 的 `margin-top:auto` 在溢出容器内失效 → 工具组不再吸底，"退出登录"要滚动才可见。建议矮窗自动切紧凑档（条目 59→46、图标 20→16、字号 11→10），或 <700 高度直接回退底部胶囊。
- **C2 顶部导航居中基准**：横屏有左栏时，`#unified-nav-container` 的 surface 实测 290–1150（中心 720 = 全页中心），而内容区中心是 840 → 导航相对内容区偏心 120px。建议横屏 + 左栏可见时以内容区为基准居中。
- **C3 `--userspace-rail-top-h` 抖动**：导航状态卡片出现/消失会让左栏 `padding-top` 在 96↔152 之间跳，整栏内容上下跳 56px。建议左栏避让改用固定上限值，或给 padding 变化加过渡（不与 C1 冲突）。

### 三条实现上的取舍（都写进了代码注释）

1. **C2 用 `left` 而不是 padding**：`#unified-nav-container` 上有 scoped 的 `padding: 0 !important`，
   加 padding 得跟着上 `!important` 才能赢（本目录不这么干）；surface 又带着状态卡动画用的 `translateY`，
   用 transform 偏移会打架。`relative + left: var(--userspace-rail-w) / 2` 是唯一不碰这两者的杠杆。
2. **品牌位用绝对定位**：占的是「与内容区首屏对齐」留出的既有空白，所以不进文档流、不增加内容高度，
   也不会把矮窗溢出问题放大。反证时撤掉该样式，品牌位立刻回落进文档流、首项被推下 56px（152 → 208）。
3. **紧凑档阈值分档写**：窄栏内容高约 784px、宽栏约 882px，用一个统一阈值会让
   1100×800 这种「窄栏本来放得下」的窗口白白压小条目。所以用媒体查询列表：
   窄栏 `≤780`、宽栏 `≤880`。
