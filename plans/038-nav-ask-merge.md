## 1. 一句话结论

**一颗悬浮的胶囊，靠自己的尺寸说话。** 小胶囊＝待命，条＝可输入，大卡＝正在回答；搜索与问答共用这一颗岛，

## 2.8 为什么必须是岛，不是下拉面板

| 维度 | 下拉面板 | 悬浮岛 |
| --- | --- | --- |
| 归属 | 导航栏的延长，必须有导航栏 | 独立悬浮物，任何页面都能存在 |
| 状态语言 | 只有开 / 关 | 尺寸本身是状态：胶囊＝待命，条＝可输入，大卡＝正在回答 |
| 几何耦合 | 要覆盖 `surface` 的 height，还要处理 mini caps / 沉浸球（`BOHAIIsland.vue:253-275`） | 与导航栏零耦合 |
| 可用范围 | 约四成路由没有导航栏 ⇒ AI 不可用（`useGlobalAiOverlay.js:27-36`） | Teleport 到 body ⇒ 全站可用 |
| 遮挡 | 撑高会改变导航栏几何 | 只盖住它自己那一块，页面不跳 |

> 「没有导航栏的页面上 AI 不可用」不是边角问题：`user-space` 子视图、沉浸阅读、admin 全在里面。
> 把入口重心迁到日常交互之后，这个洞必须先补。

## 2.9 唤起体系：一个常驻入口 + 三种加速

唤起不能依赖学一个手势 —— 手势学不会的用户就用不上 AI。结构如下：

| 端 | 常驻入口 | 加速 | 上下文唤起 |
| --- | --- | --- | --- |
| 竖屏 | 导航栏下方居中胶囊 `148×40`「问一句」 | **对着导航栏向下拖**（见 3.7） | 长按选中文字 → 问；页面内按钮 |
| 横屏 / 桌面 | 导航栏右侧星芒按钮 `32×32` | `⌘K`、`/`（等价位） | 同上 |
| 全端 | — | — | `showIsland.ai({prompt})` 直接进回答态 |

**竖屏常驻、桌面不常驻**是取舍：竖屏内容窄、拇指可达，悬浮胶囊的遮挡代价可接受；
桌面内容宽，常驻悬浮挡视线且桌面有键盘 —— 按钮只负责「被发现」，不负责「岛的身份」。

**退场**：右边缘滑动（`AiEdgeTrigger`）与「抓导航栏下拉」指向同一目标，两个手势并存用户就学不会，
留「抓导航栏下拉」砍边缘滑动（后者无视觉提示、发现性差、与 iOS 返回手势打架）。

**主动唤起的边界**：概览每天一次（胶囊长出一小段文字，不抢焦点不弹键盘，5s 缩回）；
任务照旧；通知降为胶囊上一个小圆点。原则：**只有用户刚做过动作时才允许打断用户**。

### 2.9.1 架构硬约束：壳同步渲染，内容懒加载

现有实现岛打开后要等 `BOHAIMain` 异步加载完成才 `focusComposer()`（`BOHAIIsland.vue:118-126`，最长等 5s），
用户看到的是「点了没反应、键盘晚一步」。这条比任何手势都更影响「能不能顺手用起来」：

- **岛的壳（胶囊 + 输入条）在 App 挂载时同步渲染** —— 只有一个 `input` 和一个图标，体积可忽略；
- 「最近 / 结果 / 回答」区域才 `createPanelAsync` 懒加载；
- 唤起 = 输入框立即聚焦 + 键盘立即弹起，内容在用户打字的过程中加载完。

## 3. 设定

### 3.1 四个形态（手机尺寸）

| 形态 | 尺寸 | 圆角 | 内容 |
| --- | --- | --- | --- |
| **胶囊** | 148 × 40 | 999 | 图标 + 「问一句」（待命） |
| **输入** | 344 × 52（含「最近」140） | 26 | 输入框 + 发送 |
| **列表** | 352 × ≤ 340 | 26 | 第 0 项「问 BOHAI：<原句>」+ 站内结果分组 |
| **回答** | 352 × `min(52 + 内容高 + 12, 上限)` | 30 | 答案 + 来源 chip + 站内卡片 + 展开/去全页 |

**回答态高度随字数生长**（2026-11-04 用户确认）：短答案岛就矮，长答案逐帧向下长到上限后内部滚动 ——
岛永远「装的就是它说的」，不出现一大块空岛。上限取 `min(470, 视口 − 导航 − 键盘 − 边距)`：
无键盘时 ≈470，键盘弹起时 ≈344（390×844）。追问让内容变长则继续长，开新对话才收缩。
流式期间每帧同步高度（跟手过一次 `scrollHeight`），方向只有向下，不抖。

桌面档：输入 480 宽、列表与回答 560 宽，仍居中悬浮（**不拉满** —— 拉满后一行字横跨 1000px 无法阅读）。

**岛顶恒定**：`top = 导航高 + 12`，输入条永远是岛的第一个子元素 ⇒ 每次长大都是向下长，
输入框在四态之间**逐像素不动**（本方案唯一的硬视觉契约，探针要断言）。

**动画分工**（这是「岛」的手感来源）：
宽度 `380ms cubic-bezier(.34,1.3,.64,1)`（轻微回弹）→ 高度 `460ms cubic-bezier(.16,1,.3,1)` 且**晚 20ms 起步**。
先变宽、再长高；反过来的话，会先看到一个怪高的窄条。

### 3.2 意图路由：不猜「问不问」，只决定「默认高亮谁」

| 输入特征 | 默认高亮 | 理由 |
| --- | --- | --- |
| 站内命中 = 0 | 第 0 项 | 没结果时唯一有意义的动作就是问 |
| 命中 > 0 且不像问句 | 第一个搜索结果 | 与现状**完全一致**，老用户零学习成本 |
| 命中 > 0 且像问句 | 第 0 项 | 问句要结果列表没意义 |

「像问句」的判据是**纯本地轻规则**，不调模型：
`长度 ≥ 8` 且命中 `怎么/为什么/能不能/帮我/是什么/什么时候/在哪/哪个/哪家/多少/吗/？` 之一。
（⚠️ 首版原型漏了「什么时候」，导致「八周年的活动什么时候开始」被判成普通搜索 —— 这类词必须逐个补，别只写常见的那几个。）

- `Enter` → 执行当前高亮项（用户按之前就能看见会发生什么）
- `⌘↵ / Ctrl+↵` → 强制问 AI（不看高亮）
- `Esc` → F2 时退回 F1（保留原句），再按一次关面板
- `↑↓` → 在「第 0 项 + 结果」之间连续移动（第 0 项参与序号，不是独立按钮）

> 不做「一个框自动判断意图然后直接问」：猜错的代价（一次无用的 AI 调用 + 一次错愕）高于多点一次。

### 3.3 三条硬约束

1. **绝不边打字边问 AI。** 搜索廉价无限，AI 有配额与延迟（`useRateLimiter.js` / 用量体系）。
   停顿自动触发等于每次思考都烧一次额度。AI 只在显式提交时发起。
2. **快捷键合并**：`⌘K` 与 `/` 都召唤同一颗岛，差别只在初始态 —— `⌘K` 聚焦后默认高亮 AI 项，
   `/` 走普通搜索。原先的归属之争自然消失。
3. **输入条永不清空语义**：F2 里输入框的语义是「追问」；要重新搜索先 `Esc` 回 F1。

### 3.4 会话归属

搜索框一天可能问几十次，**不接进主会话**（否则上下文与用量双双失控）。
走独立快速会话（`/temp` 已有同款机制），全页侧栏单独列一条「在搜索里问过」，
点开可「提升为主会话继续聊」。岛内不提供会话管理（切换/重命名/删除一律回全页）。

### 3.5 回答面（F2）的形态

- 首屏 5–6 行正文，超出渐隐 +「展开全文」
- 来源合并成**一行 chip**（「站内 2 · 网页 1 · 本页」），展开才看清单
- 流式阶段只出一行活动文字（复用 `boh-activity.js` 的单阶段真源），完成后该行消失
- 问题在答案区顶部以一行小字回显，输入框清空（随时可追问）
- **不加 header、不加第二层玻璃**（外层 surface 已有玻璃，叠两层会发灰 —— `MEMORY-bohai-liquid.md`）

### 3.6 减法清单

| 岛内保留 | 移回全页 |
| --- | --- |
| 输入条 / 发送 / 停止 | 模型与策略选择（9 行） |
| 流式回答（首屏 5–6 行） | 工具菜单（Cloud+ / 心理分析） |
| 来源合并 chip | 用量环 + 用量浮层（限流只出一行提示） |
| 「引用本页」一颗 chip | 会话侧栏 / 新建 / 切换 / 重命名 / 删除 |
| 展开全文 / 去全页 | 斜杠命令菜单（岛内只认 3 条检索类） |
| 追问（同一输入条） | 赞踩 / 删除消息 / 跳转栏 / 复制整段 |

### 3.7 手势：对着导航栏向下拉（竖屏加速器）

**判定**：手指落在导航栏内（y ≈ 20–40px）时是纯页面内手势，不撞系统。
真正的系统手势区只有屏幕最顶端 ~15px —— 那一条热区让给系统，接受损耗（手势是加速器，主入口是常驻胶囊）。

| 浏览器行为 | 解法 |
| --- | --- |
| Android Chrome 下拉刷新（页面在顶部时下拉） | 手势区 `overscroll-behavior-y: none` |
| iOS 橡皮筋 bounce | 手势区 `touch-action: none` + `preventDefault`（`passive: false`） |
| 手势与导航栏点击冲突 | 位移 < 12px 算点击（logo / 菜单 / 头像照常可点） |

**实现要点**：

- 可拉区域 = **整条导航栏**，热区越大越好；
- 跟手：岛高度直接跟随位移（岛内是列表不是复杂动画，动 `height` 即可，不要 `scaleY` —— 会拉伸内容）；
- **跟手期间禁用岛自身的 460ms 过渡**，松手才恢复曲线，否则岛「漂」在手指后面；
- 松手吸附：位移超过 40% 展开到输入态，否则弹回胶囊。

> 动画分工（先变宽再长高）随 P2 回答形态一起做，P1 用弹簧入场过渡。

### 探针要断言的（`scripts/probes/probe-nav-ask.mjs`）

1. 胶囊 → 输入 → 列表 → 回答，四个形态的**输入条 `top` 差值 ≤ 1px**（本方案唯一的硬视觉契约）
2. 注入 `--kb-inset: 336px` 后，输入框底边 ≤ 视口高 − 键盘高，且岛体可滚
3. 站内命中 0 时第 0 项高亮；命中 > 0 且普通词时第一个结果高亮（**两档，缺一即假绿**）
4. 岛内**不存在** `.boh-mode-pill` / `.boh-usage`（减法断言；反证 = 全页仍存在）
5. `⌘K` 与 `/` 召唤的是**同一颗岛**（同一 DOM 节点），不是两张卡
6. 岛在无导航栏的路由上仍可召唤（`user-space` 子视图抽样一条）—— 这是 Teleport 的存在理由

## 6. 风险与反证点

| 风险 | 反证方式 |
| --- | --- |
| 合并后搜索变慢（AI 组件拖累 chunk） | `BohIslandAnswer` 必须 `createPanelAsync` 懒加载；测首屏 gzip 增量 |
| 第 0 项抢了搜索的第一眼 | 灰阶/字号低于结果项，且**默认不聚焦**（仅在问句/零结果时高亮） |
| 岛遮挡页面内容（悬浮物的固有代价） | 待命胶囊只占一条高度，页面首屏留出岛位；展开态是模态语义，允许盖住 |
| 岛高在小屏 + 键盘下被压到不可读 | `clamp` 下限 240，岛体独立滚动；320×480 + 键盘档必须过 |
| 快速会话变成第二套历史 | 全页侧栏只加一行入口，不做第二套列表 UI |
